# 文言の点検表

画面の文言の案を出す前の自己点検と、他者の案のレビューに使う全項目の点検表。`../SKILL.md` の「レビュー観点チェックリスト」から開く。制作モードで案を出す前、または「この文言を見て」と頼まれたときに、各項目で「はい / いいえ / 不明」を付け、いいえと不明を改善案に結びつける。実際の利用者で確かめていない項目は、「不明」のままにする。

## 場面と目的

- [ ] 誰が・どの場面で・何をしようとして・何に困っているかを一文で言える
- [ ] その文言が、読んだ人の次の行動をどう助けるかを言える。説明で画面の欠陥を補っていない（S004）
- [ ] 文言で解く問題か。挙動や画面の変更が要るなら、文言とは別の提案として分けて書いた
- [ ] 頼まれていないボタン・確認の画面・手順を、文言の案に足していない

## ボイスとトーン

- [ ] ボイス（製品で一定）とトーン（場面で変える）を分けて決めている（S001・S027）
- [ ] エラー・解約・断る・同意しない選択肢で、冗談や熱量を上げていない（S082・S029）
- [ ] 「いいえ」側の文言を、そのまま声に出して相手に言える。断る側を貶めていない（S200）

## 用語

- [ ] 同じものを同じ語で呼んでいる。用語集（語・定義・使わない語・例）と突き合わせた（S087・S088）
- [ ] 画面の題・ボタン・確認の題・通知・メール・ヘルプで、語がそろっている
- [ ] 内部の列名・コード・技術用語を利用者向けに出していない

## 部品

- [ ] ボタンは動詞で、押した結果を言う。「OK」「はい／いいえ」だけにしていない（S051・S089）
- [ ] エラーは、何が起きたかと、どう直すかを書いた。責めていない。入力を消さない（S081・S032・S012）
- [ ] 原因が不明なら、推測でごまかさず、不明と書いた（S085）
- [ ] 空の状態に次の一手がある。空の理由（初回・0 件・権限なし・失敗）を同じ文にしていない（S048）
- [ ] 確認は、取り消せない操作・巻き込む範囲が大きい操作に限り、結果と件数を書いた。取り消せる操作は取り消しで代えた（S049・S058）
- [ ] プレースホルダーをラベルや説明の代わりにしていない（S038・S079）
- [ ] 通知は 1 件 1 要件で、同じ件を繰り返さず、他人に見えても困らない（S043・S053・S054）

## 国内の表記と敬語

- [ ] 文末（です・ます／体言止め）を、部品ごとに決めてそろえた（S121・S227）
- [ ] 敬語を足して丁寧にしていない。「させていただく」に許可と恩恵がある（S131・S134）
- [ ] 長音・和欧間の空白・全角半角・数字を、製品の表記規則にそろえた（規範が割れる論点は片方を標準にしていない）
- [ ] カタカナ語を、4 つの判断で扱った（S090）
- [ ] 二重否定を使っていない。結論を先にした（S140・S141）
- [ ] 色・位置だけで指していない（S023）

## 翻訳を前提にした書き方

- [ ] 文を断片の連結で作っていない。変数の位置を訳者が動かせる（S096・S097・S098）
- [ ] 複数形を「1 か否か」で分けていない。言語ごとの区分を使う（S099・S100）
- [ ] 文字列に UI の位置（「右の」「下の」）を埋め込んでいない
- [ ] 訳で長くなっても収まる。短い文言ほど長くなる（S102）
- [ ] ユーモアや比喩を避けた（S016）

## 騙しの文言

- [ ] 引き止め・confirmshaming・紛らわしい言い回し・既定の同意を書いていない（S200・S201・S202）
- [ ] 金額・期限・条件（税込・送料・自動更新・締め切りの時刻）を省いていない（本 skill の整理）

## 確かめ方

- [ ] 声に出して読んだ（S011）
- [ ] 用語集と、表記規則に突き合わせた
- [ ] 1440・390・320 px、文字 200%、ライトとダークで、日付・金額・締め切りが読める。描画できない環境では「未描画」と書いた
- [ ] 理解度は、利用者で確かめる計画がある（ハイライター法・言葉の説明・クローズテストなど。S156・S158・S163）。確かめていないものは「未確認」と書いた
- [ ] A/B テストは、理由を教えないことを踏まえ、質的に補う計画がある（S164）
- [ ] 作った本人とは別の目で見直した
- [ ] 生成した下書きは、ボイスとトーンの表と用語集で人が確かめた（S196・S197）
- [ ] 実在のサイト・製品の文言を写していない
