# 国内の表記と敬語

画面の文言の文末・敬語の度合い・長音・和欧間の空白・数字と全角半角・文の長さ・カタカナ語・やさしい日本語を、公用文・告示・業界の基準・企業の指針・世論調査から並べたファイル。`../SKILL.md` の「国内の表記と敬語」から開く。製品の表記規則を決めるとき、文言の揺れを直すとき、「丁寧にしたい」「やさしい日本語にしたい」と頼まれたときに開く。

規範どうしが割れている論点は、片方を標準にしない。製品の中で 1 つにそろえることを先に決め、選ぶ条件を書く。選ぶ条件は、出典が述べた範囲を除いて、本 skill の整理（推測）である。

## 規範の性格（先に読む）

- 「公用文作成の考え方」（S103 ほか）は文化審議会の建議で、内閣告示ではない。国の府省庁の公用文の目安で、民間の画面の規範ではない。解説・広報等では親しみやすい表記を用いてもよい（S104）。民間の画面に当てはめる部分は、すべて本 skill の整理である
- 内閣告示は、前書きで、専門分野や個人の表記に及ぼさないと述べる（S115・S117）。許容は、本則以外に、これによってよいものである（S116）。告示を根拠に、IT 製品の表記を一律に誤りとは言えない
- 業界の基準（JTF・Microsoft）と企業の指針（SmartHR）は、告示の許容の範囲で別の決め方をすることがある。同じ利用者が複数の製品で別の表記を見る（本 skill の整理）
- 利用者の実態は世論調査（S092・S118・S119・S120）にある。令和 2 年度から郵送法で、令和元年度以前（面接聴取法）とは比べられない、と調査自身が書く（台帳の帰属上の注意）。表記の例であって、画面の文言全般の調査ではない
- 規範・業界の基準・実態の 3 つを並べて選ぶ。どれか 1 つだけを根拠にしない（本 skill の整理）

## 表記規則の作り方（型）

1. 下敷きにする外部の基準を 1 つ選ぶ。SmartHR は、テクニカルコミュニケーター協会の『日本語スタイルガイド』第 3 版を参考にしたと述べ（S236。要旨）、外れる箇所を明記している（S237。要旨）
2. 外れる箇所を一覧にする。語・採る表記・理由・例外（例外の語は、一覧で持つ。SmartHR の例。S234。要旨）
3. 揺れを見つけ、どちらに統一するかを表にする。多くは告示の許容の範囲で、正誤ではなく統一の問題である（S116）
4. 画面の部品ごとに文体を決める。SmartHR は、監査ログの操作名は名詞で終え、説明文はです・ます調と、部品ごとに決めている（S227。要旨）
5. 変更の費用を見る。Microsoft が、外来語に由来するカタカナ用語の語末の長音を内閣告示に準拠した表記にすると発表した、という報道がある（S181。R。日付は媒体・日付の項による）。大きな製品の表記の変更は、利用者の画面の文字を一斉に変える（本 skill の整理）

## 文末と敬語の度合い

| 選択肢 | 向く条件（本 skill の整理） | 出典 |
|---|---|---|
| です・ます調 | 利用者に向けた画面に向く。国の公用文の規則は、対外的な文書でです・ますを基本とし、簡潔に敬意を表す（S127）。解説・広報等では、です・ますを基調とし、「ございます」は用いない（S128）。民間の画面の規範ではない | S127・S128 |
| 常体（である調・体言止め） | 操作の記録・見出し・ボタンなど、短く言い切る部品。SmartHR は監査ログの操作名を名詞で終える | S227（要旨） |
| 混在させる | 部品ごとに決めたなら混在ではない。決めずに混ざると製品の人格が割れる。Ubie の記事は、語調の混在が多重人格のような印象を与えうると述べる（事業者の個人の報告） | S024 |

- 文書内では、敬体と常体のどちらかに統一する（JTF。S121）。部品ごとの文体は、その部品の中で統一する（本 skill の整理）
- 敬語の量: 敬語をたくさん使えば丁寧になるわけではない（S131）。丁寧度の高い言葉を多用すると、かえってよそよそしい響きで読み手を遠ざける面がある（S130）。「ございます」は解説・広報等では用いない（S128）。「おります」「いたします」は必要に応じて使い、多用しない（S129）
- 「させていただく」: 自分側が行うことを、相手側または第三者の許可を受けて行い、そのことで恩恵を受ける事実や気持ちがある場合に使われる（S134）。許可も恩恵も無い場面（「確認させていただきました」「表示させていただきます」）に、癖で付けない
- 二重敬語は、一般に適切ではないとされる。ただし、語によっては定着したものもある（S132・S133）
- 画一的な定型: いつでも誰にでも限られた表現だけを使うと、顧客にかえって不快な思いを与えることがある（S135）。通知文のひな型は、相手と場面で書き分ける
- ファクシミリや電子メールで、文章を要点だけの短いものにし、敬語も割愛してしまう傾向への批判が、敬語の指針（答申）に記録されている（S136）。短さと敬意は綱引きになる。出典は結論を出さない
- SmartHR は、敬語を重ねすぎて情報が伝わりにくくならないようにする。依頼や完了の報告は簡潔な丁寧語をよい例とする（S238。要旨）

選ぶ条件（本 skill の整理）:

| 場面 | 向く案 | 理由 |
|---|---|---|
| 手続き・料金・解約・同意の説明 | です・ます調。結論を先に（S141）。しなくてよいことも書く（S142） | 読み手が次の行動を決められること（S103） |
| 失敗・お詫び | です・ます調。謝る場面を決め、謝るなら 1 回にする | 敬語の量でなく、原因と直し方で丁寧さを出す（S130・S131） |
| 操作の記録・履歴 | 体言止め | 一覧性。部品ごとに決める（S227。要旨） |
| 高齢の利用者や、かしこまった相手が多い製品 | 敬語を足すのでなく、手間と不安を減らす。文を短くし、結論を先に、対象外の人にも一言 | 敬語の量と丁寧さは比例しない（S131） |

## 長音（語末の長音符号）

| 論点 | 付ける側 | 付けない側 | 実態（世論調査） |
|---|---|---|---|
| 語末 -er・-or・-ar | 外来語の表記は、原則として長音符号を用いる。ただし慣用に応じて省くことができる（S114）。JTF は省略しない（S122）。Microsoft の日本語のスタイルガイドは、原則として長音を用いる（S126） | SmartHR は、語末 -er・-or・-ar の語に長音符号を付け、例外の語を一覧で持つ（S234。要旨） | 無し |
| 語末 -y | 公用文は、-ty・-ry など y で終わる語も長音符号を用いて書く（S110） | SmartHR は付けない（S234。要旨） | セキュリティー 34.2%、セキュリティ 53.5%（S118。令和 6 年度） |

- 公用文は -y にも付け（S110）、SmartHR は -y に付けない（S234。要旨）。どちらでも、製品の中で統一する。付けない語は、語の一覧で管理する（本 skill の整理）
- 規範と実態がずれる箇所がある。公用文が -y にも付けるとした一方、世論調査は付けない側が多い（S110・S118）
- 「ヴ」は、公用文では原則として「バビブベボ」を用い、むやみに使うことは慎む（S111）。「ウィ・ウェ・ウォ」は、SmartHR がそろえると述べる（S235。要旨。根拠に挙げる調査の本体は未取得）。どちらも文書内で統一する
- 年代で自然な表記が違う。「レクリエーション」は 60.0%、「レクレーション」は 33.5%（S119）。「サステナブル」は 64.5%、「サステイナブル」は 28.6%（S120）。主な読み手の年代を決めてから選ぶ

## 和欧間の空白

| 立場 | 内容 | 出典 |
|---|---|---|
| 入れない | JTF は、半角文字と全角文字の間に半角スペースを入れない。SmartHR も、数字や英単語と日本語の間に入れない（要旨） | S123・S232 |
| 入れる | Microsoft の日本語のスタイルガイドは、原則として半角スペースを入れる | S125 |
| 組版に任せる | フォントによる和欧間の空きと二重にならないかを、画面で確かめる | 本 skill の整理（文字組は、導入されていれば designer-typography） |

選ぶ条件: 翻訳の資産や既存の製品に合わせる。入れる・入れないのどちらでも、製品の中で統一し、数字や単位の前後も同じ規則にする。

## 数字・全角半角・記号

- 全角と半角が混在すると、フォントによっては不ぞろいや不自然な空白が生じ、読み取りにくくなる場合がある（S105）。全角・半角は、文書内で使い分けを統一する（S107）
- 全角の数字は、情報処理で数値として認識されない場合がある（S106）。数字とアルファベットは半角にする（JTF。S124）。SmartHR も、数字は半角の算用数字、3 桁ごとにカンマ、「か所」「か月」と書く（S233。要旨）
- 読点は「、」が原則で、横書きでは「，」も使える。一つの文書内でどちらかに統一する（S108）。実態は「、」が多い（S113）
- 解説・広報等では、必要に応じて「？」「！」を用いてよい（S109）。ただし、熱量を上げる記号は、断る側の選択肢の文言では避ける（本 skill の整理）
- 表の中の日付・桁区切り・単位・空値の表記は、導入されていれば designer-admin の `references/jp-notation.md`。本 skill は、画面の文の中の表記を持つ

## 日付・時刻・金額を文に書くとき

出典（台帳）に直接の規則は無い。次は本 skill の整理で、法的判断ではない。

- 日付は、年・月・日と曜日を、文の中で 1 つの形にそろえる。期限は、時刻と、どの時間帯の時刻かを書く（日本国内だけの製品でも、利用者が海外にいる場合がある）
- 金額は、税込か税別か、送料や手数料を含むか、いつ請求されるか（自動更新・分割・初回無料の終了）を、金額の近くに書く。省くと、誤解が生じる
- 数字と単位は改行で分けない。狭い幅（320 px）と文字を 200% にしたときに、日付・金額・締め切りが読めるかを描画して確かめる（確かめ方は SKILL.md）

## 文の長さと構成

| 項目 | 内容 | 出典 |
|---|---|---|
| 一文の長さ | 適当な長さは一概に決められないが、50〜60 字ほどになってきたら読みにくくなっていないか意識するとよい。SNS では、より短くすべきとの指摘もある | S138 |
| 一文に 1 つ | 一文に言いたいことは 1 つだけ（やさしい日本語のガイドライン） | S144 |
| 結論を先に | 結論は早めに示し、続けて理由や詳細を説明する | S141 |
| 箇条書き | 三つ以上の情報を並べるときには、箇条書を利用する | S139 |
| 二重否定 | どうしても必要なとき以外には使わない。「〜ないことはない」「〜ないわけではない」はわかりにくい | S140・S146 |
| しなくてよいこと | 「上記に該当しない場合、手続は不要です」のように、する必要のないことも明示すると、読み手の不安を軽減できる | S142 |
| 想定する読み手 | 広く一般に向けた文書は、義務教育で学ぶ範囲の知識で理解できるように書くよう努める | S137 |
| 助詞 | 格助詞を省かず、語どうしの関係が分かるように書く。「〜することができる」は避ける | S240・S239（SmartHR の要旨） |

字数の値は、性質の違うものが混ざる。公用文の 50〜60 字は意識する目安（S138）。校正ツールの既定値（SmartHR のプリセットの 120 字。S155）は、ツールの設定で、研究値ではない。災害時の外国人向けの規則（24 拍。後述）も別である。同じ一文の長さの基準として並べない。「一文は 40 字以内」は流通しているが、取得した公的資料に無い（台帳の未検証の節）。

学年を推定する式（S154）や、日本語学習者向けの 6 段階の難易度判定（S171・S172）は、UI の短い文言の合否基準ではない（対象が違う。本 skill の整理）。読みやすさの公式は、意味を測らない（S168・S170）。

## カタカナ語

- 外来語への対応は 4 つの考え方がある。「そのまま使う」「言い換える」「説明を付けて使う」「使い方を工夫する」（S090）。一律に禁止も放置もしない。定着度と読み手で決める
- 「分かりにくいから」が、カタカナ語の交じる文を好ましくないとする理由の最多で、64.1%（S092。令和 6 年度）
- 国立国語研究所は、公共性の高い媒体で使われている、国民にとって分かりにくい外来語を、分かりやすくする工夫の検討に着手した（S091）
- SmartHR は、カタカナ語を使う前に、漢字語での言い換えを検討する。受け取り方の幅が漢字語より大きいという理由（S229。要旨）
- やさしい日本語のガイドラインは、外来語はできる限り使わないとする（S145）。外国人に向けた規則で、一般の画面の規則ではない
- 判断の手順（本 skill の整理）: 語を棚卸しする → 4 つのどれかを選ぶ → 言い換えが意味をずらさないか確かめる → 読み手本人に確かめる（S148）。機器の接続画面の「ペアリング」「ファームウェア」のような語は、言い換えると別の意味になりうる。説明を付けるほうが安全な場合がある

## やさしい日本語

- 在留支援のガイドラインは、3 つのステップでやさしい日本語を作成するとする（S143）。ステップ 1 は、文書を日本語母語話者にわかりやすい文章にする。ステップ 2 は、言葉をやさしく書き換え、漢字にふりがなをつけて、外国人にもわかりやすく直す。ステップ 3 は、日本語教師や外国人に確認してもらう（S143）
- 一文は短く、一文に言いたいことは 1 つだけ（S144）。二重否定を避ける（S146）。外来語はできる限り使わない（S145）
- 機械翻訳にかける可能性に配慮し、インターネットで発信するときは、ふりがなをつけない文書もできる限り同時に用意する（S147）
- 書き換え案ができたら、日本語教師や外国人に、わかりやすいか、伝わるかをチェックしてもらう（S148）。規則を当てはめて終わりにしない
- 弘前大学の規則は、一文を 24 拍程度、長くなっても 30 拍を超えないとする（S149。区分 B。消防庁の資料による転載）。東日本大震災では、情報量の増加で、一文をどうしても長くせざるを得なかった（S150。区分 B）。字数や拍数の上限は、伝える量とセットで決める。災害時の規則を、平時の一般則として持ち込まない（本 skill の整理）
- 多くの外国人が災害情報を得られず、二重に被災した、という指摘が背景にある（S180。区分 B）

## 感覚だけで指す文言

色・形・位置・音だけで指す表現（「赤い項目を確認」「右のボタン」）を単独で使わない（S023）。別の手がかり（項目の名前・番号）を添える。判定は、導入されていれば designer-accessibility。

## 決めることの一覧（表記規則 1 枚の項目）

| 項目 | 決めること | 記録するもの |
|---|---|---|
| 文体 | 部品ごとの文末（です・ます・体言止め） | 部品・文体・例 |
| 敬語 | 「ございます」「させていただく」「いたします」の扱い | 使う場面・使わない場面 |
| 長音 | -er・-or・-ar と -y の扱い、例外の語 | 例外の一覧 |
| 和欧間 | 空白を入れるか | 例 |
| 数字・単位 | 半角・桁区切り・「か所」「か月」・単位の位置 | 例 |
| 記号 | 読点・感嘆符・括弧・波ダッシュ | 例 |
| カタカナ語 | 4 つの判断の結果 | 用語集へ（語・判断・言い換え） |
| 日付・金額 | 文中の形、条件の書き方 | 例 |
