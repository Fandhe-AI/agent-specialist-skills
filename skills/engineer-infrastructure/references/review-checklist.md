# 運用の文書のレビュー観点チェックリスト

SLO の決定記録、可観測性と警報の設計、公開の安全の方針、事後検証の文書を、出す前に自己点検するとき、または他者の文書を見るときに使う全項目の点検表。[SKILL.md](../SKILL.md) の「レビュー観点チェックリスト」から開く。依頼の対象の文書に当たる項目の群（SLO・警報・公開・事後検証など）を先に選び、その群の各項目で「はい / いいえ / 不明 / 該当なし」を付け、いいえと不明を、改善案か相談者への確認事項に結びつける。選ばなかった群は判定しない。

項目は 2 群に分ける。文書を読めば判断できる群と、相談者の計測・運用の記録が要る群である。後者は、ここでは実測していない。判定に要る証拠が足りないときは「不明」とし、何を測るかを書く。相談者が計測や記録を示し、それで確かめられれば、「はい」または「いいえ」を付ける。結果を問う項目は、証拠が得られるまで「不明」とする。可用性・性能・費用の保証はしない。数値の目標は相談者が決める。ここでは値の基準を置かない。

根拠の欄は、出典の番号（[出典台帳](sources.md)）か「本 skill の整理」である。S 番号が支えるのは、引用ブロックに逐語であることだけで、残りは「本 skill の整理」「推測」と書く。区分は台帳の凡例に従い、批判・留保の側（C）は区分を添える。各社の運用は、その会社の自称である。

## 実測や相談者のデータが要る項目

ここは、文書を読むだけでは「はい」にできない。相談者の計測・運用の記録が足りないときは「不明」とし、何を測るかを書く。記録が示され、それで確かめられれば、「はい」または「いいえ」を付ける。計画があるだけで、結果の項目を「はい」にしない。

### SLO の決定記録

- [ ] SLI の実測が SLO に定義した評価期間の全体にわたって出ていて、SLO の目標に対する達成が確かめられている。数えるときは SLI と同じ分母と評価期間を使い、記録が評価期間に足りないとき、または欠測が達成・未達を変えうるときは「不明」とする（本 skill の整理）。評価期間の全体で対象が 0 件だと確かめたときは、不明とは分け、達成・未達を付けず「該当なし」とし、0 件だったと書く（本 skill の整理）。未達は「いいえ」。値は相談者が決め、ここでは実測していない（本 skill の整理）
- [ ] error budget の消費が、SLI と同じ単位で計測され、方針の段階に照らされている（本 skill の整理。S004 が支えるのは、1 四半期の中という予算の枠だけ。計測は相談者の記録）
- [ ] 選んだ SLI が、利用者の困りごとの記録（問い合わせ・離脱など）と突き合わされ、合っている（本 skill の整理）
- [ ] SLI と同じ分母で、その要求（時間ベースならその時点）に欠かせない依存先がすべて使えたか、代わりの経路で同じ要件を満たせたかを数えた割合を、相談者の実測の記録で確かめている。数えるときは SLI と同じ分母と評価期間を使い、記録が無いとき、または欠測が判定を変えうるときは「不明」とする（本 skill の整理）。評価期間の全体で対象が 0 件だと確かめたときは、不明とは分け、達成・未達を付けず「該当なし」とし、0 件だったと書く（本 skill の整理）。S007 が支えるのは、欠かせない依存先が同時に使える範囲が上限になり、緩和策が要る、ということだけ。公開の SLA や目標値は約束で、実測の代わりにならない。公開の観測の結果（稼働の履歴など）は、対象の経路・期間・粒度が合えば使える（本 skill の整理）。その割合が SLO の目標以上である。下回るなら「いいえ」。緩和策や目標の見直しを決めただけでは変えない。緩和した後は適用後の記録で、目標を改めたら改めた目標と比べて、判定し直す（本 skill の整理）

### 可観測性と警報の設計

- [ ] 警報の precision（S013）と recall（本 skill の整理）を、警報とは別の記録（障害・問い合わせ）と突き合わせて数えている。対処した件数では数えない。記録が無ければ「不明」（本 skill の整理）
- [ ] 上限と同じ単位・期間で数えた通知の件数が、決めた上限に収まっている（本 skill の整理。S015 は事故の件数の自称の例で、通知の数ではない）
- [ ] 警報を消す・通知にしない・チケットへ移すときは、上限の内外によらず、SKILL.md の「警報を消す・通知にしない判断」の条件をすべて満たしている。外す前に、警報とは別の記録で実害の検知を確かめ、実害を検知していた警報は代わりの検知を用意してから外し、チケットへ移すのは遅れて対処しても利用者への影響が許容内のときだけにしている。記録で確かめられなければ「不明」（本 skill の整理）
- [ ] 警報の閾値が、過去の記録に当てて、鳴るべき時に鳴り、鳴らない時に鳴らないと確かめられている（本 skill の整理）
- [ ] 計測の使用量（時系列の数・保存量）が、相談者が決めた上限に収まっている（S025 が支えるのは、ラベルの組み合わせごとに時系列が増えるという点だけ。上限の値と判定は本 skill の整理）
- [ ] 計測の金額が、相談者の予算に収まっている。対象期間の請求額などの記録で判定し、使用量の判定では代えない。記録が無ければ「不明」（本 skill の整理）

### 公開の安全の方針

- [ ] 切り戻せる段では、切り戻しが、決めた条件で、許容する停止時間の内に実際に戻せると試されている。試していなければ「不明」とする。どの方式でも、戻した後も、新しい版で受けた書き込みが失われず、旧版で読め、処理中の取引を扱えることを確かめている（本 skill の整理。SKILL.md の段 2 と同じ条件）。切り戻せない段では、前へ直す手順が、決めた条件と担当で実行できると確かめている。試していなければ「不明」
- [ ] 段階公開の各段について、広げた段では、広げる前に、決めた合格の条件（判定に使う指標と許容範囲・観測する時間・要るデータの量・比べる対象）を満たしたと記録で確かめている。広げなかった段では、止めたことと、決めた対応（切り戻す・前へ直す・観測を続けるなど）をとったことを記録で確かめている。あわせて、切り戻す条件（切り戻せない段では前へ直す条件）に照らしている。切り戻せる段では、切り戻しの 3 つの条件を満たせることを、切り戻せない段では、前へ直す条件と手順を実行できることを、記録か試験で確かめている。確かめられなければ「不明」（本 skill の整理）

### 事後検証の文書

- [ ] 事後検証の時系列が、ログ・チャット・変更の記録と突き合わされている（本 skill の整理）
- [ ] 対応項目が、決めた期限内に完了している。追跡の記録で確かめる（S044。自称の運用）。完了した項目は、完了の日と期限を記録で比べる。期限を過ぎて未完了だと追跡の記録で確かめられれば「いいえ」、記録が足りなければ「不明」とする。期限前で未完了の項目は「不明」とし、判定する予定の日を書く。担当・期限・追跡の方法は、文書側の対応項目の項目で判定する（本 skill の整理）
- [ ] 上の層が、犯人を求めず、事後検証の結果を受け止めている。相談者の組織の様子が要る（S117。C。現場が責めない振り返りをしても、上の層が犯人を求めれば、それが文化を決める、という指摘）

## 使い方

- 制作モードでは、案を出す前に、作る文書に当たる群の項目を見る。レビューでは、先に見る価値が高い（本 skill の整理）次の群から見る: SLO の決定記録の「依存先」と「error budget の方針」、警報の「通知の種類」、事後検証の「寄与要因」と「対応項目」
- 「不明」が多いときは、文書を断定せず、相談者へ確認する事項として返す
- 項目は、出典が定めた合格基準ではない。出典の主張と、本 skill の整理を、根拠の欄で分けている
- 障害の最中の相談には使わない。平時の設計と障害の後の文書の点検である

## 判定の付け方

| 判定 | 意味 | 返し方 |
|---|---|---|
| はい | 文書や記録で確かめられた | 根拠を 1 行で添える |
| いいえ | 使う要素の記載が欠けている、反している、目標が未達 | 改善案を、得るものと失うものの両面で書く |
| 不明 | 判定に要る証拠が足りない。その要素を使うかどうかを確かめられない場合を含む。計測や記録が要る | 何を測るかと、誰が測るかを書く。証拠が示されたら、はい・いいえに改める |
| 該当なし | 次の (a)〜(c) のいずれかに当たる場合 | 該当なしの理由を 1 行で添える |

- (a) その要素を使っていないと確かめられた場合（フラグを使わない・外向けの約束が無いなど）
- (b) 割合を出す実測の項目で、評価期間の全体で分母になる対象が 0 件だと確かめた場合
- (c) 小さな事象で簡略版の様式を使い、省いた項目

件数が欠測で分からないときは、該当なしでなく不明とする。
