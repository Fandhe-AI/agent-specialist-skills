# 傾向の台帳（Web の見た目の傾向を、日付と出どころ付きで読む）

Web サイトの見た目の傾向を、傾向名・構成要素・作り方・出典・時点・批判の順に並べた台帳。「今時にしたい」「流行を取り入れたい」「〇〇風にしたい」と相談されたとき、傾向を採るかどうかを、被写体と目的から判断するために開く。傾向の一覧を暗記して当てはめるためのファイルではない。出典の詳細（引用原文・日付・URL・検証区分）は `sources.md` を参照する。

## 読み方（先に読む）

- 時点: 2026-11-15。傾向は数か月で変わる。台帳の行は「その日付に、その出どころが言っていたこと」であり、今の普及度ではない
- 出どころの種類を、行ごとに区別する。
  - 予測: ベンダー（制作ツール・EC 基盤・ノーコード基盤の提供会社）や予測記事が、自社の製品・読者に向けて書いたもの（S36・S37・S39・S40・S41）。利害がある。採用率を測っていない
  - 自己主張: 企業が自社の研究の結果として述べるもの（S43）。第三者の再現は取得していない
  - 実践の記録: 制作側の自己申告（S19〜S23・S83・S84）。第三者の検証ではない
  - 賞の評価: 運営者が載せた審査員のコメントと配点（S24〜S33）。賞の偏りの批判もある（S34・S35。いずれも C）
  - 実測: 均質化の研究（S50。著者のプロジェクトページの要約で、原論文未取得。サンプルは英語圏の企業・Webby 候補サイトに偏る）と WebAIM の調査（S80・S81）。見た目の傾向そのものの普及度を測った実測は、この台帳に無い
- 各行の「批判・飽き」は、出典のあるもの（S 番号つき）と、本 skill の整理（推測）を分けて書く。批判が見つからなかった行は、見つからなかったと書く
- 「作り方」の CSS・SVG の書き方は、本 skill の目安（出典なし）である。具体的な値は `../examples/` で描画して確かめた
- 日本語圏の傾向を実測した出典は取得できていない。「国内で人気」「日本人は〜を好む」とは書かない（S66 は、日本は情報が多い見た目を好むという説を、筆者自身が一般化しすぎと留保する。区分 R）

## 傾向の行

各行の出典の列は、その行の主張の根拠。作り方の列は本 skill の目安で、出典ではない。

### 1. 手描き・不完全さ（Shopify の呼び名: chicken scratch）

- 構成要素: ゆがんだ線・手で描いたような形・磨いていない見た目。Shopify は、巧みな素描より下手な落書きに近い粗さ、と書く（S36）。Webflow は、手描きの要素と現代の操作を組み合わせる傾向を挙げる（S40）
- 作り方（目安）: SVG の `path` で線を描き、`stroke-linecap: round` と太さの揺れ（複数の `path` を重ねる）で手の跡を作る。線の揺れは `feTurbulence`＋`feDisplacementMap` でも作れるが、重い。ロゴ・見出しの下線・矢印・丸囲みなど、点で使う
- 出典と時点: S36（2025-04-10 公開・2026-11-07 更新の予測記事）、S40（2025-12-23 更新の予測記事）。理由づけとして、整いすぎた画像は AI 製と連想されるという説が紹介される（S42。区分 R。記者が『理論』として紹介するもので、実証ではない）
- 批判・飽き: 出典のある批判は取得していない。本 skill の整理（推測）として、読む文字そのものを手描き風にすると可読性が落ちる（コントラストと字形の確認が要る。S74）。AI への反動という理由づけ（S42）を採るなら、一斉に採った時点で次の定型になりうる
- 使うかの問い: 被写体に手の跡の理由があるか（手仕事・手紙・工房）。無いなら、装飾の手描きは「手触りを狙う既定値」になる（S54 は cream＋セリフ＋テラコッタを第 1 項に挙げる。これは手触りを狙う様式と重なる。本 skill の解釈で、S54 が手触りを狙う様式と述べているわけではない）

### 2. コラージュ・スクラップブック（Figma: Collage、Shopify: structured scrapbook）

- 構成要素: ステッカー状の図・破れた縁・切り抜きの写真・手書き風の書体（S37）。Shopify の説明では、構成のしかたは、精密で、整理され、丁寧に選ばれたもの（S36）
- 作り方（目安）: 12 列のような秩序の土台を先に決め、断片を `rotate(-3deg)` 程度で重ねる。破れた縁は `clip-path: polygon()`、ハーフトーンは `radial-gradient` の繰り返し、紙の粒は SVG の `feTurbulence`。小さい文字は無地の面（札）に置き、質感は文字の背面に回して、大きい文字は最も不利な画素で測る。写真の切り抜きは本物の切り抜きのファイル（透過 PNG・WebP）を使い、画面幅ごとの切り抜きは `picture` で分ける（S11・S12）
- 出典と時点: S37（Figma の 2026 年版）、S36。Adobe は、手触り・アナログが好まれるという予測を挙げる（S39）
- 批判・飽き: 出典のある批判は取得していない。本 skill の整理（推測）: 断片が増えるほど読み順が壊れ、画像・質感のファイルで重くなる（LCP の目標 2.5 秒以下。S77）。回転・重ねは、320 px で横にはみ出しやすい
- 使うかの問い: 断片の素材（被写体・季節・素材）を、被写体から選べるか。汎用のステッカー素材を並べるだけなら定型になる

### 3. ネオブルータリズム・アンチデザイン

- 構成要素: 荒く、磨いていない見た目。Figma は、滑らかなミニマルなテンプレートの海の中で目立つ様式と説明する（S37）。集積サイトは、軽さ・楽観への反動と自分を位置づける（S49。運営者の記載なし。R）
- 作り方（目安）: 太い枠線・ベタ塗りの面・ずらした影（ぼかさない `box-shadow`）・システムの等幅書体・強い原色。読む文字の可読性・フォーカス・ナビの慣習は残す
- 出典と時点: S37、S49。Readymag の審査員は、グリッドへの敬意を欠く個人サイトを、冒険しないことを退ける言い方で評価した（S33）。Readymag の側は、近年の Web デザインに、慣習を破るブルータリズムの台頭と、磨かれた均質なプロダクト設計の優位という 2 つの流れがあったと書く（S26。B）
- 批判・飽き: ポートフォリオが UX の慣習に従うべきかは、両面ある（S28）。本 skill の整理（推測）: 目的が挑発でなければ、ナビ・フォームの慣習を壊す理由が無い
- 使うかの問い: ブランドが挑発したいのか。目的が信頼・安心なら合わない

### 4. 手触り・アナログ・人の手仕事

- 構成要素: 実物の質感・実在の人・実際の物語（S39）。アルゴリズムの均質さの中で、人の手仕事が差別化になるという見立て（S40）
- 作り方（目安）: 実物の写真・スキャン（紙・布・手書き）を使う。画像の代わりに質感だけ足すなら、SVG の `feTurbulence` で粒を作り、不透明度を 0.05〜0.12 に抑える（目安）。質感は、文字の下地には敷かない
- 出典と時点: S39（Adobe の 2025-12-09 の記事）、S40。写真は実物を使う根拠: 視線計測で、装飾目的の大きな画像は無視され、重要な内容として精読される画像の例に、製品・実在の人の写真がしばしば挙がる（S60。2010 年公開の記事）
- 批判・飽き: S54 は、温かい cream 背景・高コントラストのセリフ・テラコッタのアクセントを、AI の出力が偏る様式の第 1 項に挙げる。これは手触りを狙う様式と重なると、本 skill は解釈する（S54 の述べたことではない）。被写体の素材から決めた理由が言えない手触りは、定型として読まれる（本 skill の整理（推測））
- 使うかの問い: 手触りの出どころ（誰の手・何の素材）を言えるか

### 5. 特大の書体・表現的なタイポグラフィ

- 構成要素: 大きな見出し・独自の書体・動き・重ねた書体で、第一印象を作る（S37）。AI の提供元の文書は、ページの人格は書体が運ぶと書く（S55）
- 作り方（目安）: 見出しを `clamp(3rem, 14vw, 10rem)` のように画面幅に連動させ、行間は 0.95〜1.15、字間はやや詰める。和文は字面が大きいので詰めすぎない。折り返しは `text-wrap: balance` を補助に使う（非対応の環境では通常の折り返しになり、行の長短が不揃いになる）。外部フォントを使えない場合は、システムの明朝・ゴシックの太さと大きさの対比で作る（他の OS での見えは未検証）
- 出典と時点: S37（2026 年版）、S55。可変フォントの登録済みの軸は、太さ・幅・傾斜・イタリック・オプティカルサイズ（S78）
- 批判・飽き: 出典のある直接の批判は取得していない。本 skill の整理（推測）: 特大の文字は 320 px で折り返しが崩れやすく、画像の上に重ねると可読性が落ちる（S46 は、画像の上の文字はコントラストが低くなりやすいという批判を挙げる。区分 C。iOS への批判で、一般則として借りる）
- 使うかの問い: 声を出す場所はここか。ほかの層は静かか（S55: 大胆さは 1 か所）。文字組の規則（行長・約物）は、導入されていれば designer-typography

### 6. 高彩度・ハイパーカラー

- 構成要素: 合わないはずの色の組み合わせ・コントラストを限界まで押す・注意を求めるエネルギーの高いパレット（S36）。
- 作り方（目安）: `oklch()` で明度を揃えて色相を回し、彩度（C）を上げる。C の 100% は 0.4（S72）。広い色域の値は、sRGB の色を既定にして、`@media (color-gamut: p3)` の中で差し替える（色域は表示装置の判定で、`@media` の役割。S110）。`@supports` は UA の構文への対応の判定にすぎず（S111）、色域は判定できない。`@supports (color: oklch(0% 0 0))` は、`oklch()` に非対応のブラウザーの分岐にだけ使う。`oklch()` の既定値は sRGB の範囲に収める。文字は無地の面に載せ、比を測る（S74）
- 出典と時点: S36
- 批判・飽き: 関連する基礎統計（高彩度への批判ではなく全体の数字）: 上位 100 万ホームページの 83.9% で低コントラスト文字が検出される（S80）。高彩度どうしの組み合わせは、コントラスト比が足りなくなりやすい（本 skill の整理（推測））。色数を絞った作例として、パレットが 2 色の受賞作が 1 件ある（S87。1 件で、一般化しない）
- 使うかの問い: 色を何に使うか（面か・文字か・差し色か）。文字は比で判断し、色の鮮やかさを理由にしない

### 7. ミニマル・マキシマリズム（1 か所だけ大胆）

- 構成要素: 全体を抑え、1 つだけ大胆で表現的な動きを入れる（S36）。実例として Lusion は、ミニマルを少し手放して環境を足し、UI の書体・色を最小にした（S19・S20）。AI の提供元の文書も、大胆さを 1 か所に使い、まわりを静かで規律あるものに保つ、と書く（S55）
- 作り方（目安）: 声を出す場所を 1 つ決める（特大の見出し・1 枚の写真・1 つの図）。ほかは 1 書体・2〜3 色・余白で抑える
- 出典と時点: S36、S19、S20、S55
- 批判・飽き: S26 は、「破る」流れと「磨く」流れの両方を挙げる（B。混ざり始めたという見方は同記事の要約で、引用ブロック外）。本 skill の整理（推測）: 「1 か所だけ大胆」自体が型になり、どのサイトも同じ位置（ヒーロー）に置くと、声を出す場所が同じになる
- 使うかの問い: 声を出す場所は、被写体から選んだか。ヒーローに置くのが既定になっていないか

### 8. 歴史・古典の参照

- 構成要素: 古い装飾・古典の書体・古い挿絵を、現代の操作と組み合わせる（S36。S40）。Shopify は、より古く、より奇妙で暗いものへさかのぼる動きと書く（S36）
- 作り方（目安）: 参照元の様式を 1 つに絞り、版画風の挿絵や罫線の飾りを SVG で描く。装飾書体は見出しだけにし、本文は読みやすい書体にする。権利のある素材か（古い図版の権利）を確かめる
- 出典と時点: S36、S40
- 批判・飽き: 出典のある批判は取得していない。本 skill の整理（推測）: 参照元の意味（時代・文脈）を知らずに借りると、装飾だけが残る
- 使うかの問い: 被写体の歴史に、その参照の理由があるか（老舗・工芸・出版など）

### 9. 静かな Web・個人サイト

- 構成要素: 成長目標を持たない個人サイト・小さな場。磨きより個性（S41）
- 作り方（目安）: 書体 1〜2・色 2〜3・余白・実物の写真。ナビは慣習に任せ、見せ方（作品の並べ方・キャプション）に個性を置く。軽さも静けさの一部として扱う（S82・S35。いずれも C）
- 出典と時点: S41（2025-12-30 の予測記事）
- 批判・飽き: 予測であり、採用を測っていない（S41）。本 skill の整理（推測）: 静けさと、手が抜けているだけの状態は別。余白・書体・写真に、選んだ形跡があるかで分かれる
- 使うかの問い: 見せたいものが 1 つに絞れているか

### 10. ダークモード（標準化したという主張）

- 構成要素: Figma は、サイトとアプリでダークモードが標準になったと書く（S37。同社の主張で、採用率の統計ではない）
- 作り方（目安）: `prefers-color-scheme` で面と文字の色を切り替え、ライトとダークの両方でコントラスト比を測る。画像・ロゴ・影も切り替えを確かめる
- 出典と時点: S37（2026 年版）
- 批判・飽き: 黒に近い背景に 1 色の蛍光アクセントは、AI の出力が偏る様式として列挙されている（S54 の第 2 項）。ダークにすること自体ではなく、黒＋蛍光の組み合わせが既定値になっている
- 使うかの問い: ダークは設定への対応か、世界観か。世界観なら、被写体から色を選んだか

### 11. 3D・没入・スクロールで進む物語

- 構成要素: 3D・WebGL・スクロール連動・遷移。受賞作で目立つ（S19〜S23・S87。作品の技術タグは応募者の自己申告）。Awwwards の配点は Design 40・Usability 30・Creativity 20・Content 10（S29）
- 作り方（目安）: 素材（3D・イラスト）の制作が主な仕事で、コードだけでは作れない。コードで届く範囲は、スクロール連動の物語・遷移・絞った色・細部。WebGL そのものは、導入されていれば designer-creative-coding へ、動きの設計は designer-interaction へ回す
- 出典と時点: S19〜S23、S83、S84（制作側の自己申告）。Bruno は、表現の制約は性能だと述べる（S84）
- 批判・飽き: 動きの完成度に比べてアクセシビリティが弱い、という指摘がある（S34。C。点数は二次情報）。賞の評価が見栄えに偏る（S35。C。2016 年の記事）。上位 100 万ホームページの 95.9% で WCAG 2 の失敗が検出され（S80）、要素数は平均 1,437 に増えた（S81）。文章中心のサイトの肥大への批判（S82。画像の多用を否定する講演ではない）
- 使うかの問い: 素材・時間・性能の予算があるか。止める手段と、動きを減らす設定への対応を先に決めたか（S75・S76）

### 12. ガラス・透明・Liquid Glass 風

- 構成要素: 半透明で屈折する素材。Apple は、内容により焦点を当てるためと説明する（S44）。Web では `backdrop-filter: blur()` で近い見た目を作れる（S79）
- 作り方（目安）: 面の下地を十分に暗く（または明るく）して文字の比を確保し、ぼかしの強さは小さく始める。`backdrop-filter` が使えない環境では、不透明に近い無地の面に落とす（`@supports not (backdrop-filter: blur(1px))`）
- 出典と時点: S44（2025-06-09 の発表）。批判は S45（2025-10-10 の記事）。
- 批判・飽き: NN/g は、見世物を使いやすさより優先している、意味のない動きは使いやすさではない、重ねたものは見えにくくなる、と評する（S45。C。iOS への批判で、Web には一般則として借りる）。NN/g の記事は、技術者の集まる掲示板でも投稿として取り上げられた（S85。題名のみ。点数は時点情報で、一般の利用者の反応ではない）
- 使うかの問い: 透明にする理由が、内容を主役にするためか。文字の比は、最も不利な背景で測ったか

### 13. 避ける対象: AI が作りがちな見た目

- 構成要素: AI の提供元の文書は、cream の背景＋高コントラストのセリフ＋テラコッタ、近黒の背景＋蛍光色 1 色、新聞風の罫線、同じ角丸・同じ影のカードの束、すべての見出しの上の大文字のラベルなどを、取得時点（2026-11-15）の偏りとして挙げる（S54）。記事では、紫のグラデーション・Inter・角丸のカード・アイコンの箱を 3 つ並べた格子が語られる（S56。体感）。原因を学習データの偏りと説明する記事もあるが、推論で、測定は無い（S57・S59）
- 作り方（目安）: 避けるのではなく、被写体の業界・素材・言い回しから決める（S55）。作る前に、同種の依頼で誰でも出す既定の案と比べ、変えた点と理由を言う（S55）
- 出典と時点: S54・S55（取得時点）、S56〜S59（2025-10〜2026-06 の記事）
- 批判・飽き: 避ける定番の様式も、一斉に使えば次の定型になる（本 skill の整理（推測））。AI の既定の出力をそのまま使うことが画一化の原因という見方（S59 の統計的な産物という説明。区分 C）は推論で、AI を使うこと自体の可否ではない
- 使うかの問い: この案を、同じ依頼を出した別の人も得そうか（S55）

## 古くなった傾向（周期の証拠）

様式が数年で次の様式に置き換わった例。今の傾向も同じ運命をたどると想定して、部品（光沢・透明・グラデ）の理由を言える形にしておく。

## 改訂のしかた（古くなった傾向を外す）

この台帳は、更新しなければ古い予測を事実のように見せてしまう。次の手順で改訂する。

1. 日付: 更新したら、冒頭の「時点」と、各行の出典の日付を書き換える。見直しの間隔は、半年を目安にする（本 skill の目安。出典なし）。傾向の出どころの記事が更新されたと分かったときも見直す
2. 出典の再取得: 各行の出典の URL を取り直し、引用が残っているかを確かめる。取り直した内容は、差分を人が確認してから台帳へ反映する（AI 向けの設計指針の文書は、書き換わりうる。S54・S55 の URL は、固定したコミットを指す）。引用が消えた・書き換わった行は、「予測が取り下げられた」可能性があるので、台帳から外すか、時点を明記して残す
3. 実測の有無: 実測（S50・S80・S81 のような）が無い行は、「予測」のラベルを外さない。採用率を測った出典が見つかったときだけ、「実測」の欄を足す
4. 外す基準（本 skill の目安）: (a) 出典が消えた、(b) 新しい予測記事・賞の評価で言及されなくなった、(c) 批判・飽きの記述が出典つきで増えた、(d) 制作例で採る理由が被写体から言えなくなった。2 つ以上に当てはまれば、「古くなった傾向」の表へ移す。移すときは、移した日と理由を書く
5. 足す基準: 出どころが 1 つ（ベンダーの予測だけ）の傾向は、「単一の予測」と明記して入れる。ベンダーの予測のほかに、実践の記録・賞の評価・実測のいずれかがあれば、行に出どころを併記する
6. 批判の併記: 行を足すときは、批判・飽きの欄を必ず書く。出典つきの批判が見つからなければ、「見つからなかった」と書き、本 skill の整理（推測）と分ける
7. 台帳（`sources.md`）: 新しい出典は S 番号を末尾に足す。番号は振り直さない。検証区分と取得日を付け、引用は取得本文から切り出して照合する
