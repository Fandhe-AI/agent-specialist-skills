# 例: ロゴのダークモード対応（ライトとダークの版の差し替え）

ライトの地を前提に作ったロゴが、ダークの地で背景に溶けて見えなくなったときの直し方を示す例。扱うのは、版を反転でなく明度の調整で作ること、単色版の扱い、自サイトでのインライン SVG と `light-dark()`、外部へ渡す画像の `<picture>` と `prefers-color-scheme`、常に白い面での固定、強制色モードでの姿、非対応のブラウザーでの姿である。小サイズ・単色・刻印への対応は `small-size-and-monochrome.md`、ロゴの形の設計は `startup-logo-wordmark.md` を開く。題材は架空で、実在のブランドのロゴ・配色の模倣は含まない。「ダークモードでロゴが見えない」「色を反転すればいいか」と言われたとき開く。

## 依頼

- 会社: 茶房「北灯茶房」（架空）。ロゴは、紺の本体の灯籠の形と、橙の灯の 2 色。名称は文字で、マークの右に置く
- 依頼文（架空）: 「サイトをダークモードに対応させたら、ロゴが背景に溶けた。色を反転すれば済むか」
- 使う場所: 自サイトのヘッダー（トップへのリンクを兼ねる）、HTML は書けるがインライン SVG とサイトの CSS が使えない場所（CMS の記事本文・外部の埋め込み枠など）、常に白地の領収書の画面
- 読み手: 端末の配色設定がライトの人とダークの人が混ざる（想定）
- 置いた前提: 手動のテーマ切り替えは無く、配色は端末の設定に従う。ロゴの形は変えない。マーク単体の最小幅は 32 px（本 skill の目安）

### 根拠の範囲（先に読む）

- 出典のある事実:
  - `<picture>` の `<source>` に `media="(prefers-color-scheme: dark)"` を付けて、ライトとダークの画像を差し替えられる（S42）。`prefers-color-scheme` は、利用者がライトかダークのどちらを求めたかを検出する（S43）
  - `light-dark()` は、有効な配色に応じて 2 つの色の一方を返す。`prefers-color-scheme` のメディア特性を要しない。使うには、`color-scheme` に `light dark` を指定する（S44）。`color-scheme` は、要素が描画できる配色を示す（S45）
  - 文字と背景のコントラスト比は 4.5:1 以上（S33）。ロゴ・ブランド名の文字は、この要求から除かれる。ただしロゴがリンクなどの UI 部品のときは、十分なコントラストの版を選ぶことが勧められる（規範ではない。S46）
- 時点情報（2026-11-16 取得）: `prefers-color-scheme` は 2020 年 1 月から（S43）、`light-dark()` は 2024 年 5 月以降の最新の環境で動く（S44）。古い環境は未確認
- 本 skill の目安（出典なし）: 色の値、版の数、最小幅、ダークの版の作り方（明度の直し方）
- 本 skill が描画して確かめた範囲（1 つの環境のみ）: `<picture>` と `light-dark()` が、ページの `color-scheme` の指定に追従するかの違い。結果は「点検」に書く
- 範囲外: ロゴの形の設計、小サイズ版の作り方、写真の上のロゴ、手動のテーマ切り替えの実装、商標の判断

## 目的の一文

「北灯茶房」のロゴを、ライトの地でもダークの地でも、灯を点した灯籠として見分けられるようにする。

## 削るもの

| 削るもの | 理由 |
|---|---|
| RGB の単純な反転 | 本体の紺は #e3d4ba（明るい生成り）になり使えるが、灯の橙は #47b8f5（青）になり、別のブランドに見える（本 skill の計算）。本体の明暗を入れ替え、灯は色相を保って明度だけ上げる（本 skill の整理） |
| ダーク専用の新しい形 | 形は固定し、変えるのは色の値だけにする。形を変えると、版の話がロゴの再設計に変わる |
| ライトの版を暗い地へそのまま置くこと | 紺 / 暗い地は 1.29（本 skill の計算）で、本体が見えない |
| ライトの橙を暗い地へ持ち込むこと | 橙 / 暗い地は 3.43 で、本 skill の基準 4.5 に届かない。灯だけ明度を上げる |
| グレーなど中間の版 | 版はライト・ダーク・単色の 3 つだけにする（本 skill の目安） |
| 手動のテーマ切り替え | 依頼にない。足す場合は `<picture>` が追従しないことがある（「点検」） |

## 構成

版の早見表を 1 枚にまとめ、担当者が載る面から 1 手で版を選べるようにする。

```text
版       本体      灯          使う面
ライト   紺        橙          ライトの地・常に白い面
ダーク   生成り    明るい橙    ダークの地
単色     1 色（灯も本体と同じ色。灯と窓の隙間で分ける）   1 色の印刷・外部の 1 色指定
```

- 固定: 灯籠の形（笠・本体・窓・灯の形）、窓と灯の最小の隙間（マークの幅の約 6%。4/64）、名称の字面
- 可変: 色の値（本体・灯）だけ
- 版は、利用者の設定でなく、ロゴが載る面の明暗で選ぶ。常に白い面（領収書の画面・印刷）は、ダークの設定でもライトの版にする（強制色モードを除く）
- 強制色モード（利用者が選んだ限られた配色がブラウザーに強制されるモード。S47）では、版を選ばない。変数を替えて、ロゴ全体をその配色の文字色の単色にする。単色版と同じ考え方で、灯は窓との隙間で分かれる。利用者の設定を尊重する判断で、固定する面もこれに従う（本 skill の判断）
- 渡し方は 2 通り。自サイトでは、インライン SVG の形を 1 つ持ち、色を CSS の変数で替える。変数の値は `light-dark()` で切り替える。インライン SVG とサイトの CSS が使えない場所には、ライトとダークの 2 つの SVG 画像を用意し、`<picture>` で出し分ける。`<picture>` も使えず、画像の指定しかできない場合は、載る面を指定してもらい、その面に合う版を 1 つだけ渡す。`<picture>` で渡すのはマークだけにする。名称の文字は、渡し先の本文（見出しや説明）として書けるため、画像に含めない（本 skill の判断）。渡す SVG には、width と height を付ける（本 skill の目安）
- 由来の確認: 地の明暗で画像を差し替える型は、`<picture>` の用法として書かれている（S42）。1 色の版は、フルカラー・全黒・全白を持つ型がある（S19）。単色かつ極小で再現できることを、Rand は必須条件と書く（S01、B・要旨）。サイズごとの版の分け方と最小サイズは `small-size-and-monochrome.md` に譲る

## 仕様

### 出典あり

| 項目 | 値 | 根拠 |
|---|---|---|
| 画像の差し替え | 既定の `<img>`（ライトの版）と、`<source media="(prefers-color-scheme: dark)">`（ダークの版） | S42、S43 |
| 色の切り替え | `light-dark(ライトの値, ダークの値)`。`:root` に `color-scheme: light dark` | S44、S45 |
| 文字のコントラスト | 通常の文字は 4.5:1 以上（S33）。ロゴ・ブランド名の文字は要求の対象外。ただしロゴがリンクなどの UI 部品のときは、十分なコントラストの版を選ぶことが勧められる（規範ではない。S46） | S33、S46 |
| 強制色モードの検出 | `@media (forced-colors: active)`。このモードでは、通常の文字の色が CanvasText に強制される | S47 |
| 対応の時点 | `prefers-color-scheme` は 2020 年 1 月以降、`forced-colors` は 2022 年 9 月以降、`light-dark()` は 2024 年 5 月以降の最新の環境 | S43、S47、S44 |

### 本 skill の目安（出典なし）

| 要素 | ライト | ダーク |
|---|---|---|
| 地 | #f6f2ea（生成り） | #11151e（藍に寄せた暗色） |
| 本体・名称 | #1c2b45（紺） | #eadfc9（生成り） |
| 灯 | #b8470a（橙） | #f0913f（明るい橙） |

- 色の方針: 本体の明暗を入れ替える。灯は色相（HSL で 21° から 28°）を近く保ち、明度だけ上げる（38% から 59%）。ライトでもダークでも「橙」と読める範囲にとどめる判断で、数値の根拠は出典なし
- コントラストの基準: 名称・図形（本体・灯）ともに 4.5:1 にそろえる。S33 は文字の基準で、図形への適用は未照合のため、本 skill の基準として置く
- 最小幅: マーク単体で 32 px 以上。窓と灯の最小の隙間は 4/64 で、32 px のとき 2 px（`small-size-and-monochrome.md` の目安「画面は 1 px 以上」を満たす）
- 単色版: 本体と灯を同じ色にする。色は載る面の本体の色（ライトは紺、ダークは生成り）で、比は下の表の 12.70 と 13.83 に同じ。灯と窓は隙間で分ける。写真などの上では、全黒か全白を、地の明るさで選ぶ（本例は写真を扱わない）
- 非対応の姿: `light-dark()` に非対応のブラウザーでは、`@media (prefers-color-scheme: dark)` の値（同じ色）が使われる。姿は同じで、端末の設定にだけ従う
- 固定する面: 常に白い面は、配色の設定に関わらず、変数の値をライトの値に固定する（本 skill の整理）。ただし強制色モードでは、面の地が利用者の配色に置き換わるため、この固定は成り立たない。そこでは、変数を CanvasText に替えて、ロゴ全体を単色にする（本 skill の判断）。黒と白の組は 21.00（本 skill の計算）
- 図形は変数を参照するだけにする理由: 図形（symbol の中）の `fill` は、文脈を持たない `style` で `var(--logo-ink)`・`var(--logo-flame)` を参照するだけにし、面ごとの差（単色・常に白い面・強制色モード）は、`<use>` の祖先（セルや文書の根）の変数に置いて、継承で届ける。`<use>` の複製（shadow tree）には、文書側の文脈つきの規則（`.mono .hk-body` のような子孫の指定）が当たらないことがある（レビューの指摘。本 skill は仕様の該当箇所を未照合）。描画で当たって見えても、それに頼らない（本 skill の判断）
- 強制色モードで、`fill` を指定し直さず変数を替える理由: 規則で指定した `fill` は、描画で強制されなかったため（本 skill の描画。1 つの環境）。ページが挙げる強制の対象に「SVG fill attribute」はあるが、規則で指定した `fill` への扱いは、この文から分からない（S47）

色とコントラスト。比は WCAG の相対輝度式で計算した値（本 skill の計算）。4.5:1 は文字の基準（S33）で、文字でない図形（灯・本体）に適用されるかは未照合である。本例は、図形にも同じ 4.5:1 をそろえて測る（本 skill の基準）。

| 橙 / 生成り | #b8470a / #f6f2ea | 4.77 | ライトの灯 |

| 明るい橙 / 暗い地 | #f0913f / #11151e | 7.68 | ダークの灯 |

## 文言

描画に出る文言は、確認表の見出し・代替テキスト・リンク名の 3 つ。ほかの行（版の表の見出し・外部への注記・連絡先）は、ガイドラインの文書や渡し先の説明で使う文言で、本例の描画には出ない。

| 場所 | 文言 | 理由 |
|---|---|---|
| 版の表の見出し（ガイドラインの文書） | ロゴの版は、載る面の明暗で選ぶ。色を反転して作らない | 禁止を先に言い、理由を添える |
| 確認表の見出し | 地に追従（インライン）／単色／ファイルで渡す（picture）／常に白地の面 | 担当者が渡し方を 1 手で選ぶ |
| 外部の記事本文・埋め込みへの注記（渡し先の説明） | ライトの版は明るい地専用、ダークの版は暗い地専用。逆の組み合わせにしない | 1.29 と 1.18 の組を避ける |
| 代替テキスト | 北灯茶房 | 名称を読ませる。`<picture>` の画像はマークだけだが、ブランド名を `alt` に入れる。単色の版も、色の違いは内容でないため、同じ名称にする |
| ヘッダーのリンク名 | 北灯茶房 トップへ | リンクの行き先を伝える |
| 連絡先（ガイドラインの文書） | 版の使い方の問い合わせ先（担当者名・メール） | 運用の責任者を明記する（本 skill の整理。強く関与する指導層がいればプログラムは根づく、という Olins の記述は S31、B・要旨） |

## コード断片

形は 1 回だけ定義し、図形の色は変数の参照だけにする。外部の CDN・スクリプト・フォント・画像ファイルは使わない。`<picture>` の画像は、ファイルを使わないため、SVG を data URI で示す（本番は 2 つの SVG ファイルにする）。ヘッダーのロゴは、`<a>` の中の SVG で、リンクの名前を `aria-label` で付ける。

色の値の再計算（標準ライブラリだけ。入力は上の hex）。表と本文の比・反転・HSL の値は、これで再現できる。

```python
import colorsys

def rgb(h):
    return tuple(int(h[i:i + 2], 16) for i in (1, 3, 5))

def lum(h):  # WCAG の相対輝度
    def f(c):
        c /= 255
        return c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4
    r, g, b = (f(c) for c in rgb(h))
    return 0.2126 * r + 0.7152 * g + 0.0722 * b

def ratio(a, b):
    hi, lo = sorted((lum(a), lum(b)), reverse=True)
    return (hi + 0.05) / (lo + 0.05)

def invert(h):  # RGB の単純な反転
    return "#%02x%02x%02x" % tuple(255 - c for c in rgb(h))

def hsl(h):  # 色相（度）と明度（%）
    hue, light, _ = colorsys.rgb_to_hls(*(c / 255 for c in rgb(h)))
    return round(hue * 360), round(light * 100)

pairs = [
    ("#1c2b45", "#f6f2ea"), ("#b8470a", "#f6f2ea"),  # ライト
    ("#eadfc9", "#11151e"), ("#f0913f", "#11151e"),  # ダーク
    ("#1c2b45", "#ffffff"), ("#b8470a", "#ffffff"),  # 常に白い面
    ("#1c2b45", "#11151e"), ("#b8470a", "#11151e"),  # 使わない組
    ("#eadfc9", "#f6f2ea"),
    ("#1c2b45", "#000000"), ("#b8470a", "#000000"),  # 強制色モードの修正前
    ("#000000", "#ffffff"),                          # 強制色モード
]
for fg, bg in pairs:
    print(f"{fg} / {bg}  {ratio(fg, bg):.2f}")
for h in ("#1c2b45", "#b8470a"):
    print(f"invert {h} -> {invert(h)}")
for h in ("#b8470a", "#f0913f"):
    print(f"hsl {h} -> {hsl(h)[0]} deg, {hsl(h)[1]} %")
```

## 点検

- 成立: ライトとダークの 2 通りで、ヘッダーと確認表の 4 つの面（地に追従・単色・ファイルで渡す・常に白地）の計 5 つを見る。本例で描画して確かめたのは、1 つの環境の、幅 1440・390・320 px、ライトとダーク
  - 横はみ出し 0（どの幅・配色でも、文書の幅と要素の右端の最大が、画面の幅と一致）
  - 解決された色は、仕様の表のとおり（ライトは #1c2b45 と #b8470a、ダークは #eadfc9 と #f0913f、常に白い面は両方の設定でライトの値、単色は灯も本体と同色）。描画された画素（ヘッダーと確認表の各面の本体・灯の位置）の色も、同じ値だった。強制色モードでは、すべて黒（ライト）または白（ダーク）の単色だった
- 計算: コード断片の Python を実行し、表と本文の比・RGB の反転・HSL の値が一致することを確かめた
  - `<picture>` は、ライトの設定でライトの版、ダークの設定でダークの版を選んだ
  - `light-dark()` の分岐を、成り立たない条件に差し替えた非対応側でも、同じ色・同じ版になった（`@media` の値で足りる）
  - Tab でヘッダーのリンクに移り、灯の色の輪郭が出た
- 強制色モード（幅 390 px、ライトとダーク。本 skill が 1 つの環境で確かめた）: 地は利用者の配色（ライトは白、ダークは黒）に置き換わった。強制色の規則（変数を CanvasText に替える）で、ヘッダー・確認表のすべての面のロゴが CanvasText の単色（ライトは黒、ダークは白）になり、比は 21.00（本 skill の計算。黒と白の組）。灯は窓との隙間で分かれて見えた。この規則が無い版では、常に白い面のロゴが、黒の地に紺と橙のまま残った（紺 / 黒 1.48、橙 / 黒 3.94。本 skill の計算）。`<picture>` の画像は強制されず色が変わらなかった。ライトの強制色ではライトの版、ダークではダークの版が選ばれ、読めた。端末の設定と強制色の配色が食い違う組み合わせは未確認で、画像の版は強制色に合わせられない
- 追従の違い（本 skill が 1 つの環境で確かめた。他の環境は未確認）: 端末の設定とは別に、ページが `color-scheme` を上書きすると（手動のテーマ切り替えの想定）、インライン SVG の変数は上書きに従ったが、`<picture>` は端末の設定のままだった（端末がライトで上書きがダークのとき、ダークの地にライトの版が出た。上書きは、後ろに `<style>:root { color-scheme: dark }</style>` を足して再現した）。`light-dark()` に非対応の側も、端末の設定のままである。手動の切り替えを足すときは、自サイトのロゴをインライン SVG の変数に寄せ、外部へ渡す画像は端末の設定に従う前提で渡す
- 色: コントラストは計算で、画面での見え（モニターの違い・屋外）と色覚の多様性は未確認
- 未確認: 他のブラウザー・実機・古い環境、メールクライアントや外部サービスでの SVG の扱い、印刷、`prefers-contrast` の設定、名称の文字の書体のライセンス
- 差別化: 灯籠と炎の形は一般的な図形で、他の茶房と並べて見分けがつくかは未確認。没個性化の批判（S28、C）に当たりうる。名称と形の組み合わせを、見分ける手がかりに置く

- 実在の模倣: 実在のブランドのロゴ・配色を写していない
