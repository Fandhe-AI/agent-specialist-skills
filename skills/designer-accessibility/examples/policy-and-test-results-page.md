# 例: ウェブアクセシビリティ方針と試験結果の公開ページ（信用金庫）

架空の信用金庫の「ウェブアクセシビリティ方針と試験結果」のページで、対応度の表記・試験の範囲・結果・未対応の予定・窓口を、合理的配慮の提供と環境の整備を混同せずに書く例。題材は架空で、実在の製品・企業の画面の模倣は含まない。**法的な助言ではない。** 個別の事業者に何が義務か、どう表記すれば足りるかは判断しない。「ウェブアクセシビリティ方針を書きたい」「『WCAG に準拠』と書いてよいか」「合理的配慮の窓口を載せたい」と相談されたとき、方針ページの構成と文面を決めるときに開く。制度の位置づけは `../references/jp-law.md`。

## 依頼

- 製品: 架空の「はなぞの信用金庫」のウェブサイトの、方針と試験結果のページ（架空）
- 依頼文（架空）: 「ウェブアクセシビリティの方針と、試験の結果を公開するページを作りたい。営業からは『WCAG 準拠』『JIS マーク取得』『2024 年から義務なので全ページ対応済み』と書きたいと言われている。合理的配慮の窓口も載せたい」
- 現状（架空）: 方針のページは無い。試験は、40 ページで行った（結果は表のとおり。値は架空）
- 想定ユーザー: 利用者（支援技術を使う人を含む）、取引先・調達の担当、自分たちの運用担当
- 範囲外: 法的な判断・助言、個別の契約や調達の要件、金融商品の説明の内容、実際の読み上げ

### 根拠の範囲（先に読む）

- 出典のある事実: 対応度の表記は「準拠」「一部準拠」「配慮」の 3 つ。「配慮」は、準拠・一部準拠に至らない場合に使う（S095）。JIS X 8341-3:2016 は JIS マーク表示制度の対象規格ではなく、適合したものに JIS マークを付ける行為はできない（S096）。総ページ数が 100 ページを超えるときは方式 d) を推奨し、合計 40〜50 ページ程度を試験対象にするとよい（S097）。総務省の運用ガイドラインは、方針の策定・AA に準拠（試験の実施と公開）・できる限り WCAG 2.2 に基づく構築を求める（S091）。JIS X 8341-3:2016 は ISO/IEC 40500 と完全一致する形に改正され（S102）、WCAG 2.0 に当たる（S094）。事業者の合理的配慮の提供は 2024-04-01 から義務（S081・S084）。ウェブの事前の対応は、環境の整備として努力義務（S079・S086・S088）。基本方針の例は、個別の申出に電話やメールで応じる（合理的配慮の提供）とともに、ウェブサイトを改良する（環境の整備）（S087）。ガイドブックは、記載の厳密な正確性や網羅性を担保しないと書く（S089）
- 「一部準拠」の条件（S095。表「各表記の要件」の「一部準拠」の行）: ウェブアクセシビリティ方針の提示又は公開が必須、試験を実施して達成基準の一部を満たしていることを確認する（試験結果の公開は任意）、追加で表記が必要な事項は今後の対応方針。目標の適合レベルの達成基準を全て満たしていないとき、今後の対応方針を示して「一部準拠」と表記できる。部分適合を適用するページの記述などの細部は、WAIC のガイドラインで確かめる
- 台帳に原文が無い: JIS X 8341-3:2016 に含まれる達成基準の一覧（未照合。WCAG 2.0 の達成基準の一覧で確かめる）
- 本 skill の目安（出典なし）: 表の列、文面、色・寸法、結果の記号。試験の日付・ページ数・結果は架空の値
- 外れる点: 総務省の運用ガイドラインは公的機関向けで、信用金庫（民間）にそのまま求められるとは、台帳の引用は述べない。方針と試験結果の公開は、参考として使う。デジタル庁は、JIS 試験の通過を公開の判定条件にしている（S168。同庁の運用の自己説明）

## 目的の一文

試験した範囲・版・結果・未対応の予定を、「準拠」と書けない部分も含めて正直に公開し、個別の申出への対応（合理的配慮）とサイトの改善（環境の整備）の窓口を、混同せずに示す。

| 削るもの | 理由 | 代わりに |
|---|---|---|
| 「WCAG 準拠」 | JIS X 8341-3:2016 の中身は WCAG 2.0（S094・S102）。2.2 に準拠したとは言っていない。対応度の表記は 3 つ（S095） | 「JIS X 8341-3:2016 への対応度は一部準拠」と版を書く |
| 「JIS マーク取得」 | JIS マークを付ける行為はできない（S096） | 書かない |
| 「全ページ対応済み」 | 試験したのは選んだページだけ（S097 の目安は、100 ページ超なら方式 d)・合計 40〜50 ページ程度。ページの選び方の内訳は引用に無く、WAIC のガイドラインで確かめる） | 「全 120 ページのうち、40 ページ」 |
| 「義務化されたので」 | 義務になったのは事業者の合理的配慮の提供（S081）。ウェブの事前の対応は環境の整備で努力義務（S086・S088） | 2 つの窓口を分けて書く |
| 未対応を載せない | 未確認・未対応を伏せると、適合に見える | 不適合を表に載せ、今後の対応方針を書く。試験が終わっていない基準が残るなら、対応度を表明しない |
| 法的な説明 | 判断はできない | 書かない。必要なら専門家に確認する |

## 仕様

### 表記と範囲

| 項目 | 仕様 | 根拠 |
|---|---|---|
| 対応度 | 「一部準拠」（架空）。「準拠」には至っていないと明記。条件は、方針の提示又は公開（必須）・試験の実施と達成基準の一部を満たしていることの確認・今後の対応方針（S095 の表）。この例は、AA の達成基準を全て試験し、2.1.1 が不適合なので、今後の対応方針を載せる。試験が終わっていない基準が残るなら、対応度を表明せず、試験の完了後に表明する旨を書く（本 skill の整理） |
| 基準 | JIS X 8341-3:2016、適合レベル AA。WCAG 2.2 の追加の基準を試験したなら、別の行に分けて書く | S094・S102。版の違いは S003・S039 |
| 試験の範囲 | 全 120 ページ（架空）のうち、40 ページ | 100 ページ超は方式 d)・40〜50 ページ程度（S097）。ページの選び方は WAIC のガイドラインで確かめる。値は架空 |
| 日付 | 試験の日と最終更新日。古くなったら更新する | 本 skill の整理 |
| JIS マーク | 付けない・書かない | S096 |

### 試験の結果の表

| 項目 | 仕様 |
|---|---|
| 構造 | `caption` を付け、列見出し・行見出しに `scope` を付ける（S150 の考え方。台帳の引用はキャプションまで） |
| 結果 | 記号（○ × △ －）と文字（適合・不適合・未確認・該当なし）の両方。色は補助 |
| 備考 | 不適合には、場所と直す予定を書く。未確認には、確かめる方法を書く |
| 幅 | 3 列。表だけを横スクロールの容器に入れる（`overflow-x: auto`）。容器には、キャプションを `aria-labelledby` で結んだ名前を付け、焦点を受けられるようにする（`tabindex="0"`。横スクロールする表は焦点を受けられるようにする。S154）。ページ全体は横にはみ出させない。1.4.10 の例外（2 次元の配置が要る内容）の全文は WCAG 本体で確かめる |
| JIS と WCAG 2.2 | JIS X 8341-3:2016 の試験の表には、WCAG 2.2 で足された基準や、2.0 に無い基準を混ぜない。WCAG 2.2 の基準は、別の表に「参考の確認」として分ける（JIS X 8341-3:2016 の中身は WCAG 2.0。S094）。ここでは、1.1.1 を JIS の表、2.5.8（2.2 で追加）と 4.1.3 を別の表に置いた |

### 窓口

| 窓口 | 何のためか | 文面の要点 | 根拠 |
|---|---|---|---|
| 個別のご要望（合理的配慮の提供） | 手続きに支援が必要な人の申出に応じる | 電話またはメールで知らせられる。申出に応じて、電話やメールで手続きを手伝う | S087 |
| サイトの改善（環境の整備） | 申出がなくても、使いにくさを減らす | 取り組みの状況を、この表で公開する | S086・S087 |

- 2 つの窓口を、同じ見出しの下に混ぜない。前者は「あなたの申出に応じる」、後者は「サイトを直す」
- 窓口は、ウェブの入力欄だけにしない。ウェブサイトが使いにくい人が、最初に使う連絡手段になるため（S087 の例は電話とメール）
- 連絡先は架空で、電話は 000-0000-0000 の形、メールは例示用のドメイン（example.jp）にする。`#contact` の行き先は、同じページの窓口の節
