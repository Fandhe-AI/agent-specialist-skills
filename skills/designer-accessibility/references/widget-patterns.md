# 部品の役割・状態・キー操作の型

独自の部品（ダイアログ・メニュー・タブ・コンボボックス・表の並べ替え・通知）を作る、または作り直すときに、HTML の要素で足りるかを先に決め、足りない所だけ ARIA を足し、役割・状態・キー操作をそろえるための参照。「ARIA の付け方を教えて」「独自のメニューをキーボードで使えるようにしたい」と相談されたとき、`../SKILL.md` の判断の型の 1 から開く。台帳に原文のあるものと、原文が無く APG の該当パターンで確かめるものを、列で分ける。出典の詳細は `sources.md`。「本 skill の整理（推測）」と書いた箇所は、出典が述べていない応用である。

## 先に読む

- APG（ARIA Authoring Practices Guide）は規範ではない。WCAG と ARIA が W3C の規範的な技術標準で、APG は参考の資料であり、適合モデルを持たない（S055）
- キー操作の一覧は規範ではないが、定着した慣習の大半は、要件として扱うのが望ましい（S056）。macOS 向けの記述が不足している既知の問題がある（S056）
- APG の例は、設計システムでも、本番用のコードでもない（S057）。コードを本番に使う前に、支援技術との相互運用性の試験が不可欠（S054）。APG は、どの例がモバイルのブラウザーやタッチ操作に対応しているかを示していない（S054）
- ARIA の役割は、ブラウザーのキー操作も見た目も付けない（S053）。誤った ARIA は、視覚の体験を取り違えて伝え、非視覚の体験に深刻な影響を与えうる（S052）。APG の Read Me First は「No ARIA is better than Bad ARIA」と掲げる（S052）
- Using ARIA の 4 つの規則は、廃止扱いの草案に残る（S063）。規範の根拠は WAI-ARIA 1.2（S047）と ARIA in HTML（S060・S061）
- 本 skill の台帳に、APG の原文があるのは、モーダルダイアログ（S058・S059）、キーボードインターフェースの実践（S071）、タブ（S251）、メニューボタン（S252）、メニューとメニューバー（S253）、コンボボックス（S254）、ディスクロージャー（S255）、ツリー（S256）である。リストボックス・グリッドなど他の部品は、APG の該当ページで確かめる。各パターンの引用は、キー操作と役割の要点だけで、例外や選択肢の全文は APG で確かめる

## 共通の原則

| 原則 | 内容 | 根拠 |
|---|---|---|
| ネイティブが先 | 同等の機能を持つ HTML の機能があるなら、それを使う。ARIA は、ホスト言語に必要な役割・状態・性質が無い場合に使う | S047・S062（S063 の位置づけを添える） |
| 役割は約束 | 役割を付けたら、その部品の作法（キー操作・状態）を実装する。役割だけではキー操作は付かない | S053 |
| 既定と重ねない | 要素の暗黙の ARIA の意味と同じ値を、role や aria-* で重ねない。「No role」の要素に role を付けない | S060・S061 |
| 焦点を受ける要素 | 焦点を受ける・操作できる要素の `presentation` は無視され、暗黙の役割で公開される | S049 |
| 隠すなら代わりを | 見えている内容を `aria-hidden` で隠すなら、同等の意味と機能を支援技術へ渡す | S048 |
| Tab と矢印 | Tab・Shift+Tab は部品から部品へ、矢印は複数の焦点可能な要素を持つ部品の中を動く | S071 |
| 名前 | 名前は隠れていて、支援技術にだけ渡ることがある。見えるラベルと名前は、多くの場合（全てではない）同じ | S032 |
| 名前の算出 | aria-labelledby の段（有効な IDREF がある場合）が先に処理される。tooltip 属性は、他に何も結果を与えなかった場合だけ使う（AccName 1.2 は作業草案） | S064・S065 |
| 状態の通知 | 状態メッセージは、焦点を受けずに提示できる形にする | S031・S051 |

## 部品ごとの型

「台帳にある型」は、引用ブロックに書かれた範囲だけである。「台帳に無い（APG で確かめる）」は、型の全体を APG の該当パターンで確かめる印である。

| 部品 | まず HTML で足りるか | 台帳にある型（役割・状態・キー操作） | 台帳に無い（APG で確かめる） | よくある誤り |
|---|---|---|---|---|
| ボタン・リンク | `button`・`a` で足りる | `div` に `role=button` だけを付けても、キー操作と見た目は付かない（S053）。名前は 4.1.2（S030） | - | `div` ボタン。見えるラベルと名前の不一致（名前は S032） |
| モーダルダイアログ | `dialog` 要素は、おおむね良い選択肢（S077。2023 年の実務家の見立て）。ただし他の部品の代わりに使うのは不適合（S072） | 名前が必須。中に焦点可能な子孫があるようにする。表示したらダイアログ内の要素へ焦点を移す（S050）。開いたら中へ。最後の要素から Tab で最初へ。Esc で閉じる（S058）。閉じたら呼び出し元へ戻す。取り消しにくい操作では、最も破壊的でない操作に初期焦点（S059）。モーダルの間、他は inert（S073） | モバイル・タッチでの挙動（S054） | 名前が無い。閉じても焦点が戻らない。メニュー・ツールチップに `dialog` を使う（S072）。確認を安全対策にする（S164） |
| 確認ダイアログ | モーダルと同じ。要否を先に問う | 破壊的な操作では、cancel に初期焦点（S158）。モーダルは最後の手段（S152） | `alertdialog` の型 | 実行側に初期焦点。Enter の連打で実行されうる（本 skill の整理） |
| サイトのナビゲーション | リンクの一覧（`nav` など。本 skill の整理）。正しく組めば ARIA は要らない（S067） | ARIA の menu の意味を使わない（S066） | - | `role=menu` をナビに付ける |
| アプリのメニュー | 要素だけでは足りない場合がある | メニューボタンは役割 button で、`aria-haspopup`（menu か true）を持ち、開くと `aria-expanded` を true にする。Enter か Space で開き、最初の項目へ焦点を置く（S252）。メニューが開いたら焦点は最初の項目。Tab は項目の間を動かさない。Esc で閉じて、開いた要素へ焦点を戻す。無効な項目は焦点を受けるが、実行できない（S253）。Bootstrap は、ARIA の menu に必要な role と aria- を、期待せず、自動でも付けない（S237） | menuitem の矢印の動きの細部（APG で確かめる） | 汎用のドロップダウンを、操作メニューとして使う。ナビに menu を使う |
| タブ | 要素だけでは足りない | タブは少なくとも 2 つのタブストップ（タブの列とパネル）（S161）。Tab は部品の間、矢印は部品の中（S071）。矢印で前後のタブが切り替わる実装がある（S240）。手動切り替えの実装もある（S235）。パネルの内容が DOM にあれば表示はほぼ即時。通信を伴うと、選択が焦点に従うのは有害になりうる。従わないとき、利用者は Enter か Space で選ぶ（S071）。唯一の正解は無い（S068）。APG: 役割は tablist・tab・tabpanel。tab は `aria-controls`、選択中の tab は `aria-selected=true`、tabpanel は `aria-labelledby`（S251）。Tab でタブの列に入ると選択中のタブへ焦点が置かれ、次の Tab でタブパネルへ出る。左右の矢印で前後のタブへ移り、端では反対側へ回る。Home は任意。パネルに焦点可能な要素が無いときは `tabindex="0"`。パネルが遅延なく表示できるなら、焦点で自動に選ぶことを勧める（S251） | 垂直のタブの矢印（上下）の細部 | 見た目だけがタブのナビゲーションに tablist を付ける。通信を伴うタブを自動切り替えにする |
| コンボボックス | `input` と `datalist` などで足りるか、要件で決める（本 skill の整理） | コンボボックスは Tab の順路に入る。Esc でポップアップを閉じる。Alt + Down Arrow は、ポップアップを焦点を動かさずに開く（任意）。役割は combobox で、`aria-controls`（ポップアップ）と `aria-expanded` を持つ。ポップアップは listbox・tree・grid・dialog。ポップアップが listbox・grid・tree のときは、中の項目へ移っても DOM の焦点は combobox に残り、`aria-activedescendant` が項目を指す。dialog のポップアップでの焦点の扱い（実際の焦点を中へ移すか）は引用に無く、APG で確かめる（S254） | リストボックスの項目の型。ライブラリの既定値は `library-defaults.md` の 5 | 打った値が焦点移動で消える。候補の件数を伝えない（本 skill の整理。`library-defaults.md` の 5） |
| データ表 | `table`・`caption`・`th` を使う（キャプションは S150。他は本 skill の整理） | 横スクロールする表は焦点を受けられるようにする（S154）。並べ替えを有効にするときは `aria-live` の領域を足し、並べ替えの状態の変化を知らせる。領域は読み込み前に HTML に置く（S154）。並べ替えの可否は注記する（S160） | `aria-sort` の値と、ソートボタンの名前の型（APG） | 並べ替えの状態が矢印アイコンだけ。横スクロールの表に焦点が入らない（S154）。JAWS・NVDA で左右の矢印キーでスクロールしない記録（S127） |
| トースト・通知 | 画面内に残る表示で足りるか先に問う（S069） | `status` は焦点を受けない（S051）。`alert` は割り込む（S051）。操作を含めず、焦点を受けさせない（S159）。通知の領域と通知を同時に差し込むと、読み上げられないのが通常（S238）。領域を先に置くのは本 skill の整理 | `log`・`alert` の型 | 結果をトーストだけに載せる。領域と通知を同時に差し込む（S238） |
| 開閉（ディスクロージャー） | `button` と開閉する内容。標準の `details` などを使えるかは先に問う（本 skill の整理） | 開閉のボタンは役割 button。内容が見えるとき `aria-expanded` は true、隠れているとき false。Enter か Space で開閉する（S255） | `aria-controls` の使い方（APG で確かめる） | 開閉の状態を持たない。見出しの代わりに `div` を使う |
| ツリー | 要素だけでは足りない | tree の中に treeitem。親の項目は `aria-expanded`（開いている true・閉じている false）。右矢印で閉じた項目を開く（焦点は動かない）。下矢印で次の項目へ（S256） | 左矢印・Home・End・先読みの細部、複数選択 | 開閉の状態が無い。矢印が効かない |
| ドラッグでの並べ替え | ボタンやメニューでの移動 | ドラッグの機能は、ドラッグなしの単一のポインター操作でできる（2.5.7。S024） | - | ドラッグしかない |
| スクロールする領域 | - | 焦点を受けられるようにする（S154） | - | キーボードで動かせない |

## 型を決める手順

1. HTML の要素で足りるかを決める（S047）。足りるなら、そこで終わる
2. 足りないなら、型を APG の該当パターンで確かめる。台帳にある範囲（S058・S059・S071・S251・S252・S253・S254・S255・S256）は上の表。APG は規範でないので、型を選んだ理由を記録する（S055）
3. 役割・状態・キー操作・名前・焦点の移り先を、部品の仕様として書く（下の雛形）
4. 実装し、ツリーとキーボードの順路を実測する（`audit-checklist.md` の 3）
5. 支援技術で確かめる。版と日付を記録する（S054）
6. 結果を「適合・不適合・該当なし・未確認」で書く

### 仕様の雛形

| 項目 | 書くこと |
|---|---|
| 名前 | 見えるラベルと、名前の算出元（S064） |
| 役割 | 要素の暗黙の役割か、足した役割。足した理由 |
| 状態 | 選択中・展開・押下・無効・必須など。状態を持つ要素と、ツリーに出ることの確認 |
| キー操作 | Tab の順路（タブストップの数）、矢印・Home/End・Enter・Space・Esc の動き |
| 焦点 | 開いたとき・閉じたとき・消えたときの移り先 |
| 通知 | 状態メッセージの形（`status` か `alert` か、領域を先に置くか） |
| 確かめた方法 | 実測（ツリー・順路）と、支援技術（製品・版・日付） |

## よくある誤り（再生産しない）

- `div` に `role=button` だけを付ける（S053）。焦点を受ける要素に `presentation` を付ける（S049）
- `button` に `role=button` を重ねる（S060）。「No role」の要素に role を付ける（S061）
- 見えている内容を `aria-hidden` で隠し、同等の代わりを渡さない（S048）
- 見えるラベルを消して、名前を `title` だけに頼る（S065。tooltip 属性は最後の段）
- `dialog` を、メニュー・ツールチップ・ポップアップのリストボックスに使う（S072）
- ダイアログに名前が無い（S050）。閉じても焦点が戻らない（S059・S128）
- サイトのナビに menu の意味を使う（S066・S067）
- 通信を伴うタブで、選択を焦点に自動で従わせる（S071）
- 通知の領域を、通知と同時に差し込む（S238）。トーストに操作を含める（S159）
- APG の例を、そのまま製品の部品にする（S054・S057）。「APG のとおりなら WCAG に適合」と言う（S055）

## 確認できなかったもの

- リストボックス・グリッドなど、S251・S252・S253・S254・S255・S256 に含まれない APG のパターンの原文（取得していない）。S251・S252・S253・S254・S255・S256 の引用は要点だけで、各パターンの全てのキー・例外・選択肢は載せていない
- 支援技術ごとの、ARIA の役割・状態の読み上げの差（版つきの記録は S122・S127・S128 のみ）
- モバイルの画面読み上げ（VoiceOver・TalkBack）での、各型の挙動
