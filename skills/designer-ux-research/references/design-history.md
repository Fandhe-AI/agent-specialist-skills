# デザイン史: UX リサーチ・ユーザビリティ検証・情報設計の変遷

調査・検証・情報設計の判断に歴史を使うための参照ファイル。年表の暗記用ではなく、「いま使われている手法・数値・慣習が、どんな制約の中で生まれ、何を引き起こしたか」を確かめるための材料である。要点（見取り図・繰り返すパターン・場面別の使い方）と、時代別の詳細を 1 つにまとめてある。中心の問いは次の 1 つ。

> その手法・数値・慣習を生んだ前提（同質の利用者・反復・予算・組織）は、今回も成り立つか。

成り立つなら、手法は今も根拠を持つ。成り立たないなら、数値や型だけが独り歩きしている可能性がある。時代ごとに同じ 4 項目（当時の制約 / 応答 / 副作用と反動 / 今の判断への示唆）で書いてある。

このファイルを開くのは、相談者が背景を求めたとき、調査計画・手法選定の着手前（「場面別の使い方」の節）、レビューで「人数・点数・手法の由来」が不明のとき、の 3 つである。

| 知りたいこと | 開く場所 |
|---|---|
| 全体像・時期ごとの動き | 「見取り図」 |
| ある手法・数値の由来（ヒューリスティクス・5 人・SUS・ペルソナ・カードソート） | 時代別の 6 つの節 |
| 横断の型 | 「繰り返すパターン（本 skill の整理）」 |
| 場面ごとに歴史から引く問い | 「場面別の使い方」 |
| 年・版が合わない項目 | 「年が食い違う出典」 |
| 俗説・確認できなかったもの | 「確認できなかったもの・よく語られる俗説」 |

## 読み方と記法

- 時点: 2026-11-15（出典の取得日）。出典の詳細（引用原文・日付・URL・検証区分）は `sources.md` にある。本ファイルの S 番号はその台帳の番号である。
- 4 項目めの「今の判断への示唆」はすべて「本 skill の整理（推測）」で、出典が述べた因果ではない。因果（「A だから B になった」）は、出典が述べている場合だけ S 番号付きで書く。
- 区分は `sources.md` の凡例に従う（A 原典、B 第三者の複製、C 批判・論評、R 機関・出版社・サイトの地の文、U 未検証）。批判・論評は C と明記し、本人の発言として書かない。
- 英語の逐語引用は区分 A の出典だけで、短くする。日本語は要旨で、本人の発言ではない。
- 出典どうしで年が食い違うものは、両方の出典を挙げる（「年が食い違う出典」）。
- 書籍・規格の本文は読んでいない。書籍・規格について述べるときは、それを引いたページの記述の範囲だけで書く。
- 日本の個人情報保護法・研究倫理の制度、日本語圏の UX・HCD の歴史は未調査である（「確認できなかったもの」）。
- 回答での使い方: 頼まれない限り、歴史を講釈しない。判断の根拠として 1 行で使う。

## 回答での使い方（例）

歴史は、判断の根拠として 1 行で添える。講釈にしない。

- 相談「5 人でテストすれば十分だよね」: 5 人の議論は、15 人で全部の問題が見つかるというモデルを置いたうえで、5 人の小さな調査を 3 回に分けて反復する主張だった（S16）。同質の利用者・反復という前提を確かめる。実測では 5 人組の発見率が 55% から 99% まで散らばった（S18。抄録）。全部見つけたとは書かない（S19）。
- 相談「ヒューリスティック評価で済ませたい」: 1990 年代の割引ユーザビリティ工学は、費用の思い込みで手法が使われない状況への応答だった（S67）。専門家の評価は、独立した 3 から 5 人で行う仮説で、利用者調査の代わりにならない（S22）。
- 相談「ペルソナを作りたい」: 最初のペルソナは、聞き取りで話した具体の 1 人が基になった（S73）。作っても十分に使われず、利用者とつながっているという誤った安心感を生む、という観察がある（C。S69）。何の調査に基づき、誰が使い、次の判断が何変わるかを先に決める（本 skill の整理）。
- 相談「SUS で何点なら合格か」: SUS は 1986 年に作者が同僚に自由に配布した尺度で、正式な標準化はされていない（S72）。500 件の調査の平均が 68 という NN/g の記述はあるが、小標本の平均点だけでは統計的に有意な知見にならない（S27。Sauro の分析は原論文未取得）。比べる相手を先に決める。
- 相談「デザイン思考のワークショップをやりたい」: Norman は 2010 年に広報用語と書き、2013 年に結論を改めて、観察を要件に挙げた（S04、S05）。利用者を観察する回があるかを先に聞く。

## 1. 1980 年代まで: 実務で使われていない、と Nielsen は述べる（1994 年のページ）

- 当時の制約: Nielsen は、ユーザビリティ工学が実務で使われない重要な理由の 1 つは手法の費用で、より正確には費用の思い込み（perceived cost）だと述べる（S67）。1985 年の Gould と Lewis の調査で、利用者中心の原則を問われた開発者のうち、3 原則をすべて挙げたのは 16% だったと伝える（S67。Nielsen が引いた二次の記述で、原論文は未取得）。
- 応答: 聞き取りを設計に結びつける試みが、個人の実践として現れる。Cooper は、1983 年から効果的な方法を探し始め、話を聞いた女性 Kathy が最初の原始的なペルソナの基になったと述べる（S73）。Brooke は、1986 年に SUS を同僚へ自由に配布した（S72）。
- 副作用と反動: 出典が述べる範囲では、手法が実務で使われていない状態に対して、簡単な方法のほうが実際に使われやすいという提案が出た（S67）。
- 今の判断への示唆（整理・推測）: 利用者を見ることが標準になった現在でも、見送りの理由は「手法を知らない」より「費用・時間の思い込み」であることがある。見送りの理由が、費用か、時間か、組織の合意かを先に聞く。

## 2. 1989〜1994: 割引ユーザビリティ工学と 10 のヒューリスティクス

- 当時の制約: 手法の費用の思い込み（前節。S67）。
- 応答: Nielsen の「割引ユーザビリティ工学」は、シナリオ・簡略化した思考発話・ヒューリスティック評価の 3 つの技法に基づく（S67）。簡単な方法のほうが、実際の設計で使われる見込みが高い、というのがその動機である（S67）。ヒューリスティクスは、1990 年 3 月に Molich と Nielsen が 9 項目で発表し（S14）、1994 年の書籍で Nielsen の 10 項目になった（S15）。NN/g のページは、これらが具体的なガイドラインでなく広い経験則だと述べる（S12）。思考発話法について、Nielsen は 1993 年の著書に、最も価値のある方法かもしれないと書いたと、2012 年の記事で述べる（S21）。
- 副作用と反動: 簡便な手法が広まった一方で、網羅できていないことへの注意が必要になった。ヒューリスティック評価は、独立した 3 から 5 人の評価者で行い、利用者調査の代わりにならない。個々の評価者は問題の一部を見落とす（S22）。評価チーム間で同じ結果が出るかを調べた CUE の調査は、答えは大半が否定的だったと報告する（S19）。CUE の調査年は台帳の出典から確認できず、この時代の出来事とは限らない。主題が近いのでここに置く。ヒューリスティック評価への当てはめは本 skill の推測である。
- 今の判断への示唆（整理・推測）: ヒューリスティック評価・思考発話は、早く仮説を出して直すための道具で、問題の網羅や利用者の実際の成功を保証しない。報告書には評価者数・手法・見ていないことを書く。

## 3. 1990 年代後半〜2000 年代前半: Web の普及、UX という語、「5 人」

- 当時の制約: Web の利用者は多様で、設計と評価の反復を速く回す必要があった（整理・推測）。Nielsen の 1997 年の調査は、被験者の 79% が新しいページを必ず流し読みし、16% だけが 1 語ずつ読んだと報告する（S28。当時の被験者の値で、現在の利用者には当てはめない）。
- 応答: 1998 年に Norman と Nielsen が UX を、利用者と企業・サービス・製品との関わりの全体と定義し、UI と区別すべきだと述べた（S06）。2000 年に Nielsen は 5 人でのテストを提唱した。根拠は、1 人あたりの発見率の典型値 31% を置いたモデルで、15 人で全問題が見つかる。それでも 15 人の 1 回の調査より、5 人ずつの 3 回の調査のほうが UX は大きく改善する、という反復の議論だった（S16）。2012 年の記事は、定性調査は 5 人という立場を維持し、定量調査は 20 人以上・カードソートは利用者グループごとに 15 人以上・アイトラッキングは 39 人という例外を示した（S17）。
- 副作用と反動: 「5 人」は、同質の利用者と反復という前提を落として流通した。Faulkner（2003）は、5 人組の発見率が 55% から 99% までばらついたと報告した（S18。抄録のみ。本文未取得）。Molich の CUE は、5 人は反復を回すには十分でも、問題を網羅したと主張してはならない、という立場を示す（S19。年は確認できず、この時代に属するとは限らない）。Nielsen の原典（S16）も、利用者層が複数あるときは層ごとに調べる必要があり、3 層以上なら各層 3 人としており、原典と批判は一部で矛盾しない。
- 今の判断への示唆（整理・推測）: 「5 人」は、反復を前提にした探索の議論として使う。確定の主張・比較・統計の議論には使わない。人数を聞かれたら、目的（探索か、確認か、定量か）と反復の回数を先に聞く。

## 4. 2000 年代: UX の拡張、ペルソナ、HCD への内部批判

- 当時の制約: ユーザビリティだけでは、製品の価値を語りきれないという認識が広がった（整理・推測）。Morville は 2004 年に、UX の 7 つの面（Useful・Usable・Desirable・Findable・Accessible・Credible・Valuable）を示し、使いやすさは必要だが十分ではないと書いた（S47）。情報設計（IA）は、物の部分を理解できるように配置するやり方と定義される（S48・S74）。
- 応答: Cooper の実践に始まるペルソナ（S73）について、Pruitt と Grudin（2003）は、他の定量・定性の調査手法を置き換えるのでなく補完する使い方を提案した（S65・S71）。Norman は 2005 年に、人間中心設計が無批判に受け入れられていると批判し、活動中心設計が優れると主張した（S03）。2008 年には、アフォーダンスは知覚されるものを語るべきこと、設計者が提供すべきは手がかり（signifier）であることを述べた（S01・S02）。SUS は、作者が 1996 年に章として刊行し（S72）、広く使われるようになった。
- 副作用と反動: ペルソナの形骸化への批判が出た。Merholz は、Portigal の論考（未取得）への応答として、多くのペルソナが本来の目的を果たしていないことは認めつつ、悪いペルソナが多いからといって実践を捨てるべきではない、と書いた（C。S64、2008 年）。2016 年には、ペルソナが十分に使われず、利用者とつながっているという誤った安心感を生むという観察が出た（C。S69）。SUS を industry standard と呼ぶ文献があるが、正式な標準化の過程を経ていないと作者自身が述べる（S72）。
- 今の判断への示唆（整理・推測）: 成果物（ペルソナ・ハニカム・ヒューリスティクス）は、調査の代わりでなく、調査の結果を共有・判断する道具として使う。作ったことでなく、次の判断が変わったかで点検する。

## 5. 2010 年代: デザイン思考の流行と批判、公共サービスの制度化

- 当時の制約: デザインの価値を、デザイナー以外にも説明する必要があった（整理・推測）。Norman は 2010 年に、デザイン思考は昔ながらの創造的思考の広報用語だと書いた（S04）。
- 応答: Design Council は、2003 年の経緯をページに書き、Double Diamond は既存のプロセスを成文化し、名前を付け直して広めたもので、巨人の肩の上に立っていたと当時の責任者が述べる（S33・S70）。別のページは 2004 年に公開されたと書く（S34）。英国政府は 2012 年に政府デザイン原則を公開し、最初の原則を Start with user needs とした（S35）。Service Manual は、利用者調査・同意・参加者募集・アクセシビリティの運用を文書化した（S36・S37・S38・S40・S42・S45）。Spool は 2011 年に、各メンバーが 6 週間に最低 2 時間、利用者が使うところを直接見る exposure hours を提唱し（S55・S54）、英国政府の研究者が 2014 年に実務での採用を紹介した（S46）。
- 副作用と反動: Norman は 2013 年に、2010 年の結論を改め、デザイン思考は特別だと書いた（S05）。Vinsel は 2017 年に、デザイン思考の拡大を強い論調で批判した（C。S62）。Pentagram は 2018-02-23 付のページで、Natasha Jen が講演「Design Thinking Is Bullshit」を行ったと書く（R。S63。講演の内容は未取得）。実験については、Miller が 2010 年に、結果を覗いて止める危険を示し（S60）、Kohavi らは 2014 年に、数千件の実験から、結果が良すぎるときは深く調べるという経験則を示した（S61）。Brignull の欺瞞的パターンの啓発は 2010 年から続く（S58）。Hall は 2016 年に、データ駆動設計が定量データを定性データより優れたものとみなす誤った信念を強めると批判した（S49）。
- 今の判断への示唆（整理・推測）: 「デザイン思考のワークショップ」は、利用者の観察を含むかで価値が分かれる。Norman 自身が 2013 年に挙げる要件は、利用者の理解、つまり観察である（S05）。公共サービスの運用ガイドは、同意・募集・謝礼・アクセシビリティの具体を書き、民間の調査でも参考になるが、英国の法令・組織が前提である（S40）。

## 6. 2018〜2026: 規格の更新、継続的ディスカバリー、倫理・アクセシビリティ

- 当時の制約: 製品の判断が日々続くと、案件ごとの調査だけでは追いつかなくなる、と Torres は述べる。作り手は専門知識を得ると、それを持たなかった頃を忘れる（S52）。
- 応答: Torres は、判断を続けるなら顧客との接点を保ち、少なくとも週に 1 回は関わるよう勧める（S52。Torres の推奨で、実証研究の結果ではない）。ISO 9241-11 は 2018 年版で、ユーザビリティを使用の結果ととらえる枠組みを示し、方法は定めない（S09）。ISO 9241-210 は人間中心設計の原則・活動を扱い、方法・技法の詳細は扱わない（S10）。日本の JIS Z 8530 は 2019 年に改正され、ISO 9241-210:2010 に対応する（S11）。WCAG 2.2 は、通常のテキストのコントラスト比 4.5:1 以上と、ポインター入力のターゲット 24 × 24 CSS ピクセル以上を定める（S59。ページ記載の日付は 2024-12-12）。NN/g の 2026-11-06 付の Usability 101 は、ユーザビリティはデザインだけの性質でなく、常に相対の主張（usable for whom, for which task, and under what conditions）だと述べる（S66）。
- 副作用と反動: この時期の副作用を示す出典は取得していない。倫理の面では、英国政府のガイドが、同意の撤回があれば収集済みのデータを削除すること、子どもや脆弱な成人では本人と保護者の両方の同意が要ることを定める（S40）。
- 今の判断への示唆（整理・推測）: 調査を案件でなく習慣として設計できるかを聞く。規格を根拠に挙げるときは、版（ISO と JIS で版が異なる）と、本文を読んだかを区別する。2020 年代の変化（遠隔調査の一般化・生成 AI の利用など）は、扱っていない。

## 繰り返すパターン（本 skill の整理）

次の型は、時代を横断して読み取ったもので、出典が述べた法則ではない。例外は多い。

1. 費用の思い込みが手法を遠ざけ、簡便な手法が広まると、網羅できているという誤解が生まれる。割引ユーザビリティ工学（S67）→ ヒューリスティック評価の注意（S22）→ CUE の不一致（S19。ヒューリスティック評価への当てはめは本 skill の推測）。
2. 数値は、条件が落ちて単独で流通する。5 人と 85%（S16・S18）、79% と 16%（S28）、SUS の平均 68（S27。Sauro の分析を NN/g が紹介する値で、原論文未取得）、A/B テストの 26.1%（S60）。数値には、時点・対象・条件を添える。
3. 態度と行動を分ける。言うことと、することは違う（S25）。インタビューは態度の手法で、行動の観察の代わりにならない（S29）。Norman は、観察を質問票・フォーカスグループより上に置く（S05）。
4. 成果物は、作ったことで終わりやすい。ペルソナ（C。S64・S69）、デザイン思考（S05・C。S62・R。S63）、調査報告（S54）。点検は、次の判断が変わったかで行う。
5. 利用者を直接見る人を増やす。exposure hours（S54・S55・S46）、継続的ディスカバリー（S52）。調査員が見て報告するだけでは、同じ効果が出ないと Spool は述べる（S54）。
6. 規格・枠組みは方法を定めない。ISO 9241-11 は枠組み（S09）、9241-210 は方法・技法の詳細を扱わない（S10）。Double Diamond は直線でない（S34）。手法の選択は、状況に合わせて行う。
7. 公共サービスの制度化は、同意・募集・謝礼・アクセシビリティまで運用を文書化した（S40・S42・S45）。民間でも参考になるが、法令は国ごとに違う（日本は未調査）。
8. 実験は、設計（標本数の事前決定）で信頼が決まる。覗いて止めない（S60）。良すぎる結果は疑う（S61）。結果が欺瞞の産物でないかも点検する（S58）。

## 場面別の使い方

調査計画・手法選定の着手前に、該当する場面の問いを歴史から引く。問いは判断を助ける材料で、結論ではない。

### 調査計画・手法選定

1. 何を決めるための調査か。報告書で終わらないか（S54）。
2. 態度の手法に偏っていないか。行動を見る手法と組み合わせたか（S25）。
3. 規格や枠組みを根拠に挙げるとき、版と、本文を読んだかを区別したか（S09・S10・S11）。

### ユーザビリティテスト

1. 5 人は、反復を前提にした探索の人数か。利用者層ごとに分けたか（S16・S17）。
2. 「全部見つけた」と書いていないか（S19）。
3. 課題文は、答えの経路を言っていないか（S38）。
4. SUS を使うなら、比べる相手と標本の大きさを決めたか（S27）。

### ヒューリスティック評価

1. 評価者は独立に 3 から 5 人か（S22）。
2. 結果を、利用者調査の代わりにしていないか（S22）。
3. 別の評価者でも同じになるかを、報告に書いたか（S19。CUE の知見の当てはめは本 skill の推測）。

### インタビュー

1. 態度の手法の限界（想起の誤り・社会的望ましさ）を踏まえ、行動の観察で補うか（S29）。
2. 誘導質問を同僚と予行して直したか（S29・S39）。
3. 同意・録音・撤回を、台本の冒頭に入れたか（S40）。

### 情報設計

1. まとまりと名前を見つける調査（カードソート）と、決めた階層で見つけられるかの検証（ツリーテスト）を分けたか（S24）。
2. カードソートの結果をそのまま採用していないか。50 枚を超えるカードで「その他」が膨らんでいないか（S23・S24）。
3. IA を Web の画面だけの話にしていないか（S48・S74）。

### ペルソナ・デザイン思考

1. ペルソナは、聞き取りに基づく具体の人から始まったか（S73）。他の調査の代わりでなく補完か（S65）。
2. 作ったあと、次の判断が変わったか（S64・S69）。
3. デザイン思考の場に、利用者を観察する回があるか（S05）。

### 結果の共有・倫理

1. 共有資料から、参加者の個人データを除き、匿名化したか（S41）。
2. 同意の内容（目的・データ・共有先・任意・撤回・保存期間）を、事前に参加者へ示したか（S40）。
3. 障害のある人・支援技術の利用者を、計画・募集の段階から含めたか（S36・S42・S43）。
4. 日本の法令・社内規程の確認は、この歴史の範囲外である（本 skill は判断しない）。

### A/B テスト

1. 標本数を事前に決めたか。覗いて止めていないか（S60）。
2. 結果が良すぎるとき、深く調べたか（S61）。
3. 数字が上がったことが、利用者を欺いた結果でないか（S58）。
