# 例: 図書館サイトの情報設計の見直し（カードソート → 案 → ツリーテスト）

メニューの階層とラベルを「利用者の言葉でまとまりと名前を見つける（発見）」→「案を作る」→「決めた階層で見つけられるかを確かめる（検証）」の順で見直す例。題材は架空の組織で、実在の図書館・製品の模倣は含まない。調査の計画・文言・集計の最小例を示す。数値は、出典のあるもの（S 番号つき）と、本 skill の目安（出典なし）を分ける。

## 依頼

- 製品: 架空の「みなと市立図書館」公式サイト（運営は架空の「みなと市」）。現行のメニューは 6 項目で、「その他」の下に 24 ページが積み上がっている（架空の前提）
- 依頼文: 「メニューの『その他』が増えて探しにくい。カードソートとツリーテストで見直したい」
- 利用者グループ（本 skill の分け方・出典なし。典型の利用者だけを見ない考え方は S37）: A 子どもと来館する保護者 / B 調べものや仕事で使う成人 / C Web に不慣れな人・支援技術の利用者・館内で配慮を求める人
- 未提供の情報: アクセス解析・問い合わせ履歴。項目の優先順位に使う場合は相談者が確認する（この例からは分からない）

## 目的の一文

利用者が自分の用事の言葉で最初に開く項目を選べる階層に組み替え、「その他」をなくし、実装の前に、決めた階層で見つけられるかを課題で確かめる。

見つけやすさは UX の 1 つの面で、優先順位とトレードオフを明示して決める（S47）。IA は、物の部分を理解できるように並べるやり方である（S48）。

## 削るもの

調べない問いと、載せない結果。

| 削るもの | 理由 |
|---|---|
| 色・レイアウト・リンクの目立ち方 | ツリーテストは階層の評価だけを行う手法（S24）。見た目は実装後に課題つきのテストで見る（S38） |
| サイト内検索・蔵書検索の結果画面 | 今回の問いは「メニューで見つけられるか」。検索は別の調査にする |
| 「どのメニュー名が好きか」の質問 | 好みや人気を聞くだけにしない（S36） |
| 現行ラベルを並べる閉じた分類 | 現行の分類をなぞる結果になりやすい（本 skill の整理）。山の名前は参加者がつける |
| 40 枚×全グループの詳細統計 | 読む人の判断に要るのは、まとまりの核と、間違い先と、グループ間の違いだけ |
| 「項目は 7 つまで」「3 クリック」の基準 | 具体的な数の根拠として使わない。数でなくツリーテストの結果で決める |

## 構成

```text
0 確認   現行の棚卸し・利用者グループ・既存データを聞く
1 発見   カードソート（40 枚。山の名前は参加者がつける） → まとまりと言葉を集める
2 案     結果を材料に階層とラベルを作る（結果をそのまま採用しない）
3 検証   ツリーテスト（現行と案を同じ 8 課題で） → 成功・直行・間違い先
4 修正   間違い先を見て置き場所とラベルを直し、再テスト
5 実装後 画面ができたら、課題つきのユーザビリティテストで見る
```

- 発見と検証を分ける。カードソートは分類の候補を見つける手法で、ツリーテストは階層の評価に使う手法（S24）。確かめずに決めれば推測にとどまる（S24 の趣旨）
- カードソートは、そのまま従うべき分類を出すとは限らない（S24）。利用者のメンタルモデルが違うため解釈が難しい（S23）
- 直したら再度確かめる。反復はプロセスの原則（S34）

## コード断片

1. カードソートの類似度（同じ山に入れた人の割合）と「その他」の数え上げ。標準ライブラリのみ。データは例示用の架空（4 人×6 枚）:

```python
from collections import Counter
from itertools import combinations

cards = {"c01": "返す日を延ばす", "c02": "貸出中を予約", "c03": "読み聞かせ会",
         "c04": "古い新聞", "c05": "コピー機", "c06": "寄贈"}
sorts = [  # 1 人 = {自分でつけた山の名前: [カード ID]}
    {"借りる": ["c01", "c02"], "子ども": ["c03"], "調べる": ["c04"], "館内": ["c05"], "その他": ["c06"]},
    {"本の手続き": ["c01", "c02", "c06"], "催し": ["c03"], "資料": ["c04"], "設備": ["c05"]},
    {"借りる": ["c01", "c02"], "調べもの": ["c04", "c05"], "行事": ["c03"], "その他": ["c06"]},
    {"貸出": ["c01", "c02"], "子ども": ["c03"], "調べる": ["c04"], "使う": ["c05", "c06"]},
]
pair = Counter()
for s in sorts:
    for members in s.values():
        for a, b in combinations(sorted(members), 2):
            pair[(a, b)] += 1
ids = sorted(cards)
for a in ids:  # 類似度 = その 2 枚を同じ山に入れた人数 / 全員
    print(a, *(f"{1.0 if a == b else pair[tuple(sorted((a, b)))] / len(sorts):.2f}" for b in ids))
misc = Counter(c for s in sorts for g, ms in s.items() if g in {"その他", "雑多"} for c in ms)
print("その他に入れた人数:", {cards[c]: k for c, k in misc.items()})
```

実行結果（例示データ）: c01 と c02 の類似度は 1.00（全員が同じ山）、c06「寄贈」は最大でも 0.25 で、2 人が「その他」に入れた。「寄贈」のように核を持たないカードは、置き場所を決める前に山の名前の語を読む。類似度は案の材料で、階層は人が決める（S24）。

2. ツリーテストの集計。成功＝正解の節点を選んだ、直行＝成功かつ途中で戻らなかった（指標名は本 skill の整理）。割合の 95% 区間は標準の Wilson 式（出典台帳の外）。データは例示用の架空:

```python
from collections import Counter
from math import sqrt

rows = ([("t01", "borrow/renew", False)] * 11 + [("t01", "borrow/renew", True)] * 3
        + [("t01", "borrow/rules", False)] * 4 + [("t01", "search/catalog", False)] * 2
        + [("t04", "care/large-print", False)] * 8 + [("t04", "search/catalog", False)] * 7
        + [("t04", "care/large-print", True)] * 2 + [("t04", "kids/lists", False)] * 3)
correct = {"t01": {"borrow/renew"}, "t04": {"care/large-print"}}  # 事前に決めた正解

def wilson(k, n, z=1.96):
    d = 1 + z * z / n
    c = (k / n + z * z / (2 * n)) / d
    h = z * sqrt(k / n * (1 - k / n) / n + z * z / (4 * n * n)) / d
    return max(0.0, c - h), min(1.0, c + h)  # 0 人・全員のとき 0〜1 を超えないようにする

for t in sorted(correct):
    rs = [r for r in rows if r[0] == t]
    ok = [r for r in rs if r[1] in correct[t]]
    direct = [r for r in ok if not r[2]]
    lo, hi = wilson(len(ok), len(rs))
    miss = Counter(r[1] for r in rs if r[1] not in correct[t]).most_common(2)
    print(f"{t} 成功 {len(ok)}/{len(rs)} (区間 {lo:.0%}-{hi:.0%}) 直行 {len(direct)}/{len(rs)} 間違い先 {miss}")
```

実行結果（例示データ）:

```text
t01 成功 14/20 (区間 48%-85%) 直行 11/20 間違い先 [('borrow/rules', 4), ('search/catalog', 2)]
t04 成功 10/20 (区間 30%-70%) 直行 8/20 間違い先 [('search/catalog', 7), ('kids/lists', 3)]
```

読み方（本 skill の整理）: 20 人の成功率は区間が広く、点の値を強調しない。成功率は「なぜ」を言わない（S26）ので、間違い先に注目する。t04 は間違い先が「本・資料を探す」に偏る。その下に入口（別名）を置くか、置き場所を移す案を作り、再テストする。5 人程度の小標本の定量データは有意な結果になりにくいと NN/g は述べる（S27）。20 人でも区間は広い（上の出力）。

## 初見検証

実装後の新しいメニューを、説明なしで初めて見る人（利用者グループごと）に見せ、3 つの問いに答えられるかを見る。

| 問い | 期待する答え | 確認する場所 |
|---|---|---|
| 何に注意するか | 最上位の 7 項目のうち、自分の用事に近い語 | 課題の最初に選んだ項目 |
| 何を操作できるか | 項目を開き、中の項目から用事を選べる | 開いた画面の見出しと一覧 |
| どう操作するか | 迷ったら戻って別の項目を開ける | 戻った回数・「その他」を探す人の有無 |

答えられない課題は、説明を足さず、置き場所とラベルを見直す。戻りが多い課題は、ラベルの語でなく置き場所を疑う（本 skill の整理）。

## 点検

- 目的: 一文で言える。発見（カードソート）と検証（ツリーテスト）を分けた（S24）
- 人数: 根拠に条件と出所を添えた（S17）。ツリーテストの人数は出典が無い（本 skill の目安）と書いた
- 課題文: 目的を場面つきで与え、答えの経路とラベルの語を言っていない（S30・S38）
- 結果: 分類をそのまま採用していない。「その他」を作っていない。間違い先と区間を併記した
- 参加者: 同意・撤回・保存期間・謝礼の時機を設計した（S40・S42）。グループ C を含めた（S37・S43・S45）
- 手法の限界: ツリーテストは階層とラベルだけを測り、見た目や検索は見ない（S24）。実装後は課題つきのテストで見る（S38）
- 推測の明示: 利用者の用事の頻度・アクセス解析・館の規程が要る判断は、最終的に相談者が行う。日本の法令・規程の確認は別に要る
