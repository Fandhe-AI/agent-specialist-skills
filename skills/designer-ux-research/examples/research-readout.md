# 例: 経営会議向けの調査結果共有資料

ユーザビリティテストの結果を、調査の場にいなかった経営会議の出席者へ渡す資料の例。判断が変わる点を先頭に置き、事実・解釈・推奨を分け、分かっていないことと手法の限界を書く。題材・参加者・結果はすべて架空で、実在の製品・企業・個人の模倣は含まない。数値は、出典のあるもの（S 番号つき）と、本 skill の目安（出典なし）を分ける。

## 依頼

- 製品: 学習塾向けの面談・振替予約アプリ「コマ取り」（架空。運営は架空の会社「トビラ社」）
- 依頼文: 「調査結果を経営会議で共有したい。改善の優先順位を決めたい」
- 読み手: 経営会議の 5 人（社長・営業・開発・CS・財務）。調査の場にはいない。会議の持ち時間は 15 分（本 skill の目安）
- 調査（架空）: 思考発話つきの個別テストを各 45 分、2 日間で実施。保護者 6 人・教室スタッフ 5 人。課題は保護者が 2 つ（面談の予約・欠席した授業の振替）、スタッフが 1 つ（振替枠の設定の変更）。課題後に SUS
- 既存のデータ: 解約率・問い合わせ件数は未提供。この例からは分からない

## 目的の一文

経営会議が、振替予約の導線を直すかどうかを、見たこと・考えたこと・分かっていないことを分けて受け取り、その場で判断できる。

## 削るもの

調べていない問いと、載せない結果。

| 削るもの | 理由 |
|---|---|
| 解約・継続の意向、料金の受容性 | 今回は測っていない。「調べていない」と明記し、推測で埋めない |
| 所見の全 40 件 | 判断に要る 3 件に絞る。残りは別紙で、本編に載せない |
| SUS の平均点の見出し | 小標本の平均点は大きく語らない。単独では意味が薄い（S27）。付録に個別の点を置く |
| 参加者の属性つきの発言（「小 4 の母」など） | 特定につながる。個人データを除き、匿名化する（S41） |
| 録画の切り抜き | 同意で伝えた共有先に経営会議が含まれるか未確認。含まれるまで使わない（S40） |
| 「問題をすべて洗い出した」という書き方 | 5 人前後は反復を回すには足りるが、全部見つけたとは言えない（S19） |
| 改修の費用・工数 | 調査の範囲外。開発の見積と合わせて会議で決める |

## 構成

```text
1 結論と判断   お願いしたい判断 / 推奨 / 確度 を 1 枚に（先頭）
2 調べたこと   手法・人数・募集・見ていないこと
3 見たこと     事実だけ（n 人中 k 人）
4 考えたこと   解釈（確度と別の説明つき）
5 推奨         選択肢・確かめ方。費用は調査の範囲外と書く
6 分かっていないこと  限界と、次に確かめる方法
付録 A 参加者と同意の範囲   付録 B SUS の個別の点と読み方
```

- 調査は、デザインが最も答えを必要とする問いに答えるためにあり、調査のための調査はしない（S49）。先頭は判断の依頼と推奨にする（本 skill の整理）
- 事実・解釈・推奨は混ぜない。1 枚に 1 種類。事実の枚に「〜と感じている」を書かない（本 skill の整理）

## 仕様

| 項目 | 値 | 根拠 |
|---|---|---|
| 資料の長さ | 本編 6 枚 + 付録 2 枚。1 枚 2 分程度 | 本 skill の目安（出典なし） |
| 調査の実施条件 | 1 セッション 45 分、1 日 6 人以下（11 人を 2 日） | 30 から 60 分・1 日 6 セッションまで（S38。英国政府の運用） |
| 層の扱い | 保護者とスタッフを混ぜて集計しない | 利用の仕方が違う層は両方で調べる（S16）。人数は層ごとに書く |
| 人数の書き方 | 「n 人中 k 人」。20 人未満は % で書かない | 20 人は定量調査の目安（S17）。% を避けるのは本 skill の整理 |
| 確度の表記 | 高・中・低。観察が 1 人なら低。複数人でも別の説明が残るなら中 | 本 skill の整理（出典なし） |
| 手法の限界 | 全問題を見つけたとは書かない。人数・層・見ていないことを書く | S19 |
| SUS | 個別の点と範囲を付録に置く。比べる前の版・競合が無い。68 は別の調査の平均で、基準にしない | 採点は S72 と S08（区分 B の要旨）。平均 68 は 500 件の分析を NN/g が紹介する値（原論文未取得）で、0〜100 は百分率でない（S27） |
| 匿名化 | 個人データを除く。属性の組合せで特定されないか確かめる | S41。組合せの点検は本 skill の整理 |
| 共有範囲 | 同意で伝えた目的・共有先の範囲内に限る | S40 |
| 観察への招待 | 出席者が次回の 1 セッションを直接見る | 6 週間に 2 時間の経験則（S54）。調査会社の知見で査読を経ていない |

SUS の質問文は著作権表示があるため転載しない。法令・社内規程・研究倫理審査の確認は別に要る。S40・S41 は英国政府の運用で、日本の要件を満たす保証は無い。

## 文言

結果は架空。参加者の発言は匿名化済みの架空の例。

| 場所 | before | after | 理由 |
|---|---|---|---|
| 1 枚目の見出し | ユーザー調査の結果報告 | 振替予約の導線を直すかを、本日ご判断いただきたい | 判断が変わる点を先頭に置く（本 skill の整理） |
| 1 枚目の結論 | 概ね使いやすいが、改善点が複数ある | 保護者 6 人中 3 人が、欠席した授業の振替を完了できなかった。推奨: 入口を直す試作を作り、5 人前後で再確認する（確度: 中） | 結論と推奨と確度を 1 枚に |
| 事実 | 保護者は予約画面を分かりにくいと感じている | 保護者 6 人中 3 人が振替を完了できなかった。うち 2 人は最初に「予約」を開いた | 感想でなく見たこと |
| 解釈 | （なし） | 入口が「予約」と別にあることが主因と考える。確度は中（観察は 2 人）。別の説明: 課題文の「欠席」が予約を連想させた | 解釈と確度と別の説明を分ける |
| 推奨 | ボタンを大きくする | 欠席の登録の直後に振替枠を出す案を試作し、5 人前後で確かめる | 原因と対応を結ぶ。5 人前後は反復の前提（S16） |
| SUS | SUS は平均 65.9 で、業界平均 68 並み | 付録に個別の点。保護者 6 人は 27.5 から 77.5 に開く。比べる前の版が無い | 平均点を強調しない（S27） |
| 限界 | 本調査で問題を網羅した | 11 人で見えた範囲。支援技術の利用者は含められなかった。解約・継続は測っていない | S19・S37・S45 |
| 参加者 | A さん（小 4 の母）は、灰色の枠を見て諦めた | 保護者の 1 人は、灰色の枠を「満席」と読んで諦めた | 匿名化（S41） |

選択肢（5 枚目）: A 振替の導線を次の四半期の最優先にする / B 試作と再確認（5 人前後）をしてから優先順位を決める（推奨）/ C 見送る。それぞれの前提と、決めるために要る情報（費用の見積・解約との関係）を併記する。

## コード断片

1. 所見台帳（JSON）と検査。事実・解釈・推奨を別の項目にし、解釈は事実から、推奨は解釈から導く。台帳に無いことは資料に載せない。ファイル名は `findings.json`:

```json
{
  "decision": "振替予約の画面改修を、次の四半期の最優先にするか",
  "not_seen": ["解約・継続の意向", "支援技術の利用者", "スマートフォン以外の端末"],
  "findings": [
    {"id": "F1", "type": "fact", "n": "保護者 6 人中", "text": "課題 1（面談の予約）を完了: 6 人"},
    {"id": "F2", "type": "fact", "n": "保護者 6 人中", "text": "課題 2（欠席した授業の振替）を完了: 3 人"},
    {"id": "F3", "type": "fact", "n": "F2 の未完了 3 人中", "text": "最初に「予約」を開いて枠を探した: 2 人"},
    {"id": "F4", "type": "fact", "n": "F2 の未完了 3 人中", "text": "灰色の枠を「満席」と読んで断念した: 1 人"},
    {"id": "F5", "type": "fact", "n": "スタッフ 5 人中", "text": "課題 3（枠の設定の変更）を自力で完了: 4 人。残る 1 人は進行役のヒントで到達（完了に数えない）"},
    {"id": "I1", "type": "interpretation", "from": ["F2", "F3"], "confidence": "中",
     "text": "入口が「予約」と別にあることが、未完了の主因と考える",
     "alternative": "課題文の「欠席」が予約を連想させた可能性"},
    {"id": "I2", "type": "interpretation", "from": ["F4"], "confidence": "低",
     "text": "灰色の枠の意味が伝わっていない可能性がある",
     "alternative": "この 1 人の読み方が特殊だった可能性"},
    {"id": "R1", "type": "recommendation", "from": ["I1"],
     "text": "欠席の登録の直後に振替枠を出す案を試作する", "verify": "保護者 5 人前後で課題 2 の完了を見る"},
    {"id": "R2", "type": "recommendation", "from": ["I2"],
     "text": "灰色の枠に理由の文を添える案を、R1 の試作に含める", "verify": "同じ回で、灰色の枠の読み方を聞く"}
  ]
}
```

```python
import json
with open("findings.json", encoding="utf-8") as fp:
    d = json.load(fp)
by = {f["id"]: f for f in d["findings"]}
need = {"fact": ("n",), "interpretation": ("from", "confidence", "alternative"),
        "recommendation": ("from", "verify")}
parent = {"interpretation": "fact", "recommendation": "interpretation"}
for f in d["findings"]:
    miss = [k for k in need[f["type"]] if not f.get(k)]
    bad = [x for x in f.get("from", []) if by[x]["type"] != parent[f["type"]]]
    assert not miss and not bad, (f["id"], miss, bad)
assert d["findings"], "findings が空"
assert d["not_seen"], "見ていないことが空"
print("OK", {t: sum(f["type"] == t for f in d["findings"]) for t in need})
```

実行結果: `OK {'fact': 5, 'interpretation': 2, 'recommendation': 2}`。

2. SUS の採点（付録 B 用）。奇数項は（回答 − 1）、偶数項は（5 − 回答）、合計に 2.5 を掛ける。質問文は載せず、項目の番号順の回答だけを持つ。平均でなく個別の点と中央値・範囲を出す。データは例示用の架空:

```python
from statistics import median

responses = {  # 1 人 = 項目 1〜10 への回答（1〜5）
    "保護者": [[4, 2, 4, 2, 3, 2, 4, 3, 4, 2], [3, 3, 3, 3, 3, 3, 3, 3, 3, 3],
              [2, 4, 2, 4, 2, 3, 2, 4, 2, 4], [4, 2, 4, 1, 4, 2, 4, 2, 4, 2],
              [3, 3, 3, 2, 3, 3, 3, 2, 3, 3], [4, 2, 3, 3, 4, 2, 4, 3, 3, 2]],
    "教室スタッフ": [[4, 2, 4, 2, 4, 2, 4, 2, 4, 2], [5, 1, 4, 1, 5, 2, 5, 1, 4, 2],
                  [4, 3, 3, 3, 4, 2, 4, 3, 4, 3], [5, 1, 5, 1, 5, 1, 5, 1, 5, 1],
                  [3, 3, 4, 3, 3, 3, 3, 3, 3, 3]],
}
def sus(r):
    if len(r) != 10 or any(x not in (1, 2, 3, 4, 5) for x in r):
        raise ValueError("回答は 1〜5 を 10 件")
    return 2.5 * sum((x - 1) if i % 2 == 0 else (5 - x) for i, x in enumerate(r))

for group, rs in responses.items():
    s = sorted(sus(r) for r in rs)
    print(f"{group} n={len(s)} 個別 {s} 中央値 {median(s)} 範囲 {s[0]}-{s[-1]}")
```

実行結果（例示データ）:

```text
保護者 n=6 個別 [27.5, 50.0, 55.0, 65.0, 70.0, 77.5] 中央値 60.0 範囲 27.5-77.5
教室スタッフ n=5 個別 [52.5, 62.5, 75.0, 90.0, 100.0] 中央値 75.0 範囲 52.5-100.0
```

読み方（本 skill の整理）: 層ごとに分け、混ぜた平均を出さない。点は「なぜ」を言わない。成績（完了・時間）と併用する（S27）。5 人・6 人の点は、層の中でも大きく開く。

## 初見検証

会議の前に、調査に関わっていない同僚 1〜2 人（本 skill の目安）に 1 枚目だけを見せ、30 秒後に答えてもらう。

| 問い | 期待する答え | 確認する場所 |
|---|---|---|
| 何に注意するか | 「振替の導線を直すかを判断する会議」 | 1 枚目の見出し |
| 何を操作できるか（何を決められるか） | A 最優先 / B 再確認してから / C 見送り の 3 択 | 1 枚目の選択肢 |
| どう操作するか（次に何をするか） | 推奨は B。決めるために費用の見積が要る | 推奨と、足りない情報の欄 |

答えられない場合は、説明を足さず、1 枚目の要素を減らす。「確度: 中」の意味が伝わらない場合は、凡例を 1 行足す。

## 点検

- 目的: 判断が変わる点を先頭に置いた。何を決めるためかを一文で言える（S49）
- 分離: 事実・解釈・推奨が別の枚・別の項目で、解釈は事実から、推奨は解釈から導かれる（上の検査が通る）
- 数値: 「n 人中 k 人」で書き、層ごとに分けた。SUS の平均点を強調していない（S27）。20 人未満の % を書いていない
- 限界: 「全部見つけた」と書いていない（S19）。見ていないこと（解約・支援技術の利用者・他の端末）を書いた（S37・S45）
- 参加者: 個人データを除き、属性の組合せで特定されない（S41）。録画・引用は同意で伝えた共有先の範囲内（S40）
- 終わり方: 報告書で終わらない。出席者が次回の 1 セッションを観察する（S54）
- 推測の明示: 解約率・費用・社内の事情が要る判断は、最終的に相談者と経営会議が行う。日本の法令・規程の確認は別に要る
