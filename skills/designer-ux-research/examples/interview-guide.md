# 例: ユーザーインタビューガイド

開発前に、現場の実際のやり方を知るためのインタビューガイドの例。導入の台本・話題ごとの質問・誘導質問の書き換え・記録の形式までを 1 本にまとめる。題材は架空の製品・会社・参加者で、実在のものの模倣は含まない。インタビューの質問を作るとき、または質問が誘導していないかを点検するときに開く。

## 依頼

- 製品: 介護事業所向けのシフト管理ツール「そろいシフト」（架空。開発元は架空の会社「そろい舎」）。まだ作り始めていない
- 依頼文: 「現場が実際にどうシフトを組んでいるか知りたい。『こういう機能があったら使いますか』を聞いて回ればいいよね」
- 想定する参加者: 介護事業所（通所・訪問・入所）で、毎月のシフトを組む人（管理者・責任者など）
- 先に確認したこと: 調査の結果で決める判断は「最初に作る機能の優先順位」。期限は開発計画の確定の 6 週間前。既存のデータは営業の聞き取りメモだけ（偏りがありうる）

## 目的の一文

シフトを組む人が、直近の 1 か月分を、何を見て・誰と調整して・どこで手間取って組んだかを知り、最初に作る機能の優先順位を決める。

「どんな機能がほしいか」ではなく、「いま実際にどうしているか」と、そこでの言葉・道具・困りごとを集める。

## 削るもの

| 削るもの | 理由 |
|---|---|
| 「こういう機能があったら使いますか」型の質問 | 仮定への好みは、行動の根拠にならない。求めるものと必要なものは違う（S35）。何が好まれるかでなく、何がうまくいくかを見る（S36） |
| 「普段」「平均」を聞く質問 | 想起の誤りに弱い（S29）。直近の 1 回の具体的な出来事を聞く（本 skill の整理） |
| 介護を受ける人・家族の氏名や状況 | 本題に不要な個人情報は集めない。実物を見せてもらうときも、名前は伏せてもらう（本 skill の整理） |
| 職員個人の評価・勤務態度への意見 | 聞き手が判断できず、参加者の負担も大きい。出たときは深追いしない |
| 給与計算・勤怠の詳細 | 別の製品領域。今回の判断（シフト作成）と関係しない |
| 人員配置の決まりの解釈 | 法令の判断はしない。事業所が「守るべきと感じている決まり」を聞くだけにする |
| 価格の受け入れやすさ | 態度の質問で、今回の判断に使えない。別の調査にする |
| 満足度の点数 | 数を取る調査ではない。理由（なぜ）は点数で分からない（S26） |

## 構成

```text
事前: 募集 → 同意の文書 → 同僚で予行（S39）→ 修正
本番（1 回 60 分。1 対 1）
  0:00  導入・同意の確認・録音の開始            5 分
  0:05  背景（役割・事業所の種類・シフトの人数）   5 分
  0:10  直近の 1 回をたどる                    25 分
  0:35  いま使っている表や道具の実物            10 分
  0:45  困りごとの深掘り                       10 分
  0:55  聞き忘れ・締め・撤回の再確認             5 分
事後: 当日中に記録を整理 → 全員分を並べて照合 → 判断への影響を書く
```

- 話すだけで終わらせない。インタビューは態度の手法で、実際の行動は観察しないと分からない（S29）。実物を見せてもらうほか、2 事業所では、シフトを組む作業を 1 回そばで見せてもらう計画を別に立てる（本 skill の整理）
- 順序は、直近の出来事 → 実物 → 困りごと。先に困りごとを聞くと、答えが「大変です」に偏る（本 skill の整理）

## 仕様

出典のある値には S 番号を付ける。「目安」は本 skill の目安（出典なし）で、規格や法令の要件ではない。

| 項目 | 値 | 根拠 |
|---|---|---|
| 1 回の長さ | 60 分（英国政府の運用は 30 分〜2 時間） | S39 |
| 人数 | 初回 6 人（通所・訪問・入所を 2 人ずつ）。新しい話が出なくなるかを見て増減する | 目安。人数は出典なし |
| 募集 | 経路を混ぜる。紹介だけ・営業の知人だけにしない。募集会社に使うときは、除外される人がいないか確かめる | S42 |
| 参加者の幅 | 現行のやり方で困っている人を含める。「うまくいっている事業所」だけを見ない | S37 |
| 謝礼 | 最初に渡す。金額は規程に従う（出典に金額なし）。強制になるほど過大にしない | S42、S56 |
| 記録 | 音声のみ。同意があるときだけ。顔・実名・事業所名は記録に入れない | S40、S41。音声のみは本例の設定 |
| 観察者 | 1 人（記録役）。参加者に、観察者がいることと誰かを伝える | S40 |
| 実物の扱い | 見せてもらうだけ。写真・コピーは受け取らない。名前は伏せてもらう | 本 skill の整理（本例の設定） |
| 撤回 | その場で中止し、集めたデータを削除する。あとからの取り下げも受ける | S40 |
| 話したくない話題 | 飛ばしてよいと最初に伝える（参加は任意。S40）。つらい話題では強いストレスを与えない（S56）。聞き手が案件を辞退してよい仕組みも置く | S40、S44、S56 |
| 保存期間 | 6 か月（本例の設定。実際は社内規程で決める） | 目安 |
| 予行 | 同僚相手に実施し、分かりにくい質問を直し、話題の順を見直す | S39 |

## 文言

導入の台本（読み上げる。同意の項目は S40）:

> 今日はお時間をいただき、ありがとうございます。シフトを組む仕事の実際を教えていただくために、お話を伺います。正解はありません。実際にあったことを、そのまま教えてください。
> 内容は音声だけを録音します。同席するのは記録役の 1 人で、お話は私たちの開発の参考にだけ使い、報告では事業所や個人が分からない形にします。録音は 6 か月後に削除します。
> 答えたくない質問は、飛ばしていただいて構いません。途中でやめても、あとで取り下げても構いません。取り下げた場合は、録音などをすべて削除します。
> ここまでで、気になる点はありますか。よろしければ、録音を始めます。

質問ガイド（切り出しの質問と、深掘りの質問を、話題ごとに分ける）:

| 話題 | 切り出しの質問 | 深掘りの質問 |
|---|---|---|
| 背景 | いまのお仕事で、シフトにどう関わっていますか | 何人分を、どのくらいの間隔で組みますか |
| 直近の 1 回 | 直近でシフトを組んだときのことを、最初から順に教えてください。何から始めましたか | そのとき手元に何がありましたか。次に何をしましたか。誰かに確認しましたか |
| 変更 | 組んだあとに変更が出た、最近の例を教えてください | 誰がどう知らせましたか。そのとき何を見て直しましたか |
| 実物 | いつも使っている表や道具を、見せられる範囲で見せてもらえますか。名前は隠して構いません | この部分は、どうしてこの形ですか。いつ開きますか |
| 困りごと | その作業で、いちばん時間がかかったのはどこでしたか | そのときは、どうやって切り抜けましたか |
| 締め | 聞き忘れたことで、お伝えしたいことはありますか | 話を聞くとよい方はいますか（紹介だけに頼らないため、募集の経路は別に持つ。S42） |

誘導質問の書き換え（誘導質問が多いと、データの妥当性が損なわれる。S29）:

| 書き換え前 | 書き換え後 | 理由 |
|---|---|---|
| シフト作りは大変ですよね | 直近の月のシフトで、いちばん手間がかかった作業は何でしたか | 同意を促す言い方を避ける。評価でなく出来事を聞く |
| シフトを自動で作る機能があったら使いますか | 直近のシフトで、人が手で考えて決めた部分はどこですか | 仮定の好みを聞かない。どこが手作業かの事実を聞く（S25、S35） |
| 表計算は使いにくくありませんか | いま使っている表を、見せられる範囲で見せてください。どんな時に開きますか | 道具への評価を先に言わない |
| 平均するとシフト作りに何時間かかりますか | 直近の月は、何日にどのくらいの時間をかけましたか | 平均は想起の誤りに弱い（S29）。直近の 1 回にする |
| 急な欠勤の穴埋めは、いつも大変でしょう | 最近、急に人が足りなくなった日のことを教えてください | 感情の断定を避ける。つらい話題には配慮が要る（S44） |

## コード断片

1 人 1 ファイルの記録（JSON）。事実（聞いたこと・見たこと）と解釈（なぜか）を別の項目に分ける。実名・事業所名は入れず、参加者は ID で呼ぶ。同意の証拠は、文書そのものでなく参照番号で持つ（S40）。

```json
{
  "participant_id": "P03",
  "facility_type": "visiting_care",
  "role": "shift_planner",
  "session_date": "2026-12-08",
  "consent": {"recording": "audio", "observer_count": 1, "evidence_ref": "C-003", "withdrawn": false},
  "retention_until": "2027-06-08",
  "notes": [
    {"topic": "last_shift_walkthrough", "kind": "fact",
     "text": "先月分は、希望の聞き取りの紙を見ながら、表に手で並べた"},
    {"topic": "last_shift_walkthrough", "kind": "interpretation",
     "text": "希望の集め方が最初の手間かもしれない（P01・P02 と照合して判断）"}
  ]
}
```

撤回と保存期限を、人の記憶に頼らず点検する関数（撤回されたデータは削除する。S40）。この関数は削除すべきかを判定するだけで、ファイルは消さない。実際の削除は、保存場所・バックアップ・複製まで含めて社内規程に従って行う。

```python
from datetime import date

def should_delete(record, today):
    """撤回された記録、または保存期限を過ぎた記録なら True。"""
    withdrawn = record["consent"]["withdrawn"]
    expired = date.fromisoformat(record["retention_until"]) < today
    return withdrawn or expired

# 上の記録に対して: 2026-12-09 は False、2027-06-09 は True、withdrawn を true にすると True
# （3 つとも実行して確認した値）
```

## 初見検証

ガイドと台本を初めて読む人に、何を理解し・何をすればよいかを確かめる。

| 読む人 | 確かめること | 期待する答え | 外れたときの直し方 |
|---|---|---|---|
| 参加者（導入の台本） | 何が録音され、やめたいときどうするか | 「音声だけ」「いつでも取り下げられ、削除される」 | 取り下げの段落を、録音の段落の直後に移す |
| 参加者（実物を見せる依頼） | 何を見せ、何を隠すか | 「名前は隠して、見せられる範囲で」 | 見せてよいものを具体例で足す（表の列の種類など） |
| 聞き手（同僚での予行） | 質問が、はい・いいえで答えられる形になっていないか | 質問は「どのように」「いつ」「何を」で始まる | 誘導の表の形に書き換える |
| 記録役 | 事実と解釈を分けて書けるか | 発言は事実の欄、推測は解釈の欄 | 1 例を示して、再度予行する |
| 依頼者（計画の要約） | この調査で決まることと、決まらないこと | 「最初の機能の優先順位は決まる。価格・満足度は分からない」 | 「削るもの」の表を要約の先頭に置く |

## 点検

- 目的の一文に、決める判断（最初に作る機能の優先順位）が入っている
- 質問が、仮定・好み・「普段」ではなく、直近の具体的な出来事を聞く形になっている（S29、S35）
- 同僚で予行し、分かりにくい質問と話題の順を直した（S39）
- 同意の項目（目的・データ・録音・観察者・結果の使い方と共有先・任意・撤回・保存期間）を、導入の台本に入れた。同意の証拠を保管する（S40）。日本の個人情報保護法・研究倫理の要件を満たすとは言えない。法令・社内規程・倫理審査の確認が要る
- 実物の扱い（見せてもらうだけ・名前を伏せる）を決め、観察者にプライバシーの責任を説明した（S41）
- つらい話題を飛ばしてよいこと、聞き手が辞退してよい仕組みを置いた（S40、S44）
- 募集経路を混ぜ、現行のやり方で困っている人を含めた（S37、S42）
- 結果の共有では、インタビューは態度の手法であり、観察で補う必要があると書く（S29）。「現場はこうだ」と言い切らず、6 人で見えた範囲と書く
- 推測の明示: 本例の人数・順序・保存期間・種類の分け方は本 skill の目安で、個別の事業所の事情は分からない。介護の制度や配置の決まりについては、本例は判断しない
