# OSS・UI ライブラリの既定値の台帳（時点情報）

管理画面の表・一覧・詳細画面を OSS や UI ライブラリの上で作るとき、「何もしないと何が出るか」と「既定のままだと弱くなる点」を確かめるための台帳。「このライブラリで管理画面を作って」「ライブラリの表が見にくい」と相談されたとき、`../SKILL.md` の「既定値の点検」から開く。ライブラリを選ぶための比較表でも、優劣の評価でもない。出典の詳細（引用原文・URL・検証区分）は `sources.md` を参照する。

## 読み方（先に読む）

- 時点情報: 各行の値は、台帳の「版」「取得日」の項にある時点のものである。版は各リポジトリの既定ブランチの先頭コミットで、リリースタグではない。API の既定値は版で変わる。取得日は、下の「版と取得日」の表に載せた。使う前に、自分の版で原稿を確かめる
- 列の意味: 「既定値」と「根拠」は出典のある事実で、取得した原稿に書かれていた値に限る。「既定のままだと弱い点」は、本 skill の整理（推測を含む）で、出典の事実ではない。なぜ弱いか・どう直すかは、すべて本 skill の整理である
- 「既定に無い」と言えるのは、不在の記録（S281。要旨・逐語引用なし）の範囲だけである。範囲は下の「不在の記録」に書いた。範囲外の「書いていない」「見当たらない」は、不在とは主張しない（確かめていないだけである）
- 写さない: 見た目・コード・スクリーンショットは、この skill へ写さない。拾うのは、何を出す・出さない・どう符号化するかの判断と、既定値の傾向だけである
- ライセンス: 取得した原稿のライセンスは、MIT・BSD-3-Clause・Apache-2.0 である。MUI X は Data Grid の MIT 部分だけを見ており、Pro・Premium は商用ライセンスで、本文は引用していない（S210・S215）
- AI エージェント向けの skill・プロンプトは、公開されたリポジトリのものだけである。流出したプロンプトは使っていない

| 知りたいこと | 開く場所 |
|---|---|
| どの版・いつの値か | 「版と取得日」 |
| 数字・列・状態・空・件数・密度・狭い画面・固定・一括・並べ替え・日付・詳細の既定値 | 「既定値の台帳」の 1〜12 |
| 「既定に無い」と言える範囲 | 「不在の記録」 |
| AI エージェント向けの公開 skill が指示していること | 「AI エージェント向けの公開 skill」 |
| 既定のままだと弱い点の点検表 | 「既定値の点検」 |
| 台帳の古くなった行の直し方 | 「改訂のしかた」 |

## ライブラリの上で作るときの助言（本 skill の整理）

1. ライブラリを選ぶ前に、列の型を持つ表（MUI X・react-admin）か、型を持たない部品（Ant Design・shadcn/ui・Tremor）かを見る。型があれば数字は右揃えになる。Filament は `numeric()` で桁がそろう（tabular figures）が、右揃えは別に指定する（S245、S227）。型が無ければ、揃えも桁も自分で作る
2. 見た目の部品を足す前に、列・状態・詳細の見出しの定義（データ）を作る。部品の差し替えは後でできる
3. ヘッドレス（TanStack Table）は見た目の既定を持たない。上に載せた部品の既定を、そのまま信じない
4. 有料版の機能（MUI X の列の固定）を前提にしない。MIT 版の上限（1 ページ 100 行まで）も確かめる
5. 状態の色は、利用側が割り当てる。色の名前を意味にせず、状態ごとに文字を決める
6. 支援技術の既定は部品で差が大きい。`aria-sort`・行見出し・キーボード操作は、使う部品の文書で確かめてから足す

## 改訂のしかた

台帳は数か月で古くなる。次の順で直す。

1. 版を取り直す: 各リポジトリの既定ブランチの先頭コミットと日付を確かめ、「版と取得日」の表を書き換える
2. 値を照合し直す: 各行の根拠の原稿を取り直し、コマンドラインで取得して固定文字列で検索し、引用ブロックの語が今もあることを確かめる。取得先は、台帳に載っている公式のドメインに限る。取得したものは実行せず、照合にだけ使う。変わった値は新しい値へ直し、変わったことを版の表の下に日付つきで 1 行書く
3. 外す基準: ライブラリが終了した・API が置き換わった・有料版へ移った・最終コミットが 1 年を超えて古い（1 年は本 skill の目安。Tremor は 2025-10-10 で、すでに古い側にある）。外す前に、同じ観点を別のライブラリで補えるかを確かめる
4. 足す基準: 点検表に新しい観点が出た、または相談で繰り返し尋ねられたライブラリがある。足す前に、原稿の逐語を確かめる（出典にない値は書かない）
5. 不在の記録: 「無い」は、範囲（ディレクトリ・ファイル・語）を書いた記録だけを根拠にする。範囲を広げたときは、範囲ごと取り直す
6. 「既定のままだと弱い点」: 出典が付かない本 skill の整理である。出典のある事実と混ぜない
7. 台帳の行を直したら、`../SKILL.md` の記述（既定値の点検の導線）と、`sources.md` の該当項目を合わせて直す
