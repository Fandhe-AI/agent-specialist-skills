# レビュー観点チェックリスト

管理画面・業務画面の案を出す前の自己点検と、他者の案のレビューに使う全項目のチェックリスト。`../SKILL.md` の「レビュー観点チェックリスト」から開く。制作モードで案を出す前、または「この画面を見て」と頼まれたときに、各項目で「はい / いいえ / 不明」を付け、いいえと不明を改善案に結びつける。

- [ ] 誰が・何の作業を・どの頻度で行うかを一文で言える
- [ ] 作業の手順を、「表 → 機能 → 説明 → 色」の順で作っていない（記事の A さんの手順。S282、S293）
- [ ] 列を識別・判断・詳細確認に分け、一覧は判断に要る列に絞った
- [ ] 先頭列は人が読める識別子で、列の順は重要度である
- [ ] 数字は右揃えで桁がそろい、単位は見出しにあり、同じ列で書式を混ぜていない
- [ ] 状態は色だけでなく、形と文字がある。灰色にしても区別できる
- [ ] 既定の並び順と、その理由が書かれている（期限・優先度・経過）
- [ ] 空は 2 種類（データ無し・絞り込みで 0 件）、空欄は 2 種類（未設定・存在しない）に分けた
- [ ] 狭い幅の出し方を、条件を添えて選び、320 px で横にはみ出さない
- [ ] 作業の画面で、1 画面目に一覧が主役として見えている
- [ ] 同じ情報を複数の場所に重ねていない
- [ ] 選択行・現在の行・ホバー・フォーカスが別々の見せ方になっている
- [ ] 行やボタンを作り直した後の焦点が、同じ要素（`data-id` で探す）か次の操作の位置へ戻り、`body` に落ちない（`../examples/filters-views-bulk-actions.md` の仕様の節の焦点の行。本 skill の整理）
- [ ] 詳細の見出しに、名前・状態・いま要る判断の材料・主な操作がある。最重要のメモが履歴に埋もれていない
- [ ] 表の中の図は、置く条件を満たす列だけにあり、置かなかった列とその理由が書かれている
- [ ] 時間は、相対と絶対の使い分けを決め、期限と経過が示されている
- [ ] 一括操作に、選択件数・範囲・結果・取り消しがある
- [ ] 長い名前・空欄・0 件・1 件・多件・桁違いの数値で描画して見た
- [ ] 1440・390・320 px、ライトとダーク、キーボードで確かめた。1440 px で文字だけを 200% にしても横にはみ出さない（`html { font-size: 200% }` の近似とブラウザの文字サイズ設定の両方で確かめる。列を減らす切り替えは、容器に `container-type: inline-size` を付け、閾値を `rem` か `em` で書いた container query にし、どちらでも実際に切り替わることを測る）
- [ ] 個人情報は一覧に出さず、詳細でも権限で伏せている。電話・メールは必要な作業のときだけ全体を出す（本 skill の整理）
- [ ] UI ライブラリの既定のままの点を、点検表で確かめた
- [ ] 作った本人とは別の目で見直した
- [ ] 実在の製品・サイトの画面の見た目を写していない
