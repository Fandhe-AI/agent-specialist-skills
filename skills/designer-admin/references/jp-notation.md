# 国内の表記（日付・桁区切り・単位・和暦・文言）

日本の業務画面の表記（日付・時刻・数字・金額・和暦・文言・全角半角）について、SmartHR・デジタル庁などの規則の要旨を集めたファイル。`../SKILL.md` の「国内の表記」から開く。日付や金額の書式、ボタンや見出しの文言、監査ログの文体を決めるときに開く。

出典は SmartHR・デジタル庁などで、要旨は逐語引用なし（S274・S275・S276・S277・S278・S279・S280）。固定の規則ではなく、既存の製品の規則が優先する。

- 数字は半角の算用数字、3 桁ごとに半角カンマ。人は名、書類・申請は件と数え分ける（S274。要旨）
- 日付は 2025/01/01、時刻は 24 時間制で hh:mm:ss、期間は波ダッシュでつなぐ。機械が扱う日付は YYYY/MM/DD（S275。要旨）
- 金額の入力は、整数ならフォーカスを外した時点で 3 桁カンマに整形し、単位は前後に（S276。要旨）
- 和暦: 紙の書類が和暦の業務向けに、和暦を貼り付けると西暦へ変換する入力部品がある（S277。要旨）。デジタル庁は、和暦に対応した日付ピッカーを提供していない（今後対応予定）（S157）。内部は西暦で、入口で和暦を受ける形が共通する（本 skill の整理）
- 文言: 画面タイトルと項目名は名詞、ボタンは動詞（サ変動詞の する を省く）。ダイアログの見出しと実行ボタンの動作の語をそろえる（S278。要旨）。一覧であることが明らかな見出しには、一覧の語を付けない。戻るリンクは行き先を具体的に（S279。要旨）
- 監査ログは体言止めで統一し、管理者向けに一貫性・一覧性・検索性を優先する（S280。要旨）
- 支払い状態の語は、業務によって違う。未納・納付済み・一部納付・期限超過、または入金済み・未入金のどちらかに揃え、1 画面で混ぜない（本 skill の整理。台帳に出典は無い）
- 全角・半角の入力制約を、利用者に押し付けない。社員向けの業務システムに多い、という見解がある（S158。C。入力補正ライブラリの会社の発言で、利益相反がある）
