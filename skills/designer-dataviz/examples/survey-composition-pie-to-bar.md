# 例: 顧客調査の構成比（円グラフ 3 つを棒に替える）

「円グラフ 3 つで比べて」という依頼を、条件の照合で棒の一覧に組み替え、円を残してよい場面も 1 つ示す例。顧客調査・アンケートの構成比（内訳）を図にするとき、円グラフを使うか迷うときに開く。題材は架空の会社と調査で、実在の製品・企業の図表は模倣しない。

## 依頼

- 会社: 架空の文具通販「ことのは堂」。媒体は顧客調査の報告書（PDF）
- 依頼文: 「回答の内訳を、円グラフ 3 つで比べて見せて」（年代別の、いちばんよく使う支払い方法）
- 読み手: 営業企画の担当 4 人。年代で支払い方法の傾向が違うかを見て、決済手段の導入の順番を議論する
- 現状: 20 代・40 代・60 代の円グラフ 3 つ。4 区分を色違いで塗り、凡例は 1 つ。値のラベルなし
- データ（架空。単一回答の回答数）: 20 代 n = 120、40 代 n = 150、60 代 n = 80、合計 350

### 根拠の範囲（先に読む）

- 円グラフを使う条件として、英国政府の指針（S66）は、区分が 5 以下であること、区分が意味のある全体になること、突出した区分があることの 3 つを挙げる。Datawrapper は値が 5 つまでと述べる（S82）。値ラベルは 4 区分以下で有効（S123）。大きい順に並べ、12 時の位置から始める（S124）
- 円グラフの評価は割れている。Few は、量的な伝達の図の中で円グラフは最も効果が低いと評価し（S35。主張であり、実験の結果ではない）、部分と全体の関係が構造に組み込まれている強みは認める（S36）
- 「角度が読めないから避ける」とは書かない。研究者は、円グラフは角度で読まれていないと結論し（S43）、適否については何も述べないと限定している（S44）
- 突出した区分の閾値は S66 に無い。本例の目安（最大が 2 位の 1.5 倍以上）は、本 skill の目安（出典なし）である

## 目的の一文

営業企画の担当が、年代によって支払い方法の比率がどう違うかを 1 枚で比べ、決済手段の導入の順番を議論する入口にする。

## 削るもの

| 削るもの | 理由 |
|---|---|
| 円グラフ 3 つ | 次の表のとおり、3 つとも S66 の条件を満たさない。しかも、3 つの円の同じ区分を比べるには、離れた扇形の角度や面積を見比べることになる（本 skill の整理） |
| 凡例（4 色の照合） | 色の照合を読み手に課す。直接ラベルにする（S67） |
| 色の違いだけの区別 | 色だけで意味を伝えない（S60）。行の名前と値を文字で書く |
| 4 色の塗り分け | 比べたい差（電子マネーと代金引換）に色を絞り、ほかは灰色にする（本 skill の整理） |

円グラフの条件の照合（本例のデータ）:

| 条件（S66） | 20 代 | 40 代 | 60 代 |
|---|---|---|---|
| 区分が 5 以下 | 4 区分で満たす | 4 区分で満たす | 4 区分で満たす |
| 意味のある全体 | 単一回答の 100 %。満たす | 満たす | 満たす |
| 突出した区分がある | 最大 40 %（電子マネー）、2 位 35 %（カード）。1.14 倍で満たさない | 最大 40 %（カード）、2 位 30 %。1.33 倍で満たさない | カードと銀行振込が同率の 30 %。1.00 倍で満たさない |

S66 は、区分が似た大きさなら棒を使うよう述べる。3 つとも突出した区分が無いので、棒にする。

残すもの: 回答数（n）、各区分の割合（%）、単位、出典。Tufte は、図にデータの出どころと分析の過程の文書化を添えるよう述べる（S14）。

## 構成

```text

| 60 代は代金引換が 25 %                                          |

| 銀行振込           ███ 15 %      ████ 20 %      ██████ 30 %    |

```

- 行は全体の回答の多い順（クレジットカード 126 人 36 %、電子マネー 105 人 30 %、銀行振込 72 人 20.6 %、代金引換 47 人 13.4 %）に並べる。年代は列で、横軸（0〜50 %）は 3 列とも同じ。S69 は、各区分で何が起きているかは small multiples のほうが読みやすいと述べる（積み上げ棒の文脈で、本例への当てはめは本 skill の整理）
- 棒は 0 起点で、軸を切らない（S64、S126）
- 円グラフを残す場面（同じ調査の別の設問）: 「いちばんよく使う購入の経路」（単一回答、n = 350）は、アプリ 210 人（60 %）、Web サイト 105 人（30 %）、店頭 35 人（10 %）の 3 区分。全体が意味を持ち、最大が 2 位の 2.00 倍で突出している。この設問は S66 の 3 条件を満たすので、円グラフにしてよい。大きい順に 12 時の位置から時計回りに置き（S124）、3 区分なので値ラベルを付ける（S123）。棒 1 本でも同じ内容を伝えられる（本 skill の整理）

| 円の値ラベル | 4 区分以下で有効 | S123 |
| 円の並べ方 | 大きい順、12 時の位置から | S124 |
| 棒の軸 | 数値軸を切らない（0 起点） | S64、S126 |
| 凡例 | 置かない。名前と値を直接書く | S67 |
| 色 | 色だけで意味を伝えない | S60 |

本 skill の目安（出典なし）: 棒の横軸 0〜50 %（2 px = 1 %）、棒の高さ 14 px、行間 6 px。強調は電子マネーと代金引換の 2 行（年代で差が大きい項目）。円の半径 70 px、扇形の境界に白の線 2 px。図中の文字 13〜14 px。狭い画面では、円の図は幅 480 px を下限に縮め（14 px の文字が 12.0 px）、それより狭ければ横スクロールにする。年代別の表も横スクロールの包みに入れる（`overflow-x: auto`）。「最大が 2 位の 1.5 倍以上」を突出の目安にする。

| 扇形（アプリ）`#0a2a66` / 白 | 13.67 | 3:1 を満たす |
| 扇形（Web サイト）`#b84f00` / 白 | 5.05 | 3:1 を満たす |
| 扇形（店頭）`#767676` / 白 | 4.54 | 3:1 を満たす |

## 文言

| 場所 | before | after | 理由 |
|---|---|---|---|
| 見出し | 年代別の支払い方法 | 電子マネーは 20 代の 40 % に対し 60 代は 15 %。60 代は代金引換が 25 % | 図が言うことを書く（S68）。数値は下の検算と一致 |
| 列の見出し | 20 代 | 20 代（n=120） | 母数を示す。60 代は n = 80 で、1 人が 1.25 ポイントに当たる |
| 行・値 | 凡例の 4 色 | 行の名前と「40 %」の直接ラベル | S67 |
| 単位 | （なし） | 割合（％）。各列の横軸は 0〜50 %。単一回答 | 軸の起点・単位を書く |
| 出典行 | （なし） | 出典: 顧客調査（架空）。回答 350 人 | S14 |
| 補足 | （なし） | 年代の差が偶然でないかは、この図からは言えない | 統計的な検討は範囲外 |

検算（下のコードの出力と一致）: 20 代は 42、48、18、12 人で合計 120（35、40、15、10 %）。40 代は 60、45、30、15 人で合計 150（40、30、20、10 %）。60 代は 24、12、24、20 人で合計 80（30、15、30、25 %）。全体は 126、105、72、47 人で合計 350。購入経路の扇形は 216 度（60 %）、108 度（30 %）、36 度（10 %）で、合計 360 度。

## コード断片

外部のライブラリ・スクリプト・フォント・計測は使わない。割合の計算と、HTML・SVG の部品の出力（標準ライブラリのみ）。

```python
import math
from html import escape

cats = ["クレジットカード", "電子マネー", "銀行振込", "代金引換"]
groups = {"20代": [42, 48, 18, 12], "40代": [60, 45, 30, 15], "60代": [24, 12, 24, 20]}
hot = {"電子マネー", "代金引換"}

for g, counts in groups.items():
    assert abs(sum(c / sum(counts) * 100 for c in counts) - 100) < 1e-9, g
    print(g, sum(counts), [round(c / sum(counts) * 100, 1) for c in counts])
totals = [sum(c[i] for c in groups.values()) for i in range(4)]
print("全体", sum(totals), totals, [round(t / sum(totals) * 100, 1) for t in totals])

def cell(count, n, is_hot):
    pct = count / n * 100
    cls = "bar hot" if is_hot else "bar"
    return (f'<td><span class="{cls}" style="width:{pct * 2:g}px" aria-hidden="true"></span>'
            f'<span class="v">{pct:g} %</span></td>')

for i, cat in enumerate(cats):
    cells = "".join(cell(c[i], sum(c), cat in hot) for c in groups.values())
    tr = '<tr class="hot">' if cat in hot else "<tr>"
    print(f'{tr}<th scope="row">{escape(cat)}</th>{cells}</tr>')

pie = [("アプリ", 210), ("Web サイト", 105), ("店頭", 35)]   # 大きい順
cx, cy, r = 290, 110, 70
total, done = sum(v for _, v in pie), 0
for name, v in pie:
    a0, a1 = done * 360 / total, (done + v) * 360 / total   # 12 時から時計回りの角度
    pt = lambda a, rad=r: (cx + rad * math.sin(math.radians(a)), cy - rad * math.cos(math.radians(a)))
    (x0, y0), (x1, y1) = pt(a0), pt(a1)
    print(name, f"{a1 - a0:g} 度")
    print(f'<path d="M{cx},{cy} L{x0:.1f},{y0:.1f} A{r},{r} 0 {1 if a1 - a0 > 180 else 0} 1 {x1:.1f},{y1:.1f} Z"/>')
    done += v
```

## 初見検証

| 問い | 期待する答え | 確認する場所 |
|---|---|---|
| 何に注意するか | 年代で支払い方法が違う。電子マネーは若いほど多く、60 代は代金引換が多い | 見出しと、太字・濃い色の 2 行 |
| 何を読み取れるか | 電子マネーは 20 代 40 %、60 代 15 %。代金引換は 60 代 25 % | 棒の端の値 |
| どう読むか | 行が支払い方法、列が年代。各列の横軸は 0〜50 % で同じ。母数は列の見出しの n | 列の見出しと注記 |

5 人程度（本 skill の目安）に、図だけを見せて「60 代と 20 代でいちばん違う項目はどれか」を尋ねる。答えが 10 秒を超える、または項目を取り違える場合は、強調の 2 行と見出しの関係を見直す。

## 点検

- 円の条件: 円グラフを残したのは、3 条件（区分が 5 以下・意味のある全体・突出した区分）を満たす購入経路の設問だけ。年代別の 3 つは棒にした
- 棒: 軸は 0 起点（S64）。差が見えにくい設問が出たら、軸を切らずにドットプロットなどの別の図を検討する（S65）
- 色: 色を取り除いても、行名・値・太字で読める。比の計算は上のとおり。扇形の隣接色は 3:1 に届かない組があり、白の線と直接ラベルで補った（本 skill の判断。WCAG の隣接色の扱いは Understanding の本文を未照合。実機と印刷で確かめる）
- 標本: 60 代は n = 80 で、年代の差が偶然でないかは、この図からは言えない。統計的な検討は範囲外で、必要なら専門家に確認する。偶然のパターンを読む偏りにも注意する（S13）
- 推測の明示: 「3 つの円の同じ区分は見比べにくい」は本 skill の整理で、実験の結果ではない。円グラフを避ける理由を「角度が読めないから」と言わない（S43、S44）
