# デザイン史: 表から図へ、図から実験と実務ガイドへ

図表・統計図・ダッシュボードの慣習が、どんな制約から生まれ、何に直され、今の判断に何を示すかをまとめたファイル。年表の暗記用ではなく、「いま作っている図の慣習は、どんな制約から生まれたか」を確かめるための材料である。要点（見取り図・繰り返すパターン・媒体別の問い・俗説）と、時代別の詳細を 1 ファイルに置いた。中心の問いは次の 1 つ。

> その慣習を生んだ制約は、今回の媒体・読み手でも成り立つか。

成り立つなら、慣習は今も根拠を持つ。成り立たないなら、様式だけが残っている可能性がある。

このファイルを開くのは、相談者が背景を求めたとき、制作の着手前（「媒体別の使い方」の節）、レビューで「慣習の由来」の項目が不明のとき、の 3 つである。

| 知りたいこと | 開く場所 |
|---|---|
| 全体像・横断の型 | 「見取り図」「繰り返すパターン」 |
| 媒体ごとに確かめる問い | 「媒体別の使い方」 |
| ある慣習の由来（円グラフ・二軸・0 起点・虹色・sparkline など） | 「時代別の詳細」の 9 つの節 |
| 年が出典どうしで合わない項目 | 「年が食い違う・未確認の年」 |
| 俗説・未検証の主張 | 「確認できなかったもの」 |

## 読み方と記法

- 時点: 記述は 2026-11-15 時点（出典の取得日）。出典の詳細（引用原文・日付・URL・検証区分）は `sources.md` を参照する。
- 各時代の 4 項目: 当時の制約 / 応答 / 副作用と反動 / 今の判断への示唆。4 項目めの「示唆」はすべて「本 skill の整理（推測）」で、出典が述べた因果ではない。因果（「A だから B になった」）は、出典が述べている場合だけ S 番号つきで書く。「当時の制約」を出典が述べていない時代は、「整理（推測）」と書く。
- 区分は `sources.md` の凡例に従う（A 原典、B 第三者の転載・翻訳、C 論評、R 記者・歴史家・機関の地の文、U 未検証）。B・C・R は区分を明記して要旨にし、英語の逐語で本人の発言としては示さない。R を研究結果の根拠にするときは、原論文を取得していなければ「原論文未取得」と添える。書籍・未照合（N 番号）は事実の主張に使わない。
- 英語の逐語は区分 A の出典だけで、1〜2 文に限る。日本語は要旨で、本人の発言ではない。
- 年・日付: S 番号を添えた論旨上の年は、引用ブロックの原文に含まれるものに限る。単なる書誌の年（論文の発表年・投稿日）は「媒体・日付」の項による。
- 回答での使い方: 頼まれない限り、歴史を講釈しない。判断の根拠として 1 行で使う。

## 回答での使い方（例）

歴史は、判断の根拠として 1 行で添える。講釈にしない。

- 相談「円グラフは角度が読めないから避けるのだろう」: その説明は弱い。研究者本人は、円グラフは角度で読まれていないと結論しつつ、適否については何も述べないと限定する（S43、S44）。避ける理由は、区分が多い・似た大きさのときに比べにくいという実務の指針（S66）として述べる（本 skill の整理）。
- 相談「二軸は禁止と聞いた」: 禁止と言い切らない。Few は 2004 年の時点では有力な選択肢と考え（S39）、2008 年に立場を変えた（S38）。Datawrapper は 2018 年の批判（S75、S77）を 2026-07 に見直し、場合によっては最良と述べつつ、元の批判は有効とする（S76、S77）。読み手と目盛りの条件で決める（本 skill の整理）。
- 相談「棒グラフの 0 起点は絶対か」: 政府の指針などは棒の軸を切らないとし（S64、S126）、Schwabish は、棒の軸の規則は切り詰めないことだと言うのが正確だと述べ（S86）、Correll らは棒以外では助言が一様でないと述べる（S97）。論争中として、両論を示す。
- 相談「Tufte みたいにミニマルに」: Tufte 本人が、見た目の最小化とデータの最小化を区別している（S04）。削るのは飾りで、データではない。
- 相談「この装飾は要るか」: 歴史に頼る前に、読ませる図か、覚えてもらう図かを先に決める（S92。C。S95。本 skill の整理）。

## 繰り返すパターン（本 skill の整理）

次の型は、出典を横断して読み取ったもので、出典が述べた法則ではない。例外は多い。

1. 表で足りないとき、図が生まれ、図は説得の道具になった。Playfair は表を読んでも印象が残らないことを動機に書き（S110）、Minard は数値の比率を一目で感じ取れることを原則とした（B。S19）。図は主張のために作られるので、出典の明示（S14）が信頼を支える。軸・単位の明示も同じ目的で、本 skill の整理である。
2. 研究は別々の問いに答えていて、1 つの規則にならない。知覚の実験は値の比較に（S26、S27）、Tufte は証拠を考える課題に（S09）、Bateman と Borkin は記憶に（S92。C。S95）答える。1 つの結果を図全体の良さに広げない。
3. 規則は更新される。Few は二軸の評価を変え（S39、S38）、Datawrapper も変えた（S77）。古い立場だけを引かない。
4. 実務のガイドは、一般向けに保守的な既定を置き、読み方を学んだ読み手には例外を認める傾向がある。棒の 0 起点（S64）と二軸の見直し（S77）が例である。
5. 抽象化は何かを隠す。Nightingale の図は、大きさが面積か半径かで出典が食い違う（R。S115、S117）。Snow の地図には、後から訂正された誤りがある（R。S119）。軸の切り詰めは、切り詰めを示す手がかりがあっても影響が残る（S98）。
6. 色は値の見え方を変える。jet の置き換えを設計する動き（S50）、虹色型の欠点を直した設計（S52）、色覚の違いで読めない配色への批判（S48）が続いた。
7. 要約統計量は形を隠す。Anscombe の 4 組は、同じ要約統計量で異なる図を作る（S106）。
8. 画面では「一目で」が要件になり、同時に「説明には向かない」という警告も出る。Few は一画面・一目を定義し（S33）、英国政府の指針は、ダッシュボードは説明に向かず、利用者が自分で洞察を見つけることになると注意する（S72）。

## 媒体別の使い方

制作の着手前に、該当する媒体の問いを歴史から引き、その媒体の慣習の由来を確かめる。問いは判断を助ける材料で、結論ではない。

### 報告書の PDF・印刷物（`../examples/report-dual-axis-timeseries.md`、`../examples/survey-composition-pie-to-bar.md`）

1. この図は、表で渡すほうが向く読み手ではないか。Playfair が図を選んだのは、表では印象が残らないためだった（S110）。値を引かせたい読み手には、表のほうが向くことがある（Tufte が地図上の円グラフに対し、表を先に検討する姿勢。S12）。
2. 出典・加工（S14）と、軸・単位・期間が図に添えてあるか（軸・単位・期間は本 skill の整理）。
3. 白黒で印刷されても、色の意味が失われないか。色だけで意味を伝えない（S60）。
4. 円グラフは、区分が少なく、部分と全体が主題のときだけに絞ったか（S66、S36）。

### スライド・役員会の 1 枚（`../examples/report-dual-axis-timeseries.md`）

1. 見出しは、図が言うことを数文で書けたものか（S68）。
2. 離れた席から読める文字・太さか。図中の文字は水平にしたか（S71）。大きさの具体値は出典がなく、本 skill の目安として扱う。
3. 記憶に残すことが目的か、値を読み取らせることが目的か。前者では装飾が効いた研究があり（S92。C）、記憶性の研究もある（S95）。ただし、著者は全面的な推奨を避けている（S93。C）。

### Web・ダッシュボード・社内ポータル（`../examples/kpi-sparkline-table.md`、`../examples/forecast-uncertainty-band.md`）

1. 全体を先に見せ、絞り込み、詳細は求められたときに出すか（S23）。
2. 一画面で一目か。画面を割って全体を隠していないか（S33、S34）。
3. 画面は説明に向かない。説明が要る結論は、別の形式（報告書）に任せるか（S72）。
4. 平均や相関だけの数値を並べず、分布を見せる図が 1 枚あるか（S106）。
5. 画面体験（カードの数・更新の動き）は、この skill の範囲ではない。designer-apple が導入されていれば、その担当に回す。

### 地図（`../examples/regional-choropleth-rate.md`）

1. 色分けする値は、率か（コロプレスは相対値に向く。S80）。人数そのものの大きさは、記号や表に回す。
2. 色は「面積」の広がりを強調する（S81）。人口の多い小さな地域が埋もれる、という限界を注記するか（面積と人口のずれは本 skill の整理）。
3. 発散型の配色なら、中心の値を明示したか（S88）。

### 科学・研究の図

1. カラーマップは、データの性質（sequential・diverging・qualitative）で選んだか（S53）。
2. 明度の順序がデータの順序と一致するか（S49）。虹色型に頼る場合は、欠点（偽の細部・縞・色覚の曖昧さ）を直した設計か（S52）。
3. 不確実性の区間に、意味と確率を添えたか（S104、S105）。静的な誤差バーだけで推論させていないか（S102）。

## 時代別の詳細

### 1. 表から図へ: Playfair（18 世紀末〜1801 年）

- 当時の制約: 数値は表で伝えるものだった。Playfair（Atlas の序文。1787 年の標題の走査）は、表を丁寧に調べた人でも、読み終えたときには、読んだものについてごくかすかで部分的な印象しか持たない、という趣旨を書く（S110。原文は "a very faint and partial idea"。日本語は要旨で、本人の発言ではない。OCR の走査）。
- 応答: Playfair は、過去の出来事を目に向けて描く方法（原文は "painting to the eye"）として図を選んだ（S111。日本語は要旨）。歴史家は、円グラフ・時系列の折れ線・棒グラフという現代の形の多くを Playfair の発明とする（R。S112）。Tufte は、最初の円グラフは Statistical Breviary（1801）に出るとされる、と書く（S11）。
- 副作用と反動: 円グラフへの批判は、のちの Few（S35）まで続く。ただし、Few 自身は円グラフに、部分と全体の関係が構造に組み込まれている強みがあることを認める（S36）。Playfair 本人が円グラフをどう位置づけたかは取得していない（N19）。
- 示唆（整理・推測）: 図の発明の動機は、表では印象が残らないという、記憶と伝達の問題だった。いまの図表選びも、読む人が「覚えて帰る」のか「値を引く」のかで分かれる。後者には、表のほうが向くことがある（S12）。

### 2. 説得と調査のための図: Minard・Snow・Nightingale（19 世紀中ごろ）

- 当時の制約（整理・推測）: 統計は行政・軍・議会に向けた説得の材料で、数値の表は専門家以外に伝わりにくかった。Nightingale は、図は数字では把握しにくい考えを、目を通して伝えると書いたと、Science Museum Group Journal が 1858 年の文として引く（B。S114）。
- 応答（Minard）: Minard は 1862 年の著作で、図表と地図の支配的な原則を、数値の比率を一目で感じ取れるようにすることだと述べた（B。S19。Finley の英訳）。同じ文章で、図解があらゆるものに広がり、統計を図にしたのは時代の要請に応えるためだったと書く（B。S20）。1869 年の図の凡例は、帯の幅で兵の数を表し（1 mm で 1 万人）、赤が進軍・黒が退却と述べる（B。S22。Wikipedia 経由の英訳。図の署名は 1869-11-20）。
- 応答（Nightingale）: ローズ図は、月ごとのくさびの面積が死亡数に対応し（S115。R）、青が伝染病・赤が負傷・黒がその他と色分けされる（S116。R）。ただし、大きさを何で表すかの説明は、面積（R。S115）と半径（R。S117）で食い違う。原図で確認していない。
- 応答（Snow）: 1854 年のコレラの流行について Snow は 2 つの地図を示し、最初は 1854-12-04 の会で出した（S118。R）。世帯ごとの死亡を棒で表し、軽微な誤りが後に訂正された（S119。R）。
- 副作用と反動: Snow の地図が決め手だったという通説に異を唱える論文があるが、本文を取得しておらず、どちらの立場も断定しない（N21。「確認できなかったもの」を参照）。Minard の記述は、英訳と二次資料への依存が大きい。
- 示唆（整理・推測）: 古典的な図は「主張のために作られた」ものだった。図を作る人は読み手を動かす意図を持つので、出典の明示（S14）が説得の信頼を支える。軸・単位の明示も同じ目的である（本 skill の整理）。美しい古典を模倣するときも、その図が何を主張し、どの選択で何が見えなくなるかを書く。

### 3. 統計の中での図: Tukey と Anscombe（20 世紀中ごろ）

- 当時の制約（整理・推測）: 統計は数値の要約と検定が中心だった。Friendly と Wainer は、Tukey の考えを、データ分析の目的は数値だけでなく洞察だ、と要約する（R。S113。著者らの言葉で、Tukey 本人の逐語ではない）。
- 応答: Anscombe（1973）は、計算と図の両方を出し、両方を調べるべきだと述べたと、Autodesk Research のページが引く（B。S107。原論文は未照合）。Anscombe の 4 組は、各 11 組の (x, y) で、同じ要約統計量なのに大きく異なる図を作る（S106）。
- 副作用と反動: 後年、Cairo の Datasaurus と、Autodesk の「Same Stats, Different Graphs」が、同じ考えを再演した（S108。B。S109。R）。
- 示唆（整理・推測）: 平均や相関だけを KPI カードに並べる設計は、分布の形（外れ値・二峰・非線形）を隠す。探索の段階では、要約統計量と同時に分布を見せる図を 1 枚置く、という判断の根拠になる。

### 4. 理論化の時代: Bertin・Cleveland と McGill・Tufte（1960〜80 年代）

- 当時の制約（整理・推測）: 図の選び方が職人の勘にとどまっていた、という見方は出典を取っていない。
- 応答: Bertin の『Sémiologie graphique』は 1967 年にフランス語で出版された（R。S120）。出版社の紹介文は、形・向き・色・きめ・体積・大きさなどの図の技法を扱うと述べる（R。S121）。Heer と Bostock は、Bertin の視覚変数の体系に触発され、cartography・統計学・コンピュータ科学の研究者が、視覚変数の効果の知覚に基づく順位を導いた、と書く（S25）。Cleveland と McGill の実験は、2 つの印の値を比べ、小さいほうが大きいほうの何 % かを推定させる手続きだった（S26）。Heer と Bostock はその実験の位置・長さ・角度の判断を再現した（S27）。Tufte の VDQI は 1983 年春に刊行され（S128）、出版元の紹介文は、small multiples・data-ink ratio・図の欺瞞の検出を扱うと述べる（S15）。
- 副作用と反動: 順位は、値の比較という課題 1 つについての結果で、図の選び方の全体ではない。Tufte は、設計の原理を人間工学ではなく証拠を考える課題から導くと述べ（S09、S10）、知覚研究と距離を置く。のちに、実験による反論（Bateman。S92。C）が出た。
- 示唆（整理・推測）: 知覚の順位は、軸・位置で比べる課題の設計に使い、「印象に残す」課題には別の根拠（記憶性の研究。S95）を使う。順位の並びそのものは、論文の本文で確認していない（N04。「確認できなかったもの」を参照）。

### 5. 画面とビジネス: Shneiderman・Few・sparkline（1990〜2000 年代）

- 当時の制約（整理・推測）: 画面は小さく、BI 製品のダッシュボードは装飾的なゲージや円グラフが多かった。
- 応答: Shneiderman（1996）は、まず全体を見て、拡大・絞り込みをし、必要なら詳細を取り出す、という情報探索の型を示した（S23）。Few は、ダッシュボードを、最も重要な情報を 1 画面に集約し、一目で監視できるようにしたものと定義し（S33）、画面を分割して全体を見えなくする失敗を挙げた（S34）。メーターとゲージの代替として bullet graph を設計した（S40、S41）。Tufte は sparkline を、文字と同じ解像度の小さな図として、フォーラムで 2004 年に定義した（S01、S02）。本人は、sparkline に似た時系列が、基本原則（Above all else show the data）を述べた直後の最初の例だったと述べる（S128。書籍は未照合）。
- 副作用と反動: Few は 2007 年に円グラフを強く批判し（S35）、2008 年に二軸を避ける立場へ進んだ（S38）。ただし 2004 年の時点では二軸を有力な選択肢と考えていた（S39）。立場は固定でなく、更新されている。Tufte は、sparkline の見た目の最小化とデータの最小化を区別した（S04）。
- 示唆（整理・推測）: ダッシュボードは「一目で」が要件で、そのために情報を捨てるのでなく、優先順位をつける。英国政府の指針は、ダッシュボードは説明に向かず、利用者が自分で洞察を見つけることになる（S72）、理解の負担を利用者に回す（S127）と注意する。designer-apple（導入されていれば）が扱う画面体験の設計（カードの数・更新の動き）と、この領域の「何をどの図で示すか」は役割が違う。

### 6. 実験で確かめる時代（2009〜2020 年代）

- 当時の制約（整理・推測）: 設計の主張は、各人の経験と美学に頼っていた。
- 応答: Heer と Bostock（2010）は、知覚実験をクラウドソーシングで再現できると示した（S28）。Munzner（2009）は、上流の誤りが下流へ連鎖することを指摘し、課題とデータの特徴づけを最初の層に置いた（S29、S30）。Bateman ほか（2010）は、装飾つきのグラフで、解釈の正確さが劣らず、2〜3 週間後の再生が有意に良かったと報告した（C。S92）。Borkin ほか（2013）は、観察者が記憶に残る図について一貫していること、色や人が認識できるものが記憶性を高めることを報告した（S95、S96）。Kosara は、円グラフは角度で読まれていないと結論した（S43）。
- 副作用と反動: Bateman の著者は、全ての図をこの様式で作ることには慎重で、ミニマリズムの前提に疑問を投げる範囲にとどめ（C。S93）、安全上重要な場面では絞ることを認める（C。S94）。EU のガイドの要約は、原論文の要旨（S92）より強い言い方になっている（R。S85。ガイドの要約のみで、ガイドの記述を原論文の本文と照合していない。原論文の要旨・考察は S92〜S94）。Holmes は、Tufte は学術の世界に閉じ、商業の世界の、聴衆をつかむ必要に鈍感だと批判したと、EU のガイドが引く（B。S84）。Kosara は、円グラフの適否については研究が何も述べないと限定する（S44）。ドーナツは円グラフより悪くない（S45）。
- 示唆（整理・推測）: 「装飾は常に悪い」も「装飾は常に良い」も、実験の範囲を超える。記憶に残すことが目的の図（広報・教育）と、値を読み取らせる図（業務・分析）で、設計の方針を分ける。実験の対象は特定の図で、業務ダッシュボードへの一般化は未検証である。

### 7. 色と色覚（2002〜2020 年代）

- 当時の制約: matplotlib の既定のカラーマップは jet で、開発者は置き換えとして新しいカラーマップを設計した（S50。他のツールの既定は取得していない）。
- 応答: Okabe と Ito は 2002 年に、色覚の違いに配慮した配色の解説を公開し（S55 の媒体）、その配色では、黄と緑の間の色は、黄やオレンジと区別できないため避けた（S57）。凡例の色の照合をやめて直接ラベルを置くこと、色だけで情報を伝えず、色と形の両方（実線と点線、記号の違いなど）で差を示すことを勧めた（S56）。頻度は、コーカサス系の男性で 8 %、アジア系で 5 %、アフリカ系で 4 %と書く（S55）。NEI は男性の約 12 人に 1 人が色覚の違いを持つとする（S59）。W3C は、色だけで意味を伝えないこと（S60）と、図に必要な部分に隣接色との 3:1 のコントラストを求める（S61、S62）。Crameri ほか（2020）は、虹色と、明度の近い赤と緑のカラーマップが、データをゆがめ、読者の相当な割合に読めないと批判した（S46〜S48）。
- 副作用と反動: Google は 2019 年に、虹色型の Turbo を、jet の欠点（偽の細部・縞・色覚の曖昧さ）に対処した設計として公開した（S52）。虹色を一律に禁じる説は、この例で反論される。ただし jet の問題は、色の変化の速さが知覚的に一定でないことにある（S51）。
- 示唆（整理・推測）: 連続値の色は、明度の変化がデータの変化として読まれやすい（S49）ので、明度で読ませる。カテゴリは色だけに頼らず、直接ラベルを併用する（S56、S67）。ColorBrewer のように、データの性質（sequential・diverging・qualitative）で配色を選ぶ道具がある（S53）。発散型は中心の値を明示する（S88）。

### 8. 軸と実務ガイドの現在（2017〜2026 年）

- 当時の制約（整理・推測）: 公的機関・報道機関・ツールの作り手が、読み手の誤読を減らす規則を決める必要があった。
- 応答: 英国政府の Analysis Function は、棒グラフの数値軸を切らないこと（S64。理由は棒の長さの比例が崩れるため。S126）、0 から始めると話が見えないときは別の図（ドットプロットなど）を検討すること（S65）、円グラフを使う条件（S66）、凡例を避けて直接ラベルすること（S67）、装飾を避けること（S70）を指針に書く。ONS は 2019 年に二軸グラフの問題を説明した（S73）が、折れ線グラフでの軸の操作は妥当な場合があると留保する（S74）。Datawrapper は、棒・柱の最小値を 0 より大きく設定できない仕様の理由を説明し（S79）、2018 年の記事で二軸への批判を述べた（S75、S77）。その根拠として、Isenberg ほか（2011 年。15 人）が、二軸の重ね合わせた図の成績は正確さと時間の両面で悪かったと報告したことを引く（B。S129。論文本体は未取得）。
- 副作用と反動: Datawrapper は 2026-07 に、場合によっては二軸が最良だと見直し（S77）、同月に Business プランで二軸を提供した一方、元の批判は有効としている（S76）。同月の新しい指針は、二軸なら目盛りの伸び率をそろえ（S78）、片方の軸が 0 起点ならもう片方も 0 起点にするよう書く（S78）。0 起点についても、Schwabish は、棒は 0 から始めよと言うより、切り詰めるなと言うのが正確だと述べ（S86）、Correll らは、棒以外の図では助言が一様でないと述べる（S97）。切り詰めの影響は、切り詰めを示す手がかりがあっても残る（S98）。Correll らは、意味のある効果量の尺度を考えるよう提案する（S99）。
- 示唆（整理・推測）: 軸の規則は、読み手の誤読の実害と、見せたい差の大きさのつり合いで決まる。一般向けには保守的な規則（棒は 0 起点・二軸を避ける）を既定にし、読み方を学んだ専門の読み手には、注記つきで別の選択を許す、という二段構えが現実的である。

### 9. 不確実性の表現（2014 年〜）

- 当時の制約: 誤差バーなど静的な図は、確率分布を読み手が正確に解釈しにくい（S102）。
- 応答: Correll と Gleicher（2014）は、gradient plot と violin plot が推論課題に向くと提案した（S101）。Hullman ほか（2015）は、個々の抽出をアニメーションで見せる HOP を、数える・積分するという心的過程で分布を推論させる方法として示した（S103）。米国の NHC は、予報円が中心の進路の確からしさを表すこと（S104）と、円の大きさが過去 5 年の予報誤差の 3 分の 2 が入るように決まっていること（S105）を、公式に定義する。Tufte は、図が偶然のパターンを読ませる偏りを警告した（S13）。
- 副作用と反動: 予報円を影響の広がりと誤読する、という指摘は取得していない（未検証。本 skill の整理）。HOP は動く図で、印刷・報告書には向かない（整理・推測）。
- 示唆（整理・推測）: 区間を描くなら、その確率（NHC は 3 分の 2）と何の誤差から決めたかを、図の注記に書く（NHC の定義の書き方に倣う）。静的な誤差バーだけで読み手に推論させない。予測と実測を同じ図に重ねるときは、区間の意味と、どの期間の誤差から決めたかを添える。
