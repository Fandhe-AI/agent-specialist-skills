# 例: 特集ページの見せ場（特大の見出し 1 点と subgrid の構図）

読み物サイトの特集ページの冒頭を、特大の見出し 1 点と、記事 3 本の案内の並びで組む例。声を出すのは見出し 1 点だけにし、記事の案内は `subgrid` で行の高さを共有して、題の行数が違っても要旨と書き手の行をそろえる。`subgrid` に対応しない環境での姿も示す。題材は架空の文芸誌と記事で、実在のメディア・人物・作品は含まない。Web で見せ場を作るとき、文字の大きさと並びの設計に入る前に開く。

## 依頼

- 媒体: 架空の文芸誌「灯台通信」のウェブ版、第 7 号の特集ページの冒頭（最初の画面と、記事 3 本の案内）
- 依頼文（架空）: 「特集ページの最初の画面を見せ場にしたい。題は大きく見せたいが、読みにくくはしたくない。記事の案内は 3 本を並べたい」
- 想定する読み手: 寝る前にスマートフォンで開く人と、デスクトップで読む人。日本語の読み手で、文字サイズを変えている人もいる（想定）
- 範囲外: 記事本文の組み、写真・イラスト、動き・遷移（導入されていれば designer-interaction）、サイト全体の見た目の方向性（導入されていれば designer-web）

### 根拠の範囲（先に読む）

- 出典のある事実: 入れ子のグリッドは、親のトラックと独立しているので、入れ子の項目を親の線にそろえにくい。`subgrid` を指定すると、入れ子のグリッドが親のトラックを使う（S73）。行のトラックが内容で伸びる指定なら、親の内容と入れ子の内容の両方に合わせて伸びる（S73）。`@supports` は、機能への対応に依存する宣言を書く規則である（S74）。対応開始の版は MDN の機械可読データによる（D04。時点情報）
- 英語の原文（S73）: "These grids, however, are independent of the parent grid and of each other, meaning that they do not take their track sizing from the parent grid. This makes it difficult to line nested grid items up with the main grid." 日本語は要旨で、MDN の文ではない
- 和文の規則: 本文は 16 CSS px 以上（S27。1 組織の方針）。折り返しの調整（`auto-phrase`・`balance`）は使わず、割る位置はマークアップで決める（「削るもの」）。`lang` の指定は、ブラウザの和文の処理の前提（S15 は `auto-phrase` についてそう述べる）
- 本 skill の目安（出典なし）: 見出しの大きさの式と下限・色・寸法・3 列・字下げ 1 字・breakpoint
- 未検証: Safari・Firefox での見え。ほかの OS・書体での折り返し。文節 `span`（見出しと記事の題）による、スクリーンリーダーでの読み上げ・コピーの区切り（Chrome のアクセシビリティツリーの名前だけ確認した。「描画して確かめたこと」）。見出しの倍率を 200% で 1.5 倍にとどめることが S26（1.4.4）の解釈として足りるか（引用からは判断できない）。`subgrid` の現在の対応の割合（D04 は版のみ。2026-11-16 取得）

## 目的の一文

特集の題を最初の画面で 1 点だけ特大の文字で見せ、続く 3 本の記事の案内を、題の行数が違っても要旨と書き手の行がそろう並びで読ませる。

## 削るもの

| 削るもの | 理由 |
|---|---|
| 記事の題・見出しの全部を大きくすること | 声を出す場所は 1 点にし、ほかは静かにする（S70）。大きさの段階は 3 つに絞る |
| 画像・背景・動き | 目的は文字の構図。動きや画像は別の例・別の担当（本 skill の範囲外） |
| 見出しを画像に書き出すこと | 拡大・翻訳・検索に耐えない（S26）。実テキストで組む |
| 記事の案内の固定高・`min-height` | 利用者が拡大・上書きすると欠ける（S25）。行の高さは `subgrid` が内容に合わせて決める |
| 同じ角丸・同じ影の箱で区切ること | 区切りは上の罫線 1 本で足りる。箱にすると、題と要旨の差ではなく箱が主役になる（本 skill の整理。S69 は、同じ角丸・同じ影の束を既定値の例に挙げる） |
| 欧文の大文字ラベル・装飾の記号 | この特集の語には要らない。16 CSS px 未満の文字を作らない（S27） |
| 折り返しの調整（`auto-phrase`・`balance`・`line-break: strict`） | 目的は見出しと行の共有で、折り返しの調整ではない。`auto-phrase` は短い文（見出し・詩）向けの機能で（S15・S20）、対応が割れ（D01）、効く環境で題が「声に／出して読む」、リードが「短歌・／詩・掌編を」のように言い回しの途中で割れる描画があった（本 skill の確認）。割る位置は `span`（見出し・題）で決める |
| 高さをそろえるための JavaScript | `subgrid` で足りる。使えない環境では、そろわなくても読める姿にする |

## 構成

### 方向性のメモ（作る前に書いた文章）

- 目的: 寝る前に開く人に、この特集は「短い言葉を、静かに読む」ものだと最初の画面で伝え、3 本のうち 1 本を選ばせる
- 読み手と媒体: スマートフォン（幅 320〜412 CSS px）とデスクトップ。暗い部屋でも読める配色（ダークの設定に応える）。言語は和文のみ
- トーン（言葉）: 静けさ・夜・間（ま）。形容詞ではなく、題と要旨の言葉から出す
- 色: 文字と地は明暗の 2 組（ライト・ダーク）で、すべての文字を 4.5:1 以上にする（値は「仕様」のコントラスト比の表）。差し色は青緑 1 色を、「特集」の語と上の罫だけに使う
- 書体: 見出しと記事の題は明朝系の太い 700、本文はゴシック系。システム書体だけを使い、配信の許諾の問題を持ち込まない（他の OS での字面は未検証）
- サイズの段階: 3 つ。特大の見出し（1 点）、記事の題、本文と補助。補助の文字も 1 rem 以上にして、色で差を付ける。S34 は 1 ページ 2 サイズを原則とし、例外を認める（欧文の事務所の内規。[event-poster.md](event-poster.md) と同じく目安として借りる）。本例は、題と本文の 2 段に、見せ場の 1 点を足した形で、表現を認める側（S44。B。標語として扱い、Carson 本人の発言としては使わない）の選択である
- 構図: 土台は左端の 1 本の線と、記事 3 本の 3 列。見出しは左端から 2 行に組み、広い画面では 2 行目を 1 字分下げる（崩すのはここ 1 か所）。記事の案内は 3 本で、行の高さを共有する
- 参照の扱い: 特定の誌面・サイトを参照していない。参照があるなら、抜くのは技法（段の組み方・大きさの段階）と判断で、見た目は写さない

### 既定の案との比較（S70 の見直し）

同種の依頼で出がちな案との比較は、本 skill の推測である（出がちな案の調査はしていない）。

| 項目 | 出がちな案 | 本案 | 変えた理由 |
|---|---|---|---|
| 見出しの重さ | 見出しがどれも大きな太字で、どれが主役か分からない | 特大は特集の題の 1 点だけ。記事の題は 1.5 rem | 声を出す場所を 1 点にする（S70） |
| 地の色と差し色 | 温かい cream の地＋セリフ体＋テラコッタ（S69 の第 1 項） | ほぼ無彩色の明るい地＋明朝の見出し＋青緑の細い罫 | 夜に読む特集で、暖色の地を避け、差し色だけ寒色（青緑）にした。理由は題材から言える |
| 記事の案内 | 同じ角丸・同じ影のカードの束（S69 の第 4 項） | 上の罫線 1 本と、行の共有 | 題・要旨・書き手の差を、罫と余白で見せる |

S69 は、これらは一部の依頼では妥当で、既定値であって選択でないことが問題だと述べる。避ける定番も、一斉に使えば次の定型になりうる（本 skill の推測）。固定の禁止リストにはしない。

### 組み立て

```text
 広い画面（3 列）                                     狭い画面（1 列）
+--------------------------------------------+      +----------------+
| 灯台通信                          第 7 号  |      | 灯台通信 第7号 |
|============================================|      |================|
| 特集                                       |      | 特集           |
| 夜に読む、                                 |      | 夜に読む、     |
|    短い言葉        (2 行目は 1 字下げ)     |      | 短い言葉       |
| リード（30 em まで）                       |      | リード         |
| +---------+ +---------+ +---------+        |      |----------------|
| | 題      | | 題      | | 題      |  行 1  |      | 題             |
| |         | | 題(2行) | | 題(2行) |        |      | 要旨           |
| | 要旨    | | 要旨    | | 要旨    |  行 2  |      | 書き手         |
| | 書き手  | | 書き手  | | 書き手  |  行 3  |      | （2・3 本目も）|
| +---------+ +---------+ +---------+        |      +----------------+
+--------------------------------------------+
```

- 見出しは 2 つの句（「夜に読む、」「短い言葉」）を 1 行ずつにする。句はさらに文節（「夜に」「読む、」「短い」「言葉」）の `span`（`inline-block`）に分け、幅が足りない拡大時（320 px・200% など）だけ文節の間で折り返す。文節の途中では割らず、はみ出させない。名前や読み上げの区切りは「描画して確かめたこと」を参照
- 記事の題も、言い回しの単位（「眠れない夜に、」「声に出して読む」「詩集のはなし」。題 1 は「窓ぎわの短歌」）を `span`（`inline-block`）にして、単位の間で折り返す。単位はさらに文節（「眠れない」「夜に、」など）の `span` に分け、幅が足りない拡大時（200% など）だけ文節の間で折り返す。文節の途中では割らない。名前の区切りと下線は「描画して確かめたこと」を参照
- 記事 3 本は、行 1（題）・行 2（要旨）・行 3（書き手）の 3 つのトラックを共有する。行 2 は余りを受ける（`1fr`。本 skill の目安）

### 本 skill の目安（出典なし）

| 項目 | 値 | 理由 |
|---|---|---|
| 見出しの大きさ | `max(2.25rem, min(9rem, (100vw − 2 × 余白) / 6))` | 上限: 5 字に字間の上書き 0.12 em（S25 の試験値）を足した 5.6 em が内容幅に収まる（6 で割る）。下限: 320 px・200% の内容幅 256 px に、分けない最大の単位「読む、」（3 字）を字間の上書き込み（3.36 em）で入れる大きさは 76 px（2.38 rem）以下で、2.25 rem（72 px）にした。記事の題（1.5 rem）の 1.5 倍で、`rem` 基準なので文字を拡大しても見出しが記事の題より大きい。式の値は 320 px で 48 px、390 px で 59.7 px、約 939 px 以上で 144 px。下限が効くのは文字が大きく幅が狭いとき（200% では幅約 496 px 未満）。拡大しても見出しは大きくなるが、200% で 2 倍にはならない（320 px で 48 px から 72 px の 1.5 倍。1440 px でも 144 px から 220.8 px の約 1.5 倍）。2 倍にするより、文節を割らずに序列を保つことを優先した（本 skill の判断。採用の行は下の「試した案」）。S26 の引用は 200% まで内容・機能が失われないことだけで、見出しの倍率には触れていない。1.5 倍にとどめてよいかは引用からは判断できず、1.4.4 の解釈としては未照合 |
| 見出しの行送り | 1.15 | 特大の見出しは本文より詰める。本文の 1.75 を使うと、2 行が離れて 1 つの塊に見えない |
| 見出しの 2 行目 | 広い画面で 1 em 下げる | 崩すのは 1 か所。狭い画面では、内容幅を文字の大きさに回したいので下げない（本 skill の判断） |
| 記事の題 | 1.5 rem・行送り 1.4・700 | 見出し（1 点）との差。言い回しごとの `span` で折り返し、200% では文節の `span` の間で折り返す |
| 3 列にする幅 | 60 em 以上 | 3 列で 1 行が全角 17 字ほどになる幅。カード内の短い要旨（数行）なので、本文の行長の出発点（30〜40 字）とは別に扱う（本 skill の判断）。それ未満は 1 列 |
| 1 列のときの幅 | 記事の案内は 36 em まで | 本文の行長の出発点（30〜40 字。[japanese-longform-article.md](japanese-longform-article.md)）に合わせる |
| 色 | 地 `#f1f2ee`・文字 `#1b1f24`・補助 `#4a525c`・青緑 `#0f5c63`。ダーク: 地 `#101418`・文字 `#e8ebee`・補助 `#aeb6bf`・青緑 `#6fc3c9` | 夜に読む題材から、ほぼ無彩色の地と寒色の差し色にした（既定の案との比較を参照） |
| 行 2（要旨）の `1fr` | 3 本のうち最も高い要旨に合わせて行が伸びる | 行 1・3 は内容の高さ（`auto`）。余りを行 2 に回す |
| 余白・罫 | 左右 `clamp(1rem, 4vw, 4rem)`・罫 2 px（記事）・4 px（特集の上） | 実機で見て決める |

### 対応状況と、無いときの見え方

| 機能 | 使う場所 | 無いときの見え方 |
|---|---|---|
| `subgrid`（行） | 記事 3 本の行の共有 | 記事は縦並びの箱（`flex`）になり、書き手の行は下にそろうが、要旨の頭は題の行数に応じてずれる。読めなくはならない |

`subgrid` の宣言は `@supports` の中に置き、箱の並び（`flex`）を先に書いた。`@supports` の条件を偽にして描画し、非対応側の姿を確かめた（結果は「描画して確かめたこと」）。見出しの大きさは、先に `font-size: 2.25rem` を書き、`max()`・`min()` に対応しない環境ではそのまま 2.25 rem（記事の題の 1.5 倍）になる（対応状況は未照合）。

### 試した案（主に 320 px・200%、内容幅 256 px。Chrome 157 で測定。行ごとに条件を書いた）

| 案 | 見出し | 結果 |
|---|---|---|
| 下限 3 rem のまま（修正前） | 96 px | 5 行で「夜に／読／む、／短い／言葉」と割れた。390 px・200% でも「夜に読／む、／短い言／葉」 |
| 句のまま下限だけ下げる | 1.6 rem（51.2 px）／1.4 rem（44.8 px） | 5 字が収まるが、記事の題（48 px）との比は 1.07、1.4 rem では 0.93 で序列が逆転する。字間の上書きで 1.6 rem も割れた |
| `em` 単位のメディアクエリで式を変える | - | 採らない。メディアクエリの `em` は、ルートに当てた文字の 200% では変わらず（20em は 320 px のまま）、この測定法では確かめられない。式を変えても必要な大きさは同じで、句のままでは序列が保てない |
| `word-break: auto-phrase` | 96 px | 390 px・200% は文節で割れたが、320 px・200% は「夜に／読／む、」と割れた。非対応の環境では修正前と同じ。「削るもの」に挙げた理由もあり採らない |
| 文節の `span` と下限 2.5 rem | 80 px | 素の 320 px・200% は通ったが、字間の上書きで「読／む、」と割れた |
| 文節の `span` と下限 3 rem、外側に 3.36 で割る上限 | 76.2 px（320 px・200%） | 通ったが、320 px・300% で 66.7 px 対 72 px と記事の題を下回った（250% は 71.4 px 対 60 px）。下限だけの案は 300% でも逆転しない。採用案は、序列を優先し、200% を超えたときの割れは許容した（本 skill の判断） |
| 文節の境に `<wbr>`、h1 に `word-break: keep-all` と `overflow-wrap: anywhere`、下限 2.25 rem | 72 px | 折り返しは採用案と同じ（320・390 px の 200% と字間の上書きで文節の途中では割れず、はみ出しも 0）。`keep-all` を外すと 320 px・200% で「夜に読／む、／短い言／葉」と割れる（はみ出しは 0。割れる点は修正前と同じ）。ただし Chrome のアクセシビリティツリーで、名前が `<wbr>` で区切られて「夜に 読む、 短い 言葉」になり、文節の `span` と同じ。250%・300% では「夜に／読む／、」と、読点が行頭に来る割れ方になった。採らなかった |
| 文節の `span` を `inline` のまま `white-space: nowrap`、下限 2.25 rem | 72 px | 名前は修正前と同じ「夜に読む、 短い言葉」。320・390 px の 200% と字間の上書きは採用案と同じ折り返しではみ出しも 0（ライトのみ測定）。ただし 320 px で 250% に字間の上書きを当てると 22 px、300% では 52 px 横にはみ出した（250% の素は 0）。`nowrap` の代わりに `keep-all` と `overflow-wrap` を当てると、span の境でも折れなくなり、200% で「夜に読／む、」と割れた。`em` のメディアクエリは、この測定法では確かめられない。はみ出しを避けられず採らなかった |
| 文節の境に U+200B（ゼロ幅スペース） | 72 px | 名前は 1 つの文字列のまま残るが、U+200B が名前・選択・コピーに入る。検索・コピーを汚すため採らなかった（名前以外の影響は未確認） |
| 記事の題（h2）を言い回しの `span` のまま（修正前） | 24 px（200% で 48 px） | 100% は言い回しの間でだけ折れた。200% では、1440 px で「終電のあとで読／む、」、1024 px で「眠れない夜／に、」、960 px と 320 px で「窓ぎわの短／歌」「詩集のはな／し」と割れた（字間などの上書きで 1024 px も「窓ぎわの短／歌」）。言い回しの `inline-block` が段の幅より広いと、中が和文の通常の折り返し（字の間）に戻るため。名前は「眠れない夜に、 声に出して読む 詩集のはなし」と言い回しごと。題 2・題 3 には下線が描かれなかった（下の「描画して確かめたこと」） |

### 描画して確かめたこと

コード断片を md から取り出して描画した（環境は 1 つ。Chrome 157・macOS のシステム書体）。他のブラウザ・OS・端末での見えは未検証である。

- 条件: 記事の題（h2）と見出し（h1）を、100%・200%（320 px は 250%・300% も）と、幅 1440・1024・960・390・320 px、字間などの上書きの有無で測った。`subgrid` 非対応側・ダークも測った。見出しの条件は次のとおり。幅 1440・1024・960・390・320 px、320 x 256 px（1280 px の 400% 拡大に相当）。ライトとダーク。ルートの文字を 200%（既定の文字 32 px）にした 1440・390・320 px。字間 0.12 em・語間 0.16 倍・行間 1.5・段落間 2 倍（S25 の試験値）を上書きした 1440・320 px と、200% の 320・390 px。動きを入れていないので、動きを減らす設定は対象外
- 横はみ出し: `subgrid` 対応と非対応（`@supports` の条件を偽にした描画）の両方で、上のすべての条件（記事の題の修正の前後とも）で、全要素の右端が画面幅以内で、文書の横幅も画面幅と同じだった。`overflow: hidden` は使っていない
- 序列: 見出しは記事の題より常に大きい。320 px で 48 px 対 24 px、320 px・200% で 72 px 対 48 px（見出しの下限が記事の題の 1.5 倍）。見出しの大きさは、390 px で 59.7 px、約 939 px 以上で 144 px
- 記事の題のアクセシブルネーム: Chrome のアクセシビリティツリーで、見出しとリンクの名前が、修正前は言い回しごと（「眠れない夜に、 声に出して読む 詩集のはなし」。題 1 は「窓ぎわの短歌」）で、修正後は文節ごと（「眠れない 夜に、 声に 出して 読む 詩集の はなし」、「窓ぎわの 短歌」、「終電の あとで 読む、 三行の 物語」）に空白で区切られた。h1 と同じ代償で、実際の読み上げは未確認。`textContent` は修正の前後で変わらなかった。h1 の名前は変わらなかった
- 記事の題の下線: 修正前は、`span` で包んだ題 2・題 3 に下線が描かれなかった（`inline-block` の中へは下線が伝わらない。計算値は、リンクが underline、`span` が none）。下線があるのは `span` の無い題 1 だけだった。`.piece h2 span` に `text-decoration: inherit` を足した後は、3 本とも描かれた（1440 px・100% と 320 px・200% のスクリーンショット）。題 1 も `span` で包むので、この規則は欠かせない
- アクセシブルネームと選択（見出し）: Chrome のアクセシビリティツリーで、h1 と、これを参照する section の名前は「夜に 読む、 短い 言葉」と文節ごとに空白で区切られた（修正前は「夜に読む、 短い言葉」で、句の間だけ空白があった）。選択して取った文字列と `textContent` は文節 `span` の有無で変わらない（`innerText` は句の間で改行）。実際の読み上げは未確認。区切りは `<wbr>`・U+200B では解消せず、`inline` と `nowrap` では解消するが 200% を超えると横にはみ出すため、はみ出さないことを優先して残した（本 skill の判断。「試した案」を参照）
- 記事の題（h2）の折り返し: 修正前は、200% で言い回しの途中でも割れた（1440 px で「終電のあとで読／む、」、1024 px で「眠れない夜／に、」「声に出して読／む」、960 px で「窓ぎわの短／歌」「詩集のはな／し」「終電のあと／で読む、」、390 px で「眠れない夜／に、」「声に出して読／む」、320 px で「窓ぎわの短／歌」「詩集のはな／し」。字間などの上書きで 1024 px も「窓ぎわの短／歌」）。言い回しの `span` の中に文節の `span` を入れ子にした後は、100% の全幅と 200% の 1440・1024・960・390・320 px で、字間などの上書きの有無とも、文節の途中では割れなかった（例: 320 px・200% は「眠れない／夜に、／声に出して／読む／詩集の／はなし」。上書きを当てると「声に／出して」「三行の／物語」まで分かれる）。100% の折り返しは修正前と同じだった。200% を超える拡大（320 px・250%・300%）では、上書きの有無で「眠れな／い夜」「窓ぎ／わの」などと割れた。h1 と同じく、S26 は 200% までなので許容した（本 skill の判断）
- 見出しの折り返し: 100% の全幅と、200% の 1440 px では 2 行（句ごと）。200% の 390 px は 3 行（「夜に／読む、／短い言葉」）、320 px は 4 行（「夜に／読む、／短い／言葉」）で、文節の途中では割れない。字間などの上書きを当てた 320 px・200% も同じ。200% を超える拡大（320 px・250%・300%）では、見出しが 5 行で「夜に／読／む、」と割れた（S26 は 200% まで）。序列を優先し、200% を超えたときの割れは許容した（本 skill の判断）- 題の行数（非対応側で測定。390 px 以下では 1 列で縦に並ぶ）: 1440 px は 1・2・1 行、960〜1024 px は 1・3・2 行、390 px は 1・2・1 行、320 px は 1・3・2 行
- 行の共有（文書の上端から要旨の頭までの距離）: 対応する環境では、1440 px で 3 本とも 732 px、1024 px で 753 px、960 px で 750 px。非対応側では、1440 px で 699・732・699 px、1024 px で 686・753・720 px、960 px で 683・750・716 px とずれた。書き手の行は、どちらも 3 本そろった（788・837・834 px）
- 文字サイズ: 最小は 16 px（200% では 32 px）
- コントラスト比: 描画で解決された色から計算し、上の表（ライト・ダーク）と一致した

## 文言

| 場所 | 文言 | 理由 |
|---|---|---|
| 特集の題 | 夜に読む、短い言葉 | 2 つの句。読点で区切り、行の単位にする。拡大時は句の中の文節（夜に／読む、／短い／言葉）で折り返す |
| リード | 眠る前の十分間に読める、三つの文章。短歌・詩・掌編を、書き手の言葉とあわせて案内する。 | 1 文目で数と時間、2 文目で中身。文末は「案内する」の常体 |
| 記事の題 | 窓ぎわの短歌／眠れない夜に、声に出して読む詩集のはなし／終電のあとで読む、三行の物語 | 題によって 1〜3 行になる長さにして、行の共有の効果を見せる（960〜1024 px で 1・3・2 行、1440 px で 1・2・1 行）。100% で言い回しの途中で割れないよう、単位を `span` にし、200% では文節の `span` の間で折り返す |
| 書き手の行 | 柏木 澄（架空）・読了 5 分 | 名前と所要時間を 1 行で。実在の人物は含まない |
| 注記 | なし | 見せ場には注を置かない |

## 初見検証

初めて見る人に、説明なしで答えてもらう設計である（実験の結果ではない）。上の 3 つが本題で、最後の 1 つは補助。

| 問い | 期待する答え | 確認する場所 |
|---|---|---|
| 何に注意するか | 「夜に読む、短い言葉」という特集の題 | 特大の見出し（最初の画面） |
| 何を操作できるか | 3 本の記事の題（リンク） | 記事の案内の題 |
| どう操作するか | 題を押して記事へ進む。下線がリンクの手がかり | 題の下線 |
| どの要素に最初に目が行ったか | 特集の題か。記事の題が先に来たら、特大が足りないか、記事が強すぎる | 目安。実機の読み手で確かめる |

加えて、幅 320 CSS px で、見出しが句ごとの 2 行で、記事の題が 100% で言い回しの途中で割れていないかを見る。ルートの文字を 200% にした 320 px では、見出しが文節の間（「夜に／読む、／短い／言葉」の 4 行）で折り返し、記事の題も文節の間で折り返して、文節の途中で割れていないかも見る。記事の題 3 本とも下線があるかも見る。

## 点検

- 声を出す場所: 特大の文字は特集の題 1 点だけで、記事の題・リード・書き手は本文の段階（1 rem 以上）。大きさの段階は 3 つ
- 折り返し: 通常の幅で、見出しは「夜に読む、」「短い言葉」の 2 行で、記事の題は言い回しの単位の間で折り返す。200% で幅が足りないときは、見出しも記事の題も文節の間で折り返す（名前が文節ごとに区切られる代償は「描画して確かめたこと」）。記事の題の 3 本とも、リンクの下線が描かれる（`span` の中へ継承させる）。リード・要旨は和文の通常の折り返し（字の間）で、言葉の途中で割れうる。割れ方が気になる語は、文言を調整する
- 行の共有: 広い画面（60 em 以上）で、3 本の要旨の頭と書き手の行が同じ高さにある。題が 1 行でも 2 行でも、そろう
- 非対応側: `subgrid` を偽にした描画で、要旨の頭はずれるが、内容は欠けず、書き手の行は下にそろう
- 拡大・上書き: 320 px で、ルートの文字を 200% にしても、要素の右端が画面内に収まる（S26）。字間 0.12 em・語間 0.16 倍・行間 1.5・段落間 2 倍（S25 の試験値）を当てても同じ。固定高・固定幅の枠は置いていない
- 序列: 200% でも見出しが記事の題より大きく、序列が逆転していない（見出しの下限が `rem` 基準で記事の題の 1.5 倍）。拡大しても見出しは大きくなるが、2 倍にはならない（320 px で 1.5 倍。1.5 倍にとどめるのは本 skill の判断で、S26（1.4.4）の解釈としては未照合。仕様の見出しの大きさを参照）
- フォーカス: 2 行にわたるリンクの輪郭は、行ごとに分かれる（許容）
- コントラスト: すべての文字が 4.5:1 以上（ライト・ダークとも。S67）
- 失敗パターン: 欧文の助言の直輸入（左そろえ・イタリック・字間の既定化）をしていない。見出しを画像にしていない（S26）。試験値を既定値にしていない（S25）
- 推測の明示: 見出しの大きさの式・3 列の幅・色は出発点の目安で、この特集の読み手での実測ではない。他の OS・書体での折り返し、Safari・Firefox での見えは未検証。`subgrid` の対応は版の時点情報（D04）で、使う直前に再確認する
