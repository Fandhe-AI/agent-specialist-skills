# 例: 日本語の長文記事ページ

約 8,000 字のインタビュー記事を、スマートフォンでもデスクトップでも長く読める本文の組みにする例。本文のトークン（サイズ・行間・行長）、新しい CSS 機能を「あれば良くなる」扱いで入れる書き方、拡大・上書きに耐える作りを示す。題材は架空で、実在のメディア・人物は含まない。制作の着手前に開く。

## 依頼

- 媒体: 架空の書評メディア「路地の本棚」。記事は、架空の古書店主・柏木澄さんへのインタビュー（約 8,000 字）
- 依頼文: 「インタビュー記事の本文テンプレートを作って。スマホでもデスクトップでも長く読める組みにしたい」
- 想定する読み手: 通勤中にスマートフォン（幅 360〜412 CSS px）で、休日にデスクトップで読む。日本語の読み手で、ブラウザの文字サイズや行間を変えている人もいる
- 記事の中身: 小見出し、引用、ルビ（難読語）、注、欧文の語が少し

## 目的の一文

約 8,000 字のインタビューを、スマートフォンでもデスクトップでも、拡大や設定の上書きをされても、途中でつまずかず最後まで読み通せる組みにする。

## 削るもの

| 削るもの | 理由 |
|---|---|
| 見出し・引用を画像に書き出す | 拡大・翻訳・検索に耐えない（S26・S51） |
| 固定高・固定 px の枠に文字を詰める | 利用者が行間・字間を上書きすると内容が欠ける（S25・S51） |
| 本文の字間 0.12 em | 1.4.12 の値は上書きしても壊れないことの試験値で、既定値ではない。和文はベタ組が基本（S25・S01） |
| 強調のイタリック | 日本語フォントは通常イタリック体を持たず、傾けただけの斜体になり可読性に劣る（S28）。太さで強調する |
| 本文書体の多用 | 1 系統にする。書体を絞る立場（S35）と表現を認める立場があり、本文の和文書体の優劣を決める出典は無い |
| 両端そろえ（`text-align: justify`） | 書籍は行頭・行末をそろえるのが原則（S08）、Web の達成基準（AAA）は両端そろえしない設定を選べることを求める（S23）。立場が割れるため、本例は指定せず既定のままにする（本 skill の判断。理由を言える選択） |
| ぶら下げ（`hanging-punctuation`） | 対応は Safari だけ（D01）。使うなら余白が要る（S14）。効かない環境が多いので入れない |
| `text-wrap: pretty` | 改善の中身は UA 依存で、和文での効果は仕様に書かれていない（S16）。入れない |

## 構成

```text
+------------------------------------------+
| 路地の本棚                               |  サイト名（文字だけ）
+------------------------------------------+
|  棚をつくる、ということ                  |  h1: 記事題
|  古書店主・柏木澄さん（架空）に聞く      |  リード（2〜3 行）
|  取材・文 ○○（架空）  2026-11-15       |  書誌
|                                          |
|  最初の一冊を置く場所                    |  h2: 小見出し
|  　本文。段落の頭は 1 字下げ。……        |
|  ┃ 引用（左罫・淡い面）                  |  引用 + 出典の行
|  　本文。ルビ・注の番号が入る。……      |
|  注                                      |  本文末の注（番号つきの一覧）
+------------------------------------------+
```

- 本文は 1 カラムで、中央に置く。幅は字数（em）で決め、画面が広くても行を伸ばさない
- 階層はサイズ・太さ・空きで作る。サイズは本文・h2・h1 の 3 段、太さは 400・600・700 の 3 つ

## 仕様

出典のある値と、本 skill の目安（出典なし）を分ける。

出典のある数値・規則:

| 項目 | 値 | 根拠 |
|---|---|---|
| 言語の指定 | `html` に `lang="ja"` | `auto-phrase` は内容の言語が前提（S15） |
| 本文の文字サイズ | 16 CSS px 以上 | デジタル庁の方針（S27。1 組織の方針） |
| 行間 | 150% が最低限度、170%・175% が心理的負荷に配慮した行間 | S27。本例は 1.75 を選ぶ |
| 段落 | 頭を 1 字下げ、段落間は通常は行間と同じ（追加の空きなし） | 書籍の既定（S09）。欧文の「字下げか空きの一方」（S46）は持ち込まない |
| 行長の参照値 | 書籍は横組みで最大 40 字ほど（S02）、達成基準 AAA は CJK で 40 字以下（S23。利用者が選べる仕組みの要求）、電子リーダーの実験は 20〜29 字付近で速さが頭打ち（S66。R。原論文未取得） | 3 つは媒体・目的が別。1 つの最適値にしない |
| 拡大 | 200% まで内容・機能が失われない | S26（1.4.4） |
| 上書き | 行間 1.5・段落間 2・字間 0.12・語間 0.16 倍にされても失われない | S25。試験値で既定値ではない |
| ルビ | 既定は親文字の 50%。行間は途中で変えず、入る分を見込む | S27・S10 |
| 和欧間の自動の空き | CSS の既定は CJK 1 字幅の 1/8。書籍の空きの再現ではない | S13 |
| 色 | 文字は 4.5:1 以上で判定する | S67 |

本 skill の目安（出典なし）:

| 項目 | 値 | 理由 |
|---|---|---|
| 本文の大きさ | `--size: 1rem`（利用者の設定に従う） | S27 の下限ちょうど。px で固定しない |
| 行長 | `36em`（全角 36 字分）。スマートフォンは画面幅に従う | 書籍の上限（S02）と電子リーダーの実験（S66）の間の 30〜40 字を出発点にする（本 skill の目安） |
| 見出し | h1 は 2rem、h2 は 1.25rem、どちらも 700 | h1 は本文の 2 倍。Vignelli の内規（S34）は欧文の印刷向けで、目安として借りる |
| 強調 | 太さ 600（`em` のイタリックを打ち消す） | S28 の代替 |
| 余白 | 左右 1rem、h2 の前 2.5rem・後 0.75rem | 行間の整数倍にはそろえない。実機で見て決める |
| 注・引用の文字 | 本文と同じ 1rem。差は色と面で付ける | 16 CSS px 未満の文字を作らない（S27） |
| 注番号（`sup`） | 大きさは既定（`smaller`）のまま、`line-height: 0`・`vertical-align: baseline`。上げるのは `position: relative` の位置ずらし（`inset-block-start: -0.5em`） | 既定の `sup`（`vertical-align: super`）のままだと行ボックスが広がる（Chrome 156・Hiragino Sans で、注番号のある 1 行が 28 px から 30.33 px）。この指定では、注番号のある段落の高さが `行数 x 28 px` のままだった（幅 1280・500 px で確認） |

ルビは、注番号とは別に行を広げることがある。同じ実測で、段落がコンテナーの先頭にある（直前に何も無い）ときだけ、ルビのある 1 行の段落が 28 px でなく 30 px になった。直前に別の段落・見出し・`div` があると 28 px で、広がらなかった。記事の本文は小見出しや別の段落の後に続くので、ルビと注番号が同じ段落・同じ行にあっても、段落の高さは `行数 x 28 px`（56 px・84 px）のままだった（幅 1280・500 px）。コンテナーの先頭にルビつきの段落を置く場合は、2 px の増加を許容するか、`--leading` を上げる（2 にすると消えた。`rt` の `line-height`・`font-size` の指定では消えなかった）。他のブラウザー・書体では測っていない。

1 行の字数（`(画面幅 − 左右の余白 32) ÷ 16` を計算した値。最大 36）:

| 画面の幅（CSS px） | 360 | 390 | 412 | 768 以上 | 360 幅で 200% 拡大 |
|---|---|---|---|---|---|
| 全角の字数 | 約 20 | 約 22 | 約 23 | 36 | 約 9 |

可変幅では行長が字数の整数倍にならない（整数倍は印刷の規則。S03）。200% では 1 行が 9 字ほどになり読みにくいが、内容は失われない（S26 が求めるのは失われないこと）。

機能の対応と、無いときの見え方（D01。2026-11-15 時点。使う前に再確認する）:

| 機能 | 使う場所 | Chrome・Edge | Firefox | Safari | 無いとき |
|---|---|---|---|---|---|
| `line-break` | 本文（strict。狭い画面は normal） | 58 | 69 | 11 | 動く。禁則の厳しさは UA の既定になる（S17） |
| `word-break: auto-phrase` | h1・h2・リード | 119 | 未対応 | Technology Preview | 折れる位置は UA に任せる。文節の途中で折れうる（本 skill の整理。実機で確認）。`<wbr>` は、対応環境で区切りが意図と違うときの補正（S20） |
| `text-wrap: balance` | h1・h2・リード | 114 | 121 | 17.5 | 最終行が短くなるだけ。対象は 6 行以下（Chromium）・10 行以下（Firefox。S19） |
| `text-autospace` | 本文 | 140 | 145 | 18.4 | 和欧間が詰まる。手動の半角スペースで補わない（二重になる。S13・S20） |
| `text-spacing-trim` | 本文 | 123 | 未対応 | 未対応 | 連続する約物の空きが広いまま。読めなくはならない（本 skill の整理。実機で確認） |

`text-autospace` の値の細部（数字と漢字の間にも入るか）と `text-spacing-trim: normal` の挙動は、本 skill の出典の範囲を超える。実機で確認する。仕様は作業草案（S12・S13）で、変わりうる。

## 文言

| 場所 | before | after | 理由 |
|---|---|---|---|
| 題 | 【保存版】古書店のプロが語る！本棚づくりの極意とは？ | 棚をつくる、ということ | 符号は統一して濫用を避ける（S29。公用文向けの考え方で、民間の文書への義務ではない） |
| 題の折り返し | 指定なし（未対応の環境では「棚をつくる、とい／うこと」のように割れうる） | `棚をつくる、<wbr>ということ` | `<wbr>` は折れる点を足す補正で、`auto-phrase` の区切りが意図と違うときに使う（S20）。折れを防ぐ働きは無い。割りたくない語は `white-space: nowrap` の `span` で包む（本 skill の整理。実機で確認） |
| 欧文 | ＷＥＢ、ＱＡ（全角） | Web、QA（半角） | 横組みの和欧混植はプロポーショナルの欧字が基本で、全角の欧字は勧められない（S07） |
| 強調 | 古書は 棚で決まる（斜体） | 古書は **棚で決まる**（太さ 600） | 日本語のイタリックは傾けただけの斜体になる（S28） |
| 空き | 「Web 上」（手で半角スペース） | 「Web上」（空きは自動に任せる） | 自動と手動の二重を避ける（S13） |
| ルビ | 書肆（ルビなし） | 書肆（しょし） | 難読語に付ける。ルビが入る行の行間は先に見込む（S10） |

外部の CDN・スクリプト・フォント・計測は使わない。書体は端末にあるものを使い、ファイルは配信しない（配信と許諾は先に確認する）。`viewport` に拡大を止める指定を入れない。

## 初見検証

記事を初めて開く人に、説明なしで 3 つの問いに答えてもらう。

| 問い | 期待する答え | 確認する場所 |
|---|---|---|
| 何に注意するか | 誰の、何についての話か | h1 とリード |
| 何を操作できるか | 小見出しで位置が分かる。注の番号を押すと注へ飛び、「本文へ戻る」で戻れる | h2・注の番号と戻るリンク |
| どう操作するか | スクロールで読み進める。拡大しても読める | 実機（360 幅・200% 拡大） |

加えて、幅 360 CSS px の実機で 2 画面分を読んでもらい、行頭に閉じ括弧・句点が来ないか、注番号やルビのある行だけ行間が広がっていないか、和欧の間が詰まりすぎていないかを見る。

## 点検

- 拡大・上書き: 幅 360 CSS px で 200% に拡大して、横スクロールも内容の欠けも出ない（S26）。行間 1.5・段落間 2・字間 0.12・語間 0.16 倍を当てても欠けない（S25）
- 対応状況: 機能の対応は 2026-11-15 時点（D01）。使う直前に MDN・caniuse で再確認する。未対応の環境（Firefox の `auto-phrase`、Safari の `text-spacing-trim`）で見て、崩れないことを確かめる
- 約物と和欧: 手動の半角スペース・全角の欧字が残っていない。句読点・括弧・数字の表記が統一されている（S07・S29）
- 注番号の行: 注番号のある行の行送りが他の行と同じ（本例の指定で、1 行 28 px）。段落の高さを `行数 x 行送り` と比べて確かめる
- ルビの行: ルビがある行の行間が他と変わらない（S10）。本例の実測では、コンテナーの先頭の段落の 1 行目にルビがあるときだけ 2 px 広がる（仕様の残差）。気になるなら `line-height` を上げる
- 失敗パターン: 欧文の助言の直輸入（左そろえ・イタリック・字間の既定化）をしていない。40 字・80 字・20〜29 字（S66。R。原論文未取得）を同じ「最適値」にしていない（S02・S23）。固定 px・画像化した文字に頼っていない（S26・S51）
- 推測の明示: 36 字・行間 1.75・見出しの大きさは出発点の目安で、この記事の読み手での実測ではない。ルビの CSS・縦組みは本 skill の出典に無く、別に確認する。数値の最終判断は相談者が行う
