# 例: 設計レビューの技術スライド（30 枚・配布して読む資料）

投影で話す資料ではなく、配布 PDF として各自が読む技術スライドの文字組を決める例。1 枚の語数、コードの等幅、和欧混植、句読点の統一、暗室か配布かの選択を扱う。題材は架空のチームと架空の設計で、実在の製品・社名は含まない。開くのは、読ませる資料のスライドを組むとき。

## 依頼

- 場面: 架空の会社「ツバメ運送」の配車基盤チームが、再試行（リトライ）設計のレビュー資料を作る。レビュー会議の 3 日前に PDF で配り、各自が画面で読んでくる。会議中は同じ PDF を画面共有し、後日も参照される
- 依頼文: 「再試行設計のレビュー資料を 30 枚で作って。コードと表が多い。読みやすくしたい」
- 読み手: 他チームのエンジニア 12 人。日本語で読み、識別子・コード・HTTP の語は英語のまま。ノート PC かタブレットの画面で、自分の速さで読む。紙に印刷する人もいる
- 決めたいこと: 「再試行の上限を 3 回にしてよいか」の 1 点

### 根拠の範囲（先に読む）

- 出典のあるスライド向けの助言は 2 つだけで、どちらも批判・論評側の主張（区分 C）である。Tufte は、標準的なスライドは形式を内容の上に置くと批判する（S45。区分 C の要旨で、英語原文は本人の発言として引かない。取得した論評側の主張）。Butterick は、暗い部屋で上映するなら暗い部屋で読める配色にするよう助言する（S50）。どちらも欧文圏の主張で、日本語の配布資料の実験ではない
- S45 の「40 語・8 秒」の見積もりは根拠が示されないため、本例は目安にも使わない
- 文字サイズ・語数・コードの桁数は、すべて本 skill の目安（出典なし）。実際の画面と読み手で確かめる
- 発表用のスライドの作り（1 枚 1 メッセージ）は、導入されていれば designer-apple の examples にある。本例は文字組の判断だけを扱う

## 目的の一文

読み手が、会議の前に自分の速さで 30 枚を読み、「再試行の上限を 3 回にしてよいか」に賛否を言える状態にする。

## 削るもの

| 入れない要素 | 理由 | 削り方 |
|---|---|---|
| 1 枚に収まらないコード全文（例: 28 行） | 1 枚の高さの予算（下の「高さの予算」）を超え、PDF で 1 枚が 2 ページに割れる。注目する行も分からない | 9 行以内の抜粋にし、全文は付録（29・30 枚目）へ 14 行ずつ移す |
| 話す内容をそのまま書いた長文 | 配布物は話者の補足が無い。長文は階層を壊す | 本文は 3 文以内かつ 2 行（72 字）以内。見出しに結論の 1 文を置く |
| 書体 3 系統以上 | 階層はサイズ・太さ・空きで足りる。Vignelli は書体を絞る側（S35） | 和文・欧文は 1 系統、等幅 1 系統 |
| 日本語のイタリック・下線 | 日本語フォントは通常イタリック体を持たず、傾けただけの斜体になる（S28）。下線はリンクと混同する | 強調は太さと色（アクセント 1 色）。色だけにせず太さを併用する |
| コードの 8 色のハイライト | 色の意味を覚えさせる負担と、白黒印刷で区別が消える問題 | キーワードとコメントの 2 色。注目行は背景帯と太さ |
| 見出しの画像化 | 拡大・検索・コピーに耐えない（S26・S51） | 実テキスト |
| 全枚のロゴ・飾り罫 | 階層に寄与しない | 資料名と通し番号だけを右下に置く |

## 構成

30 枚を 1 枚 1 主張で組む。各枚は「見出し（結論の 1 文）＋本文 3 文以内＋図・コード・表のどれか 1 つ」で、高さの予算（仕様）に収める。収まらない内容は縮小せず、別の枚に分ける。

```text
 1       表紙
 2       目的と決めたいこと（「再試行の上限を 3 回にしてよいか」）
 3〜6    背景（障害時に依頼が増える現状。4 枚）
 7〜14   案 A（固定間隔）と案 B（指数的に延ばす）の比較（8 枚）
15〜22   案 B の詳細（コード・パラメータ表・流れ図。8 枚）
23〜27   リスクと未解決の点（5 枚）
28       決めたいことの再掲
29〜30   付録（全文コード 28 行を 14 行ずつ。用語は初出の本文で 1 文だけ説明する）
```

```text
+--------------------------------------------------------------+
| 4xxを除いて最大3回、間隔を倍々に延ばす                       |  見出し 48 px・太さ 700（コードのある枚は 1 行 22 字まで）
|                                                              |
| 一時的な失敗は、待てば成功する。永続的な…（3 文まで）       |  本文 24 px・36 字幅（864 px）・2 行まで
|                                                              |
| +--------------------------------------------------+         |
| | async function sendWithRetry(job: Job) ...       |         |  コード 20 px・64 桁・9 行以内
| +--------------------------------------------------+         |
| 数値は架空。試行で測る                    再試行設計レビュー 12 |  注記 20 px・資料名と通し番号
+--------------------------------------------------------------+
```

## 仕様

寸法は、画面で等倍（1280 px 幅）に表示したときの CSS px。基準の 16 px を 1rem とする。

| 項目 | 値 | 根拠 |

| 背景 | 明るい背景（配布・印刷向け）。暗室で上映する版は別に作る | S50（C）の考え方。選択は本 skill の整理 |
| 文字サイズ | 見出し 48 px・本文 24 px・コードと注記 20 px | 本 skill の目安（出典なし） |
| サイズの段階 | 3 段。見出しは本文の 2 倍 | Vignelli の内規は印刷の欧文で、1 ページ 2 サイズ・見出しは約 2 倍（S34）。本例は 2 倍だけ借り、コード・注記を 3 段目とする（本 skill の整理） |
| 下限の確認 | 等倍の最小 20 px は、Web 本文 16 px 以上（デジタル庁の方針。S27）を超える。縮小して読まれると下回る | S27 は 1 組織の方針。縮小は実機で確認 |
| 行長（本文） | 36 字（36em = 864 px） | 出発点は 30〜40 字（本 skill の目安）。書籍の上限 40 字（S02）と電子リーダーの 20〜29 字（S66。R。原論文未取得）の間。WCAG は CJK 40 字を AAA で述べる（S23）。字数の整数倍にそろえる（S03） |
| 行間 | 本文 1.7・見出し 1.35・コード 1.6 | 本文は S27（150% が最低限度・170% が配慮した行間）を出発点にした目安。他は目安 |
| そろえ | 左そろえ（`text-align: start`）。字下げなし | 書籍は両端そろえが原則（S08）。WCAG は両端そろえしない設定を AAA で求める（S23）。36 字幅なら行末のばらつきは小さいと推測する。選択の理由は本 skill の整理 |
| 和欧間 | ソースに手動スペースを入れず、`text-autospace` に任せる | 既定は CJK 1 字幅の 1/8（S13）。明示の空白があれば挿入されない（S20）ため、二重にしない |
| 欧字 | 半角のプロポーショナル。全角の欧字は使わない | S07 |
| 句読点 | 句点「。」・読点「、」。見出しは句点なし。本文の文は句点あり。箇条書きは体言止めで句点なし（文で書くなら全項目に句点） | 文書内で統一する（S29。公用文向けの規範）。どれを選ぶかは本 skill の選択 |
| 書体 | 和文・欧文 1 系統（Noto Sans JP 優先）・等幅 1 系統（Noto Sans Mono 優先） | S27 が採用する書体。許諾と PDF への埋め込みは先に確認する |
| 語数の上限 | 本文 3 文かつ 2 行（72 字）以内・コード 9 行（64 桁以内）・表 5 行 x 3 列。見出しと本文が増えるとコードは 6〜8 行まで減る（下の「高さの予算」） | 本 skill の目安（出典なし） |
| コード | 等幅・リガチャなし・折り返さない・縮小しない・インデント 2。枠より広いときは `pre` を横にスクロールして読む（`overflow-x: auto`。キーボードで操作できるよう `tabindex="0"` を付ける） | 本 skill の目安。64 桁は等幅の 1 桁を 0.6em（20 px なら 12 px）とみると 768 px で、本文の行長 864 px に収まる。書体で変わる。1280 px 幅の PDF は `pre` の内側が 1088 − 52 = 1036 px なので切れない。狭い画面は横スクロールに任せる |
| 日本語コメント | 行末に置き、桁そろえに使わない | 等幅書体の和文が 2 桁分とは限らない（推測）。実機で確認 |
| 数値と単位 | 数値と単位の間は改行しない空き（`&nbsp;`） | 本 skill の目安 |

### 高さの予算（PDF で 1 枚を 1 ページに収める）

1280 px 幅の PDF では、1 枚の高さは 720 px で、上下の余白が 64 px ずつなので、内容に使えるのは 720 − 128 = 592 px。文字は 16 px 基準の rem（見出し 48 px・本文 24 px・コードと注記 20 px）。部品ごとの高さ（計算値。実測は点検で行う）:

| 部品 | 高さの式 | 値（px） |
|---|---|---|
| 見出し 1 行 | 48 x 1.35 = 64.8、下の空き 32 | 96.8 |
| 見出し 2 行 | 64.8 x 2 + 32 | 161.6 |
| 本文 2 行 | 24 x 1.7 = 40.8 を 2 行 | 81.6 |
| 本文 3 行 | 40.8 x 3 | 122.4 |
| 本文とコードの間 | 本文の下 16 とコードの上 24 は重なり、大きい方 | 24 |
| コード n 行 | 20 x 1.6 = 32 を n 行 + 上下の内余白 16 x 2 | 32n + 32 |
| 注記 1 行 | 上の空き 16 + 20 x 1.7 = 34 | 50 |

コードのある枚の組み合わせ（注記あり）と、収まるコードの最大行数:

| 見出し | 本文 | 見出し + 本文 + 間 + 注記（px） | コード最大 | 検算（合計 ≤ 592） |
|---|---|---|---|---|
| 1 行 | 2 行 | 96.8 + 81.6 + 24 + 50 = 252.4 | 9 行 | 252.4 + 320 = 572.4 |
| 1 行 | 3 行 | 96.8 + 122.4 + 24 + 50 = 293.2 | 8 行 | 293.2 + 288 = 581.2 |
| 2 行 | 2 行 | 161.6 + 81.6 + 24 + 50 = 317.2 | 7 行 | 317.2 + 256 = 573.2 |
| 2 行 | 3 行 | 161.6 + 122.4 + 24 + 50 = 358 | 6 行 | 358 + 224 = 582 |

1 行増やすと、いずれも 592 を超える（例: 1 行・2 行で 10 行は 252.4 + 352 = 604.4）。12 枚目は見出し 1 行・本文 2 行・コード 9 行で、572.4 px、残りは 19.6 px。

- 超える内容は、フォントを縮めず、コードの抜粋を減らすか、別の枚に分ける。高さを固定して切り落とさない
- 付録の枚は、見出しとコードだけにする（本文と注記なし）。使える高さは 592 − 96.8 = 495.2 px で、コードは 14 行（32 x 14 + 32 = 480 px。合計 576.8 px）まで。全文 28 行は 14 行ずつ 2 枚（29・30 枚目）
- コードの代わりに表・図を置く枚は、上の「コード n 行」の分（標準形で 339.6 px）に収める。表の CSS はこの例に無いので、行の高さは実測する
- 余裕は 20 px 前後しかない。コメントの和文がフォールバック書体になると、行の高さが 32 px を超えることがある。算術で収まっても、書き出した PDF のページ数で確かめる

コントラスト比（WCAG の相対輝度式で計算。文字の基準は 4.5:1。S67）:

| 組み合わせ（前景 / 背景） | 明るい背景（配布） | 暗い背景（暗室上映の別版） |
|---|---|---|
| 本文 / 背景 | 16.56 | 14.76 |
| 注記・補助文字 / 背景 | 7.79 | 8.79 |
| アクセント（強調語） / 背景 | 6.67 | 8.98 |
| コード本文 / コード背景 | 14.90 | 12.81 |
| キーワード / コード背景 | 7.59 | 8.24 |
| コメント / コード背景 | 5.66 | 6.94 |
| 注目行の文字 / 注目行の背景 | 14.61 | 9.66 |
| コードの左罫 / 背景（非文字。参考） | 4.74 | 5.86 |

非文字の基準（3:1）は、本台帳に原文が無く未照合。左罫は参考値として載せる。

## 文言

| 枚 | before | after | 理由 |
|---|---|---|---|
| 3 | 背景 | 障害時に、再試行が重なって依頼が約3倍に増える（架空の数値） | 見出しは結論の文にする。拾い読みで話が通じる |
| 12 | 実装イメージ | 4xxを除いて最大3回、間隔を倍々に延ばす | 話題名ではなく、決めた内容を言う |
| 15 | パラメータ一覧 | 待ち時間は1回目200 ms、2回目400 ms、3回目800 ms | 数値と単位を一組で読ませる。単位の前は改行しない空き |
| 24 | ・再試行を制限する， | ・再試行の回数を制限 | 読点・句点の混在をやめ、箇条書きは体言止めで句点なしにそろえる |
| 28 | まとめ | 決めたいこと: 再試行の上限を3回にしてよいか | 最終枚は、読み手が次にすることを言う |

和欧間の手動スペースは、ソースに入れない（「4xxを除いて」「3回」）。PDF を書き出す環境の `text-autospace` の対応を、書き出し前に確認する（Chrome・Edge 140、Firefox 145、Safari 18.4。D01、2026-11-15 時点）。

## コード断片

HTML/CSS で組む 12 枚目。外部のスクリプト・フォント・計測は使わない。`text-autospace`・`text-wrap: balance`・`word-break: auto-phrase` は、対応しなくても崩れない「あれば良くなる」扱い（S13・S15・S16・D01）。文字は rem で指定し、枠の幅に比例させない。拡大・上書きで文字が縮まないようにするため（S25・S26）。

```html

    <h2 id="s12">4xxを除いて最大3回、間隔を倍々に延ばす</h2>
    <p>一時的な失敗は、待てば成功する。永続的な失敗は、待っても成功しない。後者は再試行せず、すぐ呼び出し元へ返す。</p>
<pre tabindex="0"><code><span class="k">async function</span> sendWithRetry(job: Job): Promise&lt;Result&gt; {
  <span class="k">for</span> (let attempt = 1; attempt &lt;= MAX_ATTEMPTS; attempt++) {
    const res = await send(job);
    if (res.ok) return res;
<mark>    if (!isRetryable(res)) break;   <span class="c">// 4xxは再試行しない</span></mark>
    await sleep(backoff(attempt));
  }
  return fail(job);
}</code></pre>
    <p class="note">数値は架空。試行で測る</p>
  </section>
</div>
```

## 初見検証

初めて PDF を開く読み手 3 人に、説明なしで確かめる（人数は本 skill の整理）。

| 問い | 期待する答え | 確認する場所 |
|---|---|---|
| 何に注意するか | 見出しだけを順に読んで、案 A・案 B の違いと決めたいことが分かる | 見出しの拾い読み |
| 何を操作できるか | コードを選択してコピーでき、行番号や色の指定が混ざらない。識別子（`sendWithRetry`）で検索できる | PDF ビューアでのコピー・検索 |
| どう読み進めるか | 注目行（背景帯と太字）がどれか、本文を読む前に指せる | 12 枚目のコード |
| 数値を読めるか | 「200 ms」を 1 つの塊として読める。単位の前で改行されない | 15 枚目の表 |
| 白黒で読めるか | 白黒印刷で、注目行とコメントが区別できる | 印刷物 |

見出しだけで話が通じなければ、本文を足さず、見出しと枚の分け方を直す。

## 点検

- 行長: 本文が 36 字幅（864 px）に収まり、整数倍になっている（S03）。コードの最長行が 64 桁以内（本例の最長は 61 桁）。実機で、等幅書体の桁幅を確かめる
- 狭い画面: 幅 360 px 前後で、コードの背景帯が枠の外へはみ出さず、`pre` を横にスクロールして最後まで読める。ページ全体は横にスクロールしない。コードは縮小されていない
- 拡大: 200% に拡大しても、文字が切れず枠が伸びる（S26）。ブラウザの文字サイズの上書きでも崩れない（S25）。`aspect-ratio` の伸びる挙動は実機で確認する
- 印刷・PDF: 書き出した PDF のページ数が枚数（30）と一致し、1 枚が 2 ページに割れていない。各枚が高さの予算（592 px）に収まり、コードの行数が予算の表の最大以内。付録の枚は 14 行以内。PDF で選択・検索でき、`text-autospace` が効いた環境で書き出した（版を記録する）
- 約物・和欧: 句点・読点が「。」「、」だけ。ソースに和欧間の手動スペースが無い（二重にならない。S13・S20）。日本語にイタリックが無い（S28）
- 色: 表の組み合わせを再計算し、いずれも 4.5:1 以上（非文字は参考）。色だけで意味を分けていない
- 失敗パターン: 1 枚に詰めていないか。形式が内容の上に立っていないか（S45。C）。試験値（字間 0.12em など）で本文を組んでいないか
- 範囲外: フォントの使用許諾と PDF への埋め込み、社内資料の分類の判断は、本 skill ではしない。法務・管理部門に確認する
