# デザイン史（要点）: 紙・GUI・Web・Apple の変遷

制作とレビューの判断に歴史を使うための参照のうち、すぐ使う要点だけをまとめたファイル。年表の暗記用ではなく、「いま作っているものの慣習は、どんな制約から生まれたか」を確かめるための材料である。時代ごとの詳しい節は `design-history-eras.md` にある。中心の問いは次の 1 つ。

> その慣習を生んだ制約は、今回の媒体・利用者でも成り立つか。

成り立つなら、慣習は今も根拠を持つ。成り立たないなら、様式だけが残っている可能性がある。この問いに答える材料として、紙・グラフィック、GUI・デジタル、Web、Apple の 4 つの系譜を、時代ごとに同じ 4 項目で書いてある。

このファイルを開くのは、相談者が背景を求めたとき、制作の着手前（「媒体別の使い方」の節）、レビューで「慣習の由来」の項目が不明のとき、の 3 つである。

| 知りたいこと | 開く場所 |
|---|---|
| ある慣習の由来（紙・GUI・Web） | `design-history-eras.md` の「紙・グラフィック」「GUI・デジタル」「Web」 |
| Apple が刷新した理由 | `design-history-eras.md` の「Apple の転換点」「転換点の早見表」 |
| 出典どうしで年が合わない項目 | `design-history-eras.md` の「年が食い違う出典」 |
| 全体像・横断の型・媒体別の問い・俗説 | このファイルの「見取り図」「繰り返すパターン」「媒体別の使い方」「確認できなかったもの」 |

## 読み方と記法

- 時点: 本ファイルの記述は 2026-11-15 時点（出典の取得日）。出典の詳細（引用原文・日付・URL・検証区分）は `sources.md` を参照する。
- 各時代の 4 項目: 当時の制約 / 応答 / 副作用と反動 / 今の判断への示唆。4 項目めの「示唆」はすべて「本 skill の整理」で、出典が述べた因果ではない。因果（「A だから B になった」）は、出典が述べている場合だけ S 番号付きで書く。
- Apple の転換点は 3 層に分ける。(a) Apple 自身が述べた理由。当時の Apple の文書・発表と、在籍中の役員の公の発言で、区分 A の英語原文の逐語引用を原則とする。区分 B を使う場合は区分を明記する。(b) 記者・批評家の説明。出典の区分自体は A でもよい（記者・批評家の主張だと分かるように書き、本人の発言として書かない）。(c) 本 skill の整理（推測）。(a) が取得できていない転換点は、推測で埋めず「取得していない」と書く。
- 人事・社内事情（退任と方針転換の因果、特定個人の好みなど）は断定しない。報道で語られても、Apple が理由を述べていなければ、そう書く。
- 区分は `sources.md` の凡例に従う（A 原典、B 第三者の転載・書き起こし、C 論評、R 記者・機関の地の文、U 未検証）。B・C・R は区分を明記して使い、U は事実として使わず末尾の一覧にだけ置く。
- 英語の逐語引用は区分 A の出典だけで、1〜2 文に限る。英訳（Gropius など）は「英訳」と明記する。日本語は要旨で、本人の発言ではない。例外として、末尾の区分 U の一覧には、流通する未検証の文を警告として示すため、英語の形を載せる（事実としては使わない）。
- 年が出典どうしで食い違うものは、両側の出典を挙げて注記する（8 件。Alto の稼働開始、フラット化の起点、Bill の論文の掲載号、NYC 路線図の導入、Univers のバリエーション数、iOS 7 の 3 テーマの文面、Tschichold のバーゼル移住、『Grid Systems』の版年。一覧は `design-history-eras.md` の「年が食い違う出典」）。
- Rams の 10 原則の本文は CC BY-NC-ND のため、転載も翻訳もしない（`SKILL.md` の「Dieter Rams との関係」を参照）。Ive の退社後の発言は、Apple 在籍期の理由に使わない。
- 回答での使い方: 頼まれない限り、歴史を講釈しない。判断の根拠として 1 行で使う。

## 回答での使い方（例）

歴史は、判断の根拠として 1 行で添える。講釈にしない。次の組み立てを使う。

- 相談「見出しを画像で書き出したい」: 実テキストで組む（本 skill の整理）。文字を画像に閉じ込めたのは Web フォントが無かった時代の回避策で（S141）、今は検索・翻訳・拡大に耐えるほうを選べる（本 skill の整理）。
- 相談「枠も影もなくして、ミニマルにしたい」: 手がかりの弱い UI は、見る時間と注視の回数が増えた実験がある（デスクトップの Web。S126）。枠でなく色や下線でもよいので、押せる手がかりは残す（本 skill の整理）。
- 相談「革や木の質感を足したい」: 比喩は、利用者が慣れるまでの補助輪として働き、慣れた人には装飾になった例がある（S127、S175）。この利用者は、その操作にどれだけ慣れているかを先に聞く（本 skill の整理）。
- 相談「Apple はなぜ iOS 7 でフラットにしたのか」: Apple が述べた理由は、内容を主役にすること、タッチへの慣れ、表示性能の向上である（S174、S175）。人事との因果は Apple が述べておらず、報道の範囲にとどめる（S169）。
- 相談「この区切り線は要るか」: 歴史に頼る前に、要素ごとに無いと誰が困るかを言わせる（本 skill の整理）。歴史は、その慣習を生んだ制約が今回も成り立つかを確かめる補助にとどめる（本 skill の整理）。

## 繰り返すパターン（本 skill の整理）

次の型は、4 つの系譜を横断して読み取ったもので、Apple や出典が述べた法則ではない。例外は多い。

1. 新しい媒体ではメタファーで橋を架け、習熟したら外す。Star は事務所との類推で覚えやすくし（B。S107）、1987 年の HIG は直接の経験を持つ身の回りの世界の比喩を使うとした（S156）。Microsoft のチームは、最初の UI は新しかったから物の描写が適切で、今は要らないと書いた（S115）。Apple は 2013 年に、人はガラスに触れることに慣れたと述べた（S175）。新しい入力が来ると足場は戻る。visionOS は慣れたものとの釣り合いを求めた（S183）。
2. 装飾を削ると、押せる場所の手がかりが消え、反動が来る。NN/g の 2017 年の実験では、signifier の弱い UI は強い UI より、注視の時間が平均 22% 長く、注視の回数が平均 25% 多かった（71 人、9 サイト中 3 サイトは差なし、デスクトップの Web。S126）。NN/g は 2024 年に、質感と影をすべて落とした極端に平らな UI は signifier が弱くなったと書く（S127）。手がかりは装飾でなくてよい。Material は面と影を、触れるものを説明する構造として使った（S117）。
3. 規格化が個別最適を超える。Braun は寸法と色の規則で、新製品の使い方を素早く覚えられるようにした（R。S102）。Unimark は駅の表示の標準を作った（R。S98）。Mac OS 8 は、見た目と振る舞いを切り離した（S160）。デザインシステムは製品とチームの規模に応じて広がった（S119）。ただし規格の担い手にも警戒があった（Noyes。R。S96）。
4. 技術の制約が消えると、様式が残る。残った様式は、制約が本当に消えたかを確かめて見直す。表と spacer GIF は Grid に（S132、S148）、文字の画像化は Web フォントに置き換わった（S141）。Federighi は、以前の影の表現は画面の限界から目をそらす手段だったと述べた（S175）。紙の固定の版面の目安は、利用者の環境で変わる画面には、そのままでは持ち込めない（S72）。
5. 素材や層の表現は、製品群の統一の要請から来る。Snow White は統一したデザイン言語への要請の中で語られる（R。S159）。Aqua、iOS 7 の半透明、Liquid Glass は、Apple 自身が系譜として並べた（S184）。Yosemite は iOS との連携を、Big Sur は製品群の一貫性を、Liquid Glass は全プラットフォームへの展開を挙げた（S177、S180、S185）。Material も、プラットフォームと画面の大きさをまたぐ統一を目指した（S118）。
6. 規則は判断の道具で、自己目的化すると反動が来る。Tschichold は後年、書体の容赦ない制限が国家社会主義の類似に思えたと語った（B。S88）。Ulm では、分析だけではデザインにならないという対立があった（R。S101）。Apple の 1992 年の HIG は、すべての原則を常に満たすことはできないと書き（S157）、2026 年の HIG も、原則を優先度を比べる道具とした（S21）。
7. 抽象化は何かを捨てる。捨てたものを書く。NYC の路線図の凡例は、相対距離を読みやすさのために変えたと断った（S99）。Star は、WYSIWYG の見た目だけでは構造が見えないため、構造を見せる表示を別に用意した（B。S107）。
8. 利用者の側に調整の余地を残す方向は、一貫している。CSS1 は読者が自分のスタイルシートで調整できることを特徴とし（S134）、WCAG は拡大・コントラスト・動きの調整を求め（S72）、メディアクエリは OS の設定をページに伝える（S73）。

## 媒体別の使い方

制作の着手前に、該当する媒体の問いを歴史から引き、その媒体の慣習の由来を確かめる。問いは判断を助ける材料で、結論ではない。

### LP・サイト（`../examples/web-landing-page.md`）

1. この見た目は、意味のある要素で実現されているか。構造の外側の仕掛け（画像化した見出し、`div` の偽ボタン）は、表レイアウトと spacer GIF の失敗の再来である（S133、S132）。
2. 320 px 幅の 1 画面目に、何の製品か・誰のためか・次の行動が残るか。注意はファーストビューに偏る（C。S144）。
3. 装飾を減らしたとき、押せる手がかりは残っているか（S126）。
4. スクロール連動の演出は、動きを減らす設定で静止の構成に置き換わり、動きが無くても伝わるか。連番画像のような重い手法が、1 画面目の表示を遅らせていないか（S153、S154、S151）。

### スライド（`../examples/slides-presentation.md`）

1. 単位は 1 枚か、前後の連続か。紙の本は 1 ページではなく見開きを単位とした（S81）。
2. 1 枚 1 メッセージに分けたことで、比較が見えなくなっていないか。関連する情報は並べて示すほうが視覚的な推論がうまく働く（S104）。
3. 書体と大きさの種類を絞ったか。絞る規則が目的化し、内容に合わない形を押しつけていないか（B。S88）。
4. 退屈の原因は内容か装飾か（S104）。Apple 公式のスライドの原則は確認できておらず、ここでの適用は本 skill の整理である。

### アプリ画面（`../examples/app-onboarding.md`、`../examples/app-settings.md`、`../examples/app-empty-and-error-states.md`）

1. 比喩や質感は、利用者の習熟度に見合っているか。慣れた利用者には、比喩は装飾になる（S127、S175）。
2. 押せるものに、知覚できる手がかり（signifier）があるか（S123）。
3. 新しい概念・新しい入力のとき、慣れたものとの釣り合いを取っているか（S183）。
4. 標準の語彙（部品・位置・挙動）に乗っているか。同じ見た目は同じ挙動か（S124）。

### ダッシュボード（`../examples/business-dashboard.md`）

1. データを最も目立たせ（HIG。S59）、装飾が主役になっていないか。聴衆の退屈は内容の失敗であって、装飾の失敗ではない（Tufte の論評。S104）。
2. 抽象化して読みやすくしたとき、何を捨てたかを凡例に書いたか（S99）。
3. 色の意味を固定したか。Braun は電源だけを緑にした（R。S102）。色を一点に使うと意味が立つ、と読める（本 skill の整理）。HIG は同じ色に別の意味を持たせないよう書く（S53）。

### ハードウェア UI（`../examples/hardware-ui.md`）

1. 製品群で寸法・色の規則をそろえ、新製品でも使い方を覚えやすくしたか（R。S102）。
2. 小さな表示は、一目で分かる図像に絞ったか。低解像度の時代、Kare は 16×16 の点で概念を表す問題に向き合った（S110）。
3. 規格を固定しすぎて、製品が古びる危険を考えたか（R。S96）。

### 「Apple っぽく」の依頼（`../examples/anti-pattern-apple-look.md`）

1. 様式の記号になっていないか。MoMA は、Bauhaus が一般には時代を超えた国際モダニズム様式の略語として使われがちだと注意した（R。S85）。同じ構図が「Apple っぽい」にも起きうる（本 skill の整理）。
2. 平坦・余白・薄い文字を、Apple らしさと取り違えていないか。iOS 7 の発表文が強調したのは、動き・配色・機能的な層で、flat という語は無い（S116）。
3. 装飾を減らしたとき、押せる手がかりは残っているか（S126）。

### モーション（`../examples/motion-and-animation.md`）

1. 動きは、階層や押せることを伝える情報か、装飾か。Material は面と影を、触れるものと動くものの構造として使った（S117）。
2. 動きを減らす設定に対応したか（S73、S72）。
3. 重い演出の費用を払う価値があるか。細かい質感と影は描画処理を多く要し（S127）、Web では LCP・CLS の目安がある（S151）。
4. 慣れた挙動を先に担保したか。Apple は iOS 7 を、控えめな動きで、既存の利用者にすぐ馴染むと発表した（S116）。
