# 例: 「Apple っぽくして」を様式の模倣から原則に組み替える（アンチ例）

「Apple っぽくして」という依頼を、様式（余白・半透明・細い文字・角丸）の模倣として受け取ると、可読性・手がかり・目的を損なう。依頼の言葉を原則に翻訳し直す例。題材は架空のサービスで、Apple の製品名・ロゴ・コピー・製品写真の模倣は含まない。

## 依頼

- 製品: 家計の共有メモ「ツミキ」（架空。運営は架空の会社「ミドリ舎」）。紹介ページとホーム画面を作る
- 依頼文: 「ホームページとアプリのホーム画面を Apple っぽくして。余白を広く、半透明で、細い字で、高級感を出して」
- 受け取り方の分岐: 依頼を様式の指定として読むか、「説明なしで分かる」という目的の指定として読むか
- 想定するユーザー: 家計を二人で共有する人。初見で、スマートフォンで開く

## 目的の一文

「Apple っぽい」の中身を確かめる。見た目の再現ではなく、「説明しなくても分かる」「削ぎ落としてある」「細部まで整っている」ことを実現する。

## 削るもの

様式を足すのをやめ、様式が隠していた問題を削る。

| 削るもの | 隠していた問題 |
|---|---|
| ページ全面の半透明ガラス | コンテンツ層にガラスを使わない（S65）。背景次第で文字が読めなくなる（S15、S32） |
| 太さ 200 の細い文字 | 細いウェイトは小さい文字で見づらい（S51） |
| 画面を埋める巨大な余白と中央揃えの大見出し | 重要なものを上と先頭側に置く。揃えと配置で関係を示す（S52） |
| すべてのボタンのピル形と同じ大きさの角丸 | 形は入れ子の関係で決まる。装飾の統一を目的にしない（S69） |
| 操作を隠して「すっきり」させるメニュー | 見た目が minimal になるだけで simple にはならない（S18）。簡潔さは最小化ではない（S17） |
| スワイプだけの重要操作 | 独自ジェスチャーは重要操作の唯一の手段にしない。発見できるか（S25、S12） |
| 背景の自動再生・視差・出現の演出 | 目的の無い動きは入れない（S56）。止める手段が要る（S72） |
| Apple の製品を連想させる写真・書体・コピー・ロゴ風の図形 | 見た目の模倣は推奨しない。ブランドの表現は自社のコンテンツ層に置く（S70） |

## 構成

様式から原則への翻訳表。依頼の言葉を、まず目的の問いへ変える。

| 依頼の言葉 | 様式として受け取った場合 | 原則として受け取った場合 | 返す問い |
|---|---|---|---|
| 余白を広く | 全体に大きな余白を取る | 関係のあるものを近づけ、無関係なものを離す（S52） | この要素は何の隣にあるべきか |
| 半透明 | 全面ガラス・ぼかし | ガラスはナビとコントロールの層だけ。コンテンツには使わない（S65、S71） | 文字の下地は、どの背景でも読めるか |
| 細い字 | 太さ 100〜300 | 階層は太さ・サイズ・色を調整して作る。細いウェイトを避ける（S51） | 小さい字が、拡大した時にも読めるか |
| 角丸 | 全部に同じ角丸 | 入れ子の形は、外側の半径から内側の余白を引いた半径にする（S69） | 形の関係は一貫しているか |
| ミニマル | 機能を奥へしまう | 目的に寄与しないものを削る。隠さない（S17、S18） | 隠した機能を、誰が探し当てるか |
| 高級感 | 暗い背景に薄い灰色 | コントラストと作り込み。細部まで配慮する（S54、S48） | 見えない所まで手を入れたか |
| 動かして | 全部に動きを付ける | 目的のある動きだけ。途中で止められる（S56） | 動きは何を伝えるか |

```text
依頼: 「Apple っぽくして」
  1. 目的を一文で言い直す    例: 二人が家計の「今月の残り」を 5 秒で見られる
  2. 削る                     目的に寄与しない要素・文言・動きを外す
  3. 初見検証                 何に注意する / 何を操作できる / どう操作する
  4. 様式は結果として確かめる 余白・角丸・太さは、手がかりと可読性の結果として決める
```

## 仕様

after（原則ベース）の仕様。他の例の値と同じ根拠に揃える。

| 項目 | 値 | 根拠 |
|---|---|---|
| 見出し | 結論の 1 文。太さ 700 | 太さの下限は S51。重要な場面の見出しは太く左揃えに調整された（S69。適用範囲はアラートとオンボーディングなど） |
| 本文の太さ | 400 以上。300 以下は使わない | S51 |
| 階層 | 太さ・サイズ・色の調整。装飾ではなく配置とグルーピング | S51、S69 |
| 余白 | 関係の近さで決める。値は 8・16・32 px の倍数 | 本 skill の目安（出典なし）。iOS の余白 pt 値は原文に無い |
| 角丸 | 外側 20 px、内側は外側から余白 8 px を引いた 12 px | 入れ子の半径は外側から余白を引く（S69）。値は本 skill の目安 |
| ピル形ボタン | 高さ 44 px、半径は高さの半分（22 px） | カプセルの半径は高さの半分（S69）。44 は S57（44 pt）と S72（2.5.5 の 44 CSS px） |
| 面の透過 | 使わない。コンテンツ層は不透明の面 | S65。標準の素材はコンテンツ層に使う |
| 色 | 共通パレット。アクセントは主要操作だけ | S53、S71 |
| ジェスチャー | 重要操作には見える別経路を置く | S25、S55 |
| 動き | 色の変化のみ。動きを減らす設定で止める | S56、S55、S73 |
| 配色の対応 | ライト・ダーク・高コントラストの各文脈で成立（高コントラストはライトとダークの両方で確認し、計 4 通り） | S53、S54 |

コントラスト比（WCAG の相対輝度式で計算。基準 4.5:1。S72）。before の透過ガラス上の文字は、背景写真に依存して計算できない。計算できないこと自体が問題である。

| 組み合わせ（前景 / 背景） | ライト | ダーク | 高コントラスト（ライト） | 高コントラスト（ダーク） |
|---|---|---|---|---|
| 本文色 / 背景 | 16.79 | 16.72 | 21.00 | 21.00 |
| 補助文字色 / 背景 | 8.74 | 9.10 | 16.79 | 18.79 |
| ボタン文字 / アクセント | 6.39 | 9.41 | 9.81 | 13.50 |
| アクセント / 背景（リンク） | 6.39 | 8.95 | 9.81 | 13.50 |

## 文言

| 場所 | before（様式の模倣） | after（原則） | 理由 |
|---|---|---|---|
| 見出し | 家計を、もっとシンプルに。 | 今月の残りは 48,200 円。二人で見られます。 | 雰囲気でなく、使った後の状態を言う。金額は架空の例 |
| 副文 | 美しく、直感的な体験。 | 使った分を記録すると、残りが自動で変わります。 | 機能の自慢でなく、次の 1 手と結果を言う（S58） |
| ボタン | はじめる | 家計を作る | 動詞で始め、何が起きるかを言う（S57、S58） |
| ホーム画面の操作 | （左へスワイプで削除・長押しで編集） | 行を開くと「編集」「削除」のボタンがある | ジェスチャーの代わりに見える経路を置く（S25、S55） |

英語の原文（S17、HIG Design principles）: "Simplicity isn’t minimalism." 日本語は要旨で、簡潔さは、要素を減らして見た目を静かにすることと同じではない。

英語の原文（S65、HIG Materials）: "Don’t use Liquid Glass in the content layer." 日本語は要旨で、ガラスの素材はコントロールとナビの層に限る。

英語の原文（S69、WWDC25 356）: "Instead of relying on decoration, hierarchy should be expressed through layout and grouping." 日本語は要旨で、階層は装飾でなく配置とグルーピングで表す。

## コード断片

before（CSS のみ）は採用しない見本。after（HTML と CSS）は原則に沿った書き方。外部の資源・スクリプト・フォント・計測は使わない。

```css
/* before（採用しない）: 様式の模倣。背景写真に依存し、コントラストは計算できない */
.hero-before {
  background: url("hero.jpg") center / cover;               /* 写真は不特定。文字の下地が変わる */
}
.hero-before .glass {
  background: rgb(255 255 255 / 0.18);                       /* 全面の半透明 */
  backdrop-filter: blur(24px);                               /* ぼかしは動きを減らす設定でも残る */
  border-radius: 40px; padding: 120px 80px;                  /* 角丸も余白も関係なく大きい */
  color: #ffffff; font-weight: 200; font-size: 28px;         /* 細い字。下地次第で読めない */
  text-align: center;
}
.hero-before .glass { animation: float 8s ease-in-out infinite; }  /* 目的の無い常時の動き */
```

```html
<main class="hero">
  <h1>今月の残りは <span class="nb">48,200 円</span>。二人で見られます。</h1>
  <p class="lead">使った分を記録すると、残りが自動で変わります。</p>
  <a class="btn" href="/new">家計を作る</a>
</main>
```

## 初見検証

| 問い | 期待する答え（after） | 確認する場所 |
|---|---|---|
| 何に注意するか | 「今月の残りは 48,200 円」 | 見出しの 1 文 |
| 何を操作できるか | 「家計を作る」ボタン | 目立つのが 1 つだけ |
| どう操作するか | 押す。編集・削除は行を開いてボタンで | 見えるボタンがある |

様式の検証として、要素を 1 つずつ外し、目的（残りが 5 秒で見える）が崩れるかを確かめる。崩れない要素は削る。余白・角丸・太さは、この検証を通った後の結果として決める。

## 点検

- アクセシビリティ: 重要操作がジェスチャーだけでない。動きを減らす設定で動きが止まる。コントラストは 4 通りの配色で上の比率を満たす（S55、S72）
- 可読性: 文字の下地が不透明で、背景に依存しない。文字を 200% に拡大しても崩れない（S51、S65）
- やり直し: 削除は取り消せる（元に戻す）か、失われるものを示して確認する（S26）
- 失敗パターン: 様式を原則の代わりにしていないか（S22、S27）。Liquid Glass の可読性への批判や、透明な層への指摘がある（S15）。また、既存の Apple 製品を使い慣れた人の「直感的」は学習済みの習慣であり、初見の人が分かることとは別である（S37）
- 法的・表記の注意: Apple の商標・製品の外観・コピーを模倣しない。借りるのは考え方で、見た目を写すことではない
- 推測の明示: 「Apple っぽさ」を相談者が何で測るかは、この例からは分からない。評価の基準（誰に・何を感じさせたいか）を先に確認する
