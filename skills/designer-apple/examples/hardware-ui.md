# 例: ハードウェア・組み込み UI（物理操作と画面の分担）

ボタンとメニューを増やした家電の操作を、「物理操作が主役、画面は状態を見せる」作りへ組み替える例。題材は架空の製品で、実在の製品の外観・名称は模倣しない。公式の根拠が薄い題材で、画面付き製品の HIG と公開された発言を転用した、本 skill の整理（転用）である。

## 依頼

- 製品: 温度を選べる電気ケトル「ユノ」（架空。製造は架空の会社「ミドリ舎」）。小さな液晶と回転ダイヤルを持つ
- 依頼文: 「ケトルの操作を考え直して。ボタンが 6 つあって、説明書を見ないと使えない。Apple っぽくミニマルに」
- 現状: ボタン 6 つ（電源・温度＋・温度−・保温・モード・ロック）、液晶に英字略語の状態表示、エラーは「E-03」、アプリ連携が初期設定の前提
- 想定するユーザー: 朝の台所で、片手が濡れているか、ふさがっている人

### 根拠の範囲（先に読む）

- Apple の Industrial Design やハードウェアの UI に関する HIG の指針は、今回の調査では確認できていない。参照できるのは、画面付き製品（Apple Watch など）の HIG と、公開された設計思想の発言（`../references/sources.md`）である
- 画面付き製品の値（操作対象の大きさ・ボタンの個数など）は、組み込みの小さな液晶へそのまま当てはまるとは原文に書かれていない。転用する場合は目安と明記する
- 安全規格・電気用品の法令・耐久性・熱設計は、この例の範囲外。個別の確認が要る

## 目的の一文

湯を沸かしたい人が、説明を読まずに、ダイヤルを回して押すだけで、希望の温度の湯を得る。

## 削るもの

| 削るもの | 理由 |
|---|---|
| 温度＋・温度−の 2 つのボタン | 回して選ぶ 1 つのダイヤルに統合する（重複の統合） |
| モード・保温・ロックのボタン | まれにしか使わない操作は二次導線へ。保温はダイヤルの 1 つの選択肢にする |
| 液晶の英字略語（HEAT・KEEP） | 簡潔な言葉。ラベルに必要な語だけ、日本語で（S58 の転用） |
| 「E-03」などのエラー番号 | 原因と次の行動が分からない。文で言う（S58 の転用） |
| アプリ連携を初期設定の前提にすること | 近接や通信だけを唯一の経路にしない（S26）。本体だけで全操作が完結する |
| 起動時のロゴ演出と待ち時間 | 速く使えることが先。起動は即時（S63 の転用） |

## 構成

物理操作と画面の分担。

| 操作・情報 | 物理 | 画面 | 理由 |
|---|---|---|---|
| 温度を選ぶ | ダイヤルを回す。段ごとに触感のクリック | 選んだ温度を大きく即時に表示 | 回しても画面が変わらないと、効果が無いと受け取られる（S26）。遅れると応答の感覚が急に悪化する（S29） |
| 開始・停止 | ダイヤルを押し込む | 「加熱中」の語と進み具合 | 押す動作が結果と同じ場所にある。誤って始まらない操作にする（S34 の考え方。区分 B） |
| 保温 | ダイヤルを回して「保温」の位置へ | 「保温 70℃」 | 別ボタンを足さず、選択肢の 1 つにする |
| 状態の通知 | 完了時に短い音 1 回 | 「できあがり 100℃」 | 音だけ・色だけにしない（S61、S55） |
| 異常 | 加熱しない・短い音 | 「水が足りません。水を入れてください。」 | 原因と次の行動を言う（S58） |

```text
        本体の上面                      液晶（常時はこの 1 画面）
   +----------------------+        +------------------------+
   |   ( ダイヤル )       |        |   98℃                  |  温度: 大きく・ほぼ全面
   |   回す = 温度を選ぶ  |        |   加熱中  [=====>   ]  |  状態の語 + 進み具合
   |   押す = 開始・停止  |        +------------------------+
   |  [LED]               |
   +----------------------+
```

- 画面の階層は 0 層。待機・加熱中・保温・できあがり・異常の 5 つの状態を、同じ位置に同じ形で出す（S27 の考え方）
- 画面なしでも、ダイヤルの位置と LED で最低限の状態が分かる。重要な操作を画面だけに依存させない（S26 の考え方）

## 仕様

| 項目 | 値 | 根拠 |
|---|---|---|
| ボタン・ダイヤルの個数 | 1（ダイヤルの押し込みを含む） | 目安（出典なし）。画面付き製品では、アイコンのボタンは 1 行に 3 つまで、文字なら 2 つまでという指針がある（S52、watchOS）。転用は目安 |
| 物理ダイヤルの大きさ・トルク・クリック間隔 | 試作で確認する | 値の根拠は確認できていない |
| 温度表示 | 画面の高さの約 3 分の 1 の文字高 | 本 skill の目安（出典なし）。腕を伸ばした距離で読めるかを試作で確認 |
| 状態の語 | 温度の約 3 分の 1 の大きさ・太さ 600 以上 | 本 skill の目安（出典なし）。細い太さを避ける（S51 の転用） |
| 文字の最小 | 画面高の 1 割程度 | 本 skill の目安（出典なし）。画面付き製品の最小は 11〜12 pt だが、遠方から読む前提と異なる（S51） |
| 画面付き製品の参考値 | 操作対象は既定 44 x 44 pt・最小 28 x 28 pt（watchOS）。文字は少なくとも 140% に拡大できることが理想（watchOS） | S55。組み込みの液晶へそのまま当てはまるとは原文に無い |
| フィードバック | 回転 → 画面の値が遅れず変わる | 視覚フィードバックが無いと効果が無いと受け取られる（S26）。遅延で応答の感覚が悪化（S29） |
| 通知の手段 | 画面の文・音・LED の 2 つ以上 | 色・文字・音で受け取れるように（S61）。音だけ・動きだけにしない（S55） |
| 点滅・自動の繰り返し | 付けない。1 秒に 3 回を超える点滅を作らない | 速い動きと点滅に注意（S55）。点滅の回数は S72（2.3.1）。実機に動きを減らす設定が無いなら最初から付けない |
| 起動・復元 | 即時。前回の温度を復元 | S63、S24 の考え方の転用 |
| 色 | 共通パレット。警告だけエラー色。色以外に語を添える | S53、S72 の 1.4.1。具体色は本 skill の目安 |

## 文言

| 場面 | before | after | 理由 |
|---|---|---|---|
| 加熱中 | HEAT 98C / TGT 100C | 98℃ 加熱中 | 略語を避け、語で状態を言う（S58） |
| 完了 | 沸騰完了（ブザー長め） | 100℃ できあがり（短い音 1 回） | 結果を、見ていなくても分かる形で知らせる（S61） |
| 異常 | E-03 | 水が足りません。水を入れてください。 | 原因と次の行動（S58） |
| 保温 | KEEP ON / OFF | 保温 70℃ | 状態と値を 1 つの語で |
| 初回 | アプリをダウンロードして接続してください | 水を入れて、ダイヤルを押してください | 前提を 1 つにする。アプリは任意 |

英語の原文（S26、HIG Digital Crown）: "If you don’t provide visual feedback, people are likely to assume that turning the Digital Crown has no effect in your app." 日本語は要旨で、回転操作には、画面の変化という視覚フィードバックが要る。

英語の原文（S03、Ive、Telegraph 2012）: "Our products are tools and we don't want design to get in the way." 本件への当てはめは本 skill の推測で、ケトルの操作では、デザインが湯を沸かすことの邪魔をしないことを基準にする。

## 初見検証

| 問い | 期待する答え | 確認する場所 |
|---|---|---|
| 何に注意するか | 今の温度と状態（加熱中・水が足りない） | 液晶の大きな数字と状態の語 |
| 何を操作できるか | 上面のダイヤル | 本体に操作できそうな部品が 1 つだけ |
| どう操作するか | 回して温度を選び、押して始める | ダイヤルの形・回すと数字が変わること |

説明書を渡さずに、台所で 1 回目の湯沸かしをしてもらい、最初の 1 手までの時間と迷った所を見る。濡れた手・片手・暗い朝の条件を分けて見る。

## 点検

- アクセシビリティ: 温度の選択を、触感のクリックと画面の値の両方で確認できる。完了・異常を音だけ、色だけにしない。視覚に頼れない人のための別の知らせ方（例: 段ごとの触感・音の高さ）は、試作で確かめる
- 可読性: 4 通りの配色で上の比率を満たす。照明の強い台所で液晶が読めるかは実機で確かめる（この例では分からない）
- やり直し: 押し込みを 2 回でキャンセルできる。誤って始まらないよう、押し込みの深さ・保持の設計を試作で確かめる（根拠: S34 の考え方、区分 B）
- 失敗パターン: 形状や薄さを先行して、湯気・放熱・持ちやすさを後回しにしていないか。Federighi は 2017 年に、Mac Pro の設計が熱の制約に自ら入り込んだ面があったと述べた（S20）。画面付き製品の「近づけるだけ」の簡潔さには、前提と失敗時の回復手順が裏にある（S45）ので、アプリ連携を足す場合は、失敗時の戻り方を別に設計する
- 推測の明示: 価格・部品・安全規格・製造のコストは、この例では分からない。法令や認証が要る判断は、専門家と相談者が行う
